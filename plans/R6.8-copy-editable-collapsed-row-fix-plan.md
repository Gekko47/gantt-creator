# R6.8 defect fix — collapsed rows in the editable copy

Status: implemented (Core rule, tests, message mapping, docs). The live reproduction on the owner's
workbook is the remaining gate.

## Outcome

Pressing **Copy editable** on a workbook that has a **collapsed section** must produce the verified
editable copy. Today it always fails with the generic sentence *"Excel refused to create the copy.
Run Refresh chart, then copy again."*, and Refresh cannot help.

The fix: a hidden worksheet row contributes **no data-panel primitives**; the plot-area shapes of the
visible rows are unchanged. A second, independent defect also ships in the same change: the copy
command must name the typed reason instead of one sentence that prescribes an ineffective remedy.

## Evidence (fact / inference)

Facts — observed in `%LOCALAPPDATA%\GanttCreator\logs\gantt-creator-addin.log` on 2026-11-19:

- Five Copy attempts (08:00:43, 08:00:50, 08:01:28, 08:02:51, 08:32:42), each:
  `gantt.protection window open released=True` → `gantt.shape.create-steps n=24` → window close.
  Protection is released; 24 staged shapes are created; the refusal is on the **25th** create.
- The instrumented run recorded the exact refusal:
  `gantt.shape create-refused id=G-<token>:panel-cell:Description kind=Rectangle refusal=InvalidGeometry step=validate b=518.362,89,45,0`
  → a data-panel cell for the `Description` column with **height 0**.
- `PanelCellGrid.RowHeightsPt` documents the convention: a hidden worksheet row is measured at zero
  height (`PanelCellGridRefusal.NegativeRowHeight` remarks).
- `PanelRowProjection.TryProject` projects **every** event, hidden or not (no `Visible` filter), in
  `RowNumber` order, so a hidden row keeps a panel row at a zero measured height.
- `PanelBuilder.AddBody` emits `panel-cell:{column}` (ZLayer.Background) and `panel-text:{column}` for
  every row using `grid.RowHeightsPt[rowIndex]` as the height — a zero-height row emits zero-height
  rectangles and text boxes.
- `ExcelShapeWriter.Validate` → `IsUsableBounds` requires `Width > 0 && Height > 0`, so the first
  zero-height panel cell refuses with `InvalidGeometry` before any host call.
- `EditablePanelStagingComposer.Stage` collapses **every** non-success write to
  `StagingCompositionRefusal.HostRejected`, keeping the real reason in
  `StagingCompositionOutcome.WriteRefusal`; `CopyEditableCommand.TranslateLifecycle` ignores it and
  prints the generic sentence.
- No production code deletes staging-named shapes outside `StagingLifecycle`'s own registry cleanup
  (searched `src`): the live writer's `ListOwned` proves only live names, so **Refresh chart cannot
  remove a staging shape** — the advice in both messages is not achievable.

Inferences (not yet proved, to be confirmed by test):

- Hidden rows produce no plot-area placements (`LaneRowAnchorResolver` refuses a degenerate row
  height), so the plot shapes in the copy are already correct and the panel is the only place a
  hidden row leaks into the export scene.
- If a plot primitive did carry zero area, the same refusal class would reappear; the composition
  test below closes that hole for the whole scene, not only the panel.

## Design

**D1 — a hidden row is not part of the data panel.** In `PanelBuilder`, a row whose measured height
is `<= 0` is a hidden worksheet row: emit no `panel-cell:` rect, no `panel-text:`, and no
`panel-border-h:` line for it. The row keeps its positional slot and its zero height, so
`Rows.Count == RowHeightsPt.Count`, the panel's running-sum top values, `Bounds`, and
`TotalRowHeightPt` are all unchanged — only the primitives that describe nothing are gone. The border
is dropped too: the row's top and bottom edges coincide, and the previous row's bottom border already
draws that line.

**D2 — the rule is measurement-driven, not policy-driven.** The height is the only visibility signal
the panel request carries, and zero means hidden by an existing, documented convention. No new
`PanelRow` member, no new profile flag, no change to `PanelRowProjection`.

**D3 — the copy command names the reason.** `TranslateLifecycle` maps
`StagingCompositionRefusal.HostRejected` through `outcome.Composition?.WriteRefusal`:

| Typed refusal | Sentence |
|---|---|
| `TargetProtected` | The worksheet is protected. Unprotect it, then copy again. |
| `AlreadyExists` | A temporary copy shape with that name is already on the sheet. Delete the shapes named `GanttCreatorStaging…`, then copy again. |
| `InvalidGeometry` | Part of the copy has no visible area, so Excel cannot create it. Run Fix, then copy again. |
| `UnsupportedIdentifierForm`, `BlankIdentifier` | The copy could not be composed. Run Fix, then copy again. |
| `NoActiveWorkbook`, `WorksheetMissing` | Open the workbook with the Gantt table, then copy again. |
| `HostRejected`, `NotFound`, `InvalidOwnershipTag` | Excel refused to create the copy. |

`StagingAlreadyPopulated` stops advising a Refresh and names the shapes to delete.

**D4 — keep the debug instrument.** `ExcelShapeWriter.RefuseCreate` (id, kind, typed reason, step,
geometry) stays: it is the record that made this defect diagnosable, and the contract test pins it.

**D5 — the panel stays scene-authoritative.** No clamp, no minimum extent, no composer filter: the
scene simply stops describing a row that is not on the visible table.

```mermaid
flowchart LR
    A[table read] --> B[PanelRowProjection all rows]
    B --> C[PanelCellGrid measured heights, hidden row = 0]
    C --> D[PanelBuilder: hidden row emits no cell, text or border]
    D --> E[SceneBuilder: plot shapes unchanged]
    E --> F[ExportBoundsResolver]
    F --> G[Staging composer]
    G --> H[group and verified copy]
```

## Steps

1. Core: add the hidden-row rule to `PanelBuilder.AddBody` and `AddBorders` with the doc comment that
   names the zero-height convention and cites the entity-guide panel section.
2. Core tests (`PanelBuilderTests`): a grid with one zero-height row emits no primitive owned by that
   row and no border for it, while every other row's primitives and the panel `Bounds` are unchanged;
   a positive-height row still emits cell, text and border.
3. Composition guard (`SceneShapeRendererTests` or the R6.2/R6.3 contract tests): every translated
   request from a scene with a hidden panel row has a positive width and height.
4. AddIn: type-aware `HostRejected` message plus the truthful `StagingAlreadyPopulated` message;
   positive tests for each mapped member and for the absent "Run Refresh chart" wording.
5. Docs: entity guide panel section, [`docs/adr/0067-hidden-rows-contribute-no-panel-primitives.md`](../docs/adr/0067-hidden-rows-contribute-no-panel-primitives.md)
   with its index row and narrative, the R6.8 work-item evidence block, `docs/STATUS.md`.
6. Gates: `pwsh ./scripts/verify-quick.ps1`, then the live reproduction (Refresh, then Copy editable,
   paste into Excel and PowerPoint, ungroup to edit, zero residue) and `verify-office.ps1` where the
   host allows it.

## Acceptance tests

- A collapsed fixture's export scene contains no primitive with a non-positive extent, and the panel's
  `Bounds` equals the value it had before the rule.
- The staged composition on the user's workbook succeeds; the pasted group's child count equals the
  composition's primitive count.
- `HostRejected` names `InvalidGeometry`, `TargetProtected`, and `AlreadyExists` distinctly; no copy
  refusal advises a Refresh.

## Risks and rollback

- Scene primitive counts change for collapsed fixtures: any pinned count or golden image that includes
  a collapsed section must be reviewed, not silently accepted (golden changes need their own commit).
- A row measured at zero but not actually hidden is unrenderable either way; skipping it is the only
  outcome the host accepts.
- Rollback: revert the `PanelBuilder` rule; the message change and the writer trace are independent and
  can stay.

## Deferred

- A staging sweep that deletes tag-proven `GanttCreatorStaging…` shapes before composing, so residue
  never forces a manual delete. It contradicts R6.5 D1's "birth registration, never a sheet scan" as
  written, so it needs an owner decision rather than an opportunistic change.
