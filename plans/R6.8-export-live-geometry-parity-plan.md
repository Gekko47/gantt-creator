# R6.8 follow-up — the editable copy composes with the live chart's geometry rules

Status: approved in principle (owner accepted all four rules 2026-11-19 and asked for the
comparison). Audit complete; implementation not started.

## Outcome

Copy Editable must produce a composition that reads as the live chart: the data panel where the
table is, the plot where the plot is, every lane on the panel row it belongs to, the title over
the table, the splitter fill inside the plot, and every user setting honoured exactly as Refresh
honours it.

Today the copy composes from a separate geometry route keyed on
`SceneCompositionProfile.EditableExport`, written before the panel became part of the export
(R6.1/R6.2). The owner's live comparison exposed four visual faults; the audit found three more.

## Audit — the copy engine against the refresh engine

Both profiles share `ExcelSceneBuildRequestFactory.CreateCore` and `SceneBuilder`; the
divergences are the values the export **overrides** and the branches it **takes**.

| # | Setting / rule | Live (Refresh) | Copy (EditableExport) | Code |
|---|---|---|---|---|
| 1 | Splitter band extent | starts at the plot's left edge | starts at the panel's left edge, filling the table | [`BuildSplitters`](../src/GanttCreator.Core/Scene/SceneBuilder.cs:1067), comment at line 1064 |
| 2 | Title placement | owned textbox at the table's left edge, table width, on the reserved row that carries the year band | full-width band centred above panel + bands | [`FrameBandsBuilder`](../src/GanttCreator.Core/Scene/FrameBandsBuilder.cs:168) and `AddTitle` at 474; live twin at [`GanttRefreshOrchestrator`](../src/GanttCreator.Office/GanttRefreshOrchestrator.cs:710) |
| 3 | Lane alignment | every lane anchored to its measured worksheet row | lanes stacked sequentially; a row that owns no lane pulls every later lane up one row | [`CreateExport`](../src/GanttCreator.Office/ExcelSceneBuildRequestFactory.cs:263) pins anchoring off; [`ExportBoundsResolver`](../src/GanttCreator.Core/Scene/ExportBoundsResolver.cs:95) refuses an anchored request |
| 4 | Label position (`Auto`) | resolved against the live chart bounds | resolved against the export chart bounds, which have no anchor-row overhang — a below-line label cannot fit and flips above | [`BuildDelineators`](../src/GanttCreator.Core/Scene/SceneBuilder.cs:1189); [`DelineatorBuilder`](../src/GanttCreator.Core/Scene/DelineatorBuilder.cs:374) |

No divergence found in: chart chrome colours, frame/band themes, alternate banding, minor/major
grid toggles, time scale and period-label format, date display format, hidden columns, measured
column widths and row heights, plot margin, lane metrics, milestones, the panel's fills, header
type and text colours (all resolve through `GanttTableAppearance` / `GanttCatalogues` in both
profiles).

**Inference to verify, not assume:** fault 4 is probably a symptom of fault 5. The below-line
label box must fit inside `ChartBounds`; the live chart extends the plot by the anchor row and
the copy does not. Fix 5 first and re-measure 4 before adding any rule for it.

## Design

**D1 — The splitter fill belongs to the plot.** `BuildSplitters` takes the plot rectangle, not the
frame's panel bounds, so the band cannot cover the data panel. Guide §10 says the band spans the
plot.

**D2 — The export title is the live title.** For a panel-drawing profile the title box is
`x = panel left`, `width = panel width`, `y` and `height` = the year band's row, centred within
that box — the same box the live textbox occupies
([`GanttRefreshOrchestrator`](../src/GanttCreator.Office/GanttRefreshOrchestrator.cs:710)).
The plot top stops reserving a title band (fix 7).

**D3 — Every panel-drawing composition anchors its lanes.** `AnchorLanesToRows` becomes a
function of the profile: a composition that draws the panel anchors to the same grid the panel
uses; a panel-less composition does not. `ExportBoundsResolver`'s guard changes from "refuse
anchored" to "refuse a profile/anchoring mismatch", which is testable in both directions and still
catches a live request re-profiled to export. `LaneRowAnchorResolver` already returns
origin-relative row tops (`RowTopsPt[ordinal] - OriginTopPt`) and `SceneBuilder` adds the plot top
once, so the zero-origin export grid aligns lane 1 with panel row 1 by construction.

**D4 — The export keeps the anchor row.** The export grid is rebuilt with the live measured
`AnchorRowHeightPt`, and the export frame's bottom padding gains it, so the plot-spanning bands
overhang and the closing line is drawn exactly as on the sheet. A zero-height anchor row stays a
legitimate configuration and reproduces the pre-ADR-0038 geometry.

**D5 — Whatever the workbook stores is what the copy uses.** `ExportPanelTheme` takes the themed
`GridLinePt` rather than the catalogue default. Any future panel style resolves through the same
authority the live table uses.

**D6 — Labels keep their configured position.** An explicit `LabelPosition` / `DateLabelPosition`
is honoured verbatim in both profiles (already true); `Auto` resolves against equivalent geometry.
If D4 does not make `Auto` agree, the residual rule is decided from the measured difference — not
guessed.

## Steps

1. Core: `BuildSplitters` takes the plot rectangle; guide §10 wording.
2. Core: `FrameBandsBuilder` title box over the panel for a panel-drawing profile; the year band
   keeps its row.
3. Core: `ExportBoundsResolver` profile/anchoring rule; `CreateExport` anchors.
4. Office: export grid carries the measured anchor row; the frame's bottom padding includes it.
5. Office: `CreateCore` stops reserving the title band for the export profile.
6. Office: `ExportPanelTheme.Resolve` takes the themed grid-line metric.
7. Tests: one fact per rule — splitter band left equals the plot's left; the title box equals the
   panel box on the year row; anchored lanes land on the panel row tops for a mixed-height grid
   containing a spacer, a delineator and a projected child; the anchor row yields the overhang and
   the closing line; the panel border takes the themed width; the export request reserves no title
   band and carries the anchor row.
8. Re-measure the delineator label on the live copy; only then decide D6's residual rule.
9. Docs: ADR-0068 "the editable copy composes with the live geometry rules" (amending ADR-0030 D6,
   ADR-0034 D1, ADR-0038 D1, ADR-0048), guide §3/§10, `docs/STATUS.md`, the R6.8 work item.
10. Gates: `verify-quick.ps1`, then the live re-copy of the same workbook and a visual comparison
    against the live chart.

## Risks and rollback

- Enabling anchoring for the export can refuse a lane whose owner row is hidden
  (`DegenerateRowHeight`). A hidden row is a collapsed child and draws on its parent's lane, so the
  owner is never hidden — a test pins that case before the flag flips.
- The export composition's bounds grow by the anchor row, so the staged group grows with it; the
  paste-size assertion in the live gate moves with it.
- Each rule is independently revertable; the ADR records which of them changed visual output.

## Deferred

- The 7-to-134-second variance measured on the 211-shape copy (2026-11-19) is host clipboard
  contention, not a product limit. The refusal record now names the observed format set, so the
  next occurrence is diagnosable; no bounded retry is added.
