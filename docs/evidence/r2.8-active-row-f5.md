# Evidence — R2.8 active-row insertion F5 interaction

> **Status:** Human-confirmed on 2026-09-24. This record covers the R2.8 active-cell-relative row insertion follow-up on the Windows desktop Excel host.

## Human interaction outcome

The human operator confirmed that the change works as intended in Excel.

- The `Add activity`, `Add milestone`, and `Add delineator` Ribbon commands insert rows in the expected locations.
- With a row selected inside `tblGanttData`, a new row is inserted immediately below the active row rather than at the active row position or at the bottom of the table.
- Rows following the insertion point shift down while retaining their data and stable IDs.
- The first initialized insert does not leave an extra blank row inside the table.
- The scaffold rows show the expected generated `Id`, `Type`, and default `StyleKey` values; optional authoring fields remain blank until the user supplies them.
- The screenshot confirmed that the data table ended after the inserted body row; the partially visible row number below the table was not an extra table row.
- The screenshot also confirmed that the Gantt Creator Ribbon commands were visible and the table remained the active worksheet context.
- The Gantt chart was not rendered by the add-row commands. This is consistent with the refresh-only rendering contract; the human screenshot was taken before an explicit Refresh.

## Debug-log observations

Two F5 Debug output sets were reviewed.

- The previous run loaded the add-in assemblies and then reported one `System.Runtime.InteropServices.COMException` in `GanttCreator.Office.dll`; Excel still exited with process code `0`.
- The current run loaded `GanttCreator.AddIn`, `GanttCreator.Core`, and `GanttCreator.Office` with symbols, reported no exception, showed normal thread exits, and ended with Excel process exit code `0`.
- Runtime module-load messages such as `Skipped loading symbols`, `Module is optimized`, and the anonymous dynamic-method assembly are normal debugger/runtime messages and were not treated as failures.
- The current Debug output alone does not identify which Ribbon command was clicked. The automated live Office integration suite supplies the command-path evidence; the human result above supplies the visual F5 interaction evidence.
