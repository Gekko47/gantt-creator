# Work item — R5.24 Settings in-place write

> One ID per file. One concern per commit. Design: [`plans/settings-in-place-write-plan.md`](../../plans/settings-in-place-write-plan.md).

## Outcome

`WriteSettings` and `WriteTheme` rewrite their contract tables in place when the live table already matches its shape, so no settings command perturbs the host's selection context through a `ListObject` delete and re-add; every other shape still takes the existing delete-and-recreate path, the observable catalogue contract is unchanged, and the settings-only commands no longer restore a tab that never moved.

## Exclusions

- No removal of the refresh or command tab restores: `Refresh()`, `FinishRefresh` and the Copy/PowerPoint/PNG commands keep theirs because their own selection restore can re-activate Table Design.
- No change to `Write`, `WriteThemed`, `UpgradeAdditiveSchema`, the additive repair, `RollBack`, or the `WriteOrReplaceTable` method itself — only its callers try the in-place path first.
- No schema version bump, no settings key added or removed, no anchor change, no reader change.

## Decisions

- **D1** In-place only when all hold: a table named `tblGanttSettings`; headers equal `GanttCatalogues.SettingsHeaders` (same count, ordinal names); body row count equals `BuildSettingRows(merged).Count`; origin equals `GanttCatalogues.SettingsAnchor`. Anything else takes the existing path.
- **D2** Write order: apply Text format to the Value column, then write the body matrix. The header row is never written.
- **D3** Rollback is the existing `TableSnapshot` → `RollBack` path. A new `SetBodyValues` seam lets a contract test force the in-place write to fail, preserving the rollback validator's positive test (today it triggers on `AddTable`, which this path never calls).
- **D4** No extent is recorded in `written` on the in-place path: `RollBack` consults `written` only for a table that did not exist, and the in-place path requires an existing table. Deviation from the plan, recorded here.
- **D5** No `ListObject.Resize`. A row-count mismatch falls back; the row count is catalogue-defined, so a mismatch means the table is off-contract.
- **D6** `WriteTheme` takes the same path for `tblGanttStyles`, `tblGanttMetrics`, `tblGanttSettings` and `tblGanttConfig`. A custom-style create or delete changes the styles row count, so that table alone falls back; the other three stay in place.
- **D7** A settings-only command does not restore the tab. `SetAutoRefresh` and `ApplyHiddenColumns` lose their `ActivateGanttTab` call: with the write in place the tab never moves, and the restore was itself the reported refocus. The refresh and selection-restoring commands keep theirs (ADR-0058 amendment 2026-11-28).

## Risk and rollback

The risk is that the host still changes its selection context on a body-only `Value2` write, so the takeover survives and the slice buys nothing. The live gate decides; if it survives, the next rung is the invalidation narrowing as its own work item and no restore is added. A second risk is D7: the two removed restores rely on the in-place write holding in the host, so the live gate must confirm the toggle and the Columns menu do not take over; if either does, its restore returns with the recorded evidence. Rollback is a single revert: the in-place branch and its two seams are additive, and the fallback is the current production path.

## Definition of done

Per `AGENTS.md`: the new branch and its fallback each have a positive contract test; the rollback validator keeps a positive test through the new failure seam; the Release build, analyzers and coverage gates pass; no test is weakened; the ADR amendment, work item and `STATUS.md` are current; the diff holds only this concern.

## Notes during implementation

- The anchor-origin check is implemented as one seam, `GetTableOrigin(ListObject)`, which reads `table.Range` into a local before reading `Row`/`Column` (no chained proxy expression).
- The `ConfigSheetFake` gains a body-write model and a recorded origin, because `GetResizedRange` previously discarded the anchor and `Add` could not know where a table sat.
- `verify-quick.ps1` failed once at the AddIn suite on `GanttRefreshSchedulerTests.The_switch_and_the_chart_lock_compose_independently` ("Both suspensions lifted and the command still did not schedule"). The test passes 1/1 in isolation (1 s) and exercises no path this change touches. Per `docs/04-TEST-STRATEGY.md` a flaky test is a defect, so it is recorded rather than rerun to green; the timer-based `SpinWait` shape is the follow-up defect.
- `verify.ps1` and `verify-office.ps1` are owed; the live tab observation in the acceptance tests above is the deciding evidence for the in-place change.
- Ribbon-flow audit (2026-11-28): every flow that writes settings now reaches the in-place path — the six plot setters, the plot-date setters, the chart title, the auto-refresh toggle, column visibility and the theme dialog. Restores retained: `Refresh()` (sheet activation and the label/style commands), `FinishRefresh` (both refresh paths), and the Copy/PowerPoint/PNG commands, each of which restores a selection. Restores removed: `SetAutoRefresh`, `ApplyHiddenColumns`.
