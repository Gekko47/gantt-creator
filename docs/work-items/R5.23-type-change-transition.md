# Work item — R5.23: the Type-change transition

> **Status**: Implemented 2026-11-27 (code, tests, docs); the Office host gate is owed.
> **Depends on**: R2.5 (validation), R2.7b/c (style capabilities), R5.6a (named styles),
> R5.14 (date-label vocabularies), R5.20/ADR-0050 (the automatic-refresh switch),
> ADR-0055 (the chart lock).
> **Supersedes**: the per-column rules inside `ExcelTypeChangeNormaliser` (the "R5.1"
> heal comment), which now delegates to Core.

## Outcome

A `Type` edit leaves a row whose type-dependent cells are valid for the NEW type, on the
change path and irrespective of whether the chart is rebuilt, and the ribbon, validator
and scene all read that healed row.

## The defect this closes

`Activity → Delineator` (or any `Custom Activity → Delineator`) left the description and
date labels describing the previous type:

1. `StyleKey` was only ever filled when blank, so a span style survived on a Delineator.
   The ribbon offered `span positions ∩ corners = {Auto, None}` and `SceneBuilder` took
   the span style's default label position for a corner-label builder.
2. `DateLabelPosition` has two vocabularies that share `Auto` and `None`. A corner left
   on a span blocked with `UnknownDateLabelPosition`; the shared tokens flipped meaning
   silently.
3. The heal ran only inside a render pass, so with `AutoRefreshEnabled` off or the chart
   unlocked a Type edit was never healed.

## Rulings

- **R1** A Type edit heals its row on the change path, before the render decision.
- **R2** The rules live once, in Core `EntityTypeTransition`, and use the catalogue,
  hierarchy and style projections the validator and the ribbon use.
- **R3** A Type change that crosses the which-date ↔ placement boundary blanks
  `DateLabelPosition`, shared tokens included.
- **R4** `Finish`, `LaneId` and `StackIndex` are retained for a Delineator (guide §24);
  Splitter/Spacer keep today's clearing.
- **R5** A style key is usable when it resolves and its family matches the type's; a
  style offering only `Auto`/`None` is neutral and usable anywhere.
- **R6** A token that names neither label vocabulary is left for the validator.
- **R7** A parent converted to a type that cannot own children is reported, not
  re-parented.

## Implementation

- **Core** — `EntityTypeTransition.Apply(row, newType, oldType, styles)` returns the cells
  to rewrite with a stable reason. `EntityTypeCatalog.IsStyleKeyUsable` is the shared
  predicate. `ITypeChangeNormaliser.Normalise(styles)` now receives the registry the pass
  already read.
- **Office** — `ExcelTypeChangeNormaliser` is the writer only: one column walk, one body
  read, one write per changed cell. It accepts an optional old-type resolver for the
  change path.
- **AddIn** — `TypeChangeHealCommand` opens the shared protection window, suppresses the
  four application settings, matches the cached pre-edit rows by engine `Id`, heals, and
  records `gantt.types heal cached=<n> cells=<k>`. `ISheetChangeAnalyzer.IsTypeColumnChange`
  flags the burst; `GanttRefreshScheduler` runs the heal before its one render/projection
  action. The caller republishes, so a Type burst still costs one capture.
- **Validator/planner** — `StyleKeyNotAllowedForType` is a Warning for a requiring type
  with a resolvable but unusable style, and `StyleKeyWritePlanner` heals that case to the
  type default in the same pass.
- **Ribbon** — the three label captures return `Default`/`Auto` when the stored token is
  not in the offered set.

## Acceptance tests

- `EntityTypeTransitionTests`: the 17×17 ordered matrix, each healed row validated with no
  `LabelNotAllowedForType`, `UnknownLabelPosition`, `DateLabelNotAllowedForType`,
  `UnknownDateLabelPosition` or `StyleKeyRequired`, and a second pass writing nothing; one
  fact per rule row (style reset, neutral style, boundary reset, corner on a span, corner
  kept on a sweep, dateless clear, lane retention, fill cleared, unparseable left).
- `StyleKeyWritePlannerTests`: a resolvable foreign style is healed to the type default;
  a neutral style and a live user choice are left alone.
- `GanttRowValidatorTests`: the same foreign style is a Warning, not an error.
- `GanttRefreshSchedulerTests`: a Type burst heals then projects while suspended; a
  non-Type burst projects only.
- `RibbonStateRepublishTests`: an out-of-set description label and date label read as
  Default.
- `ExcelTypeChangeNormaliserTests`: the existing seams and facts still pass.

## Gates

`verify-quick.ps1` and `verify.ps1` are reported in the handoff. The Office host gate is
**owed**: `Custom Activity → Delineator` with the automatic refresh off must show the four
corners in the description-label dropdown and the corner vocabulary in the date-label
dropdown, with no validation error, before any explicit Refresh.

## Exclusions

No schema change, no scene or renderer change, no automatic re-parenting, and no
vocabulary stored per row.
