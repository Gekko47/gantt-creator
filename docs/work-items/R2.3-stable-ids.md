# Work item — R2.3

## Outcome

`GanttCreator.Core` owns stable row identity as pure, immutable, Office-free code: `GanttRowId` generates opaque text IDs once (`G-` plus 32 lowercase hex digits), parses them strictly (Ordinal, trimmed, no case-folding, `TryParse` never throws), and contract tests prove IDs survive insert, sort, move, and delete independent of row number.

## Scope

- `docs/work-items/R2.3-stable-ids.md` (this file)
- `src/GanttCreator.Core/GanttRowId.cs` — immutable value object: `New`, `Parse`, `TryParse`, value equality
- `tests/GanttCreator.Core.Tests/GanttRowIdTests.cs` — contract tests
- `docs/REPO-MAP.md` — Core mapped responsibility gains stable row identity

### Decisions recorded here

- **D1 — Format `G-` plus 32 lowercase hex digits.** Full `Guid.NewGuid()` entropy (`"N"` form) with a constant `G-` prefix. The prefix guarantees the first character is a letter: Excel keeps the cell as text (an all-digit 32-character value would exceed Excel's 15-digit precision, and a leading `=`/`+`/`-`/`@` would parse as a formula), and the same neutral ID space serves `Id`, `LaneId`, and `ParentId`. Lowercase-only, Ordinal, mirroring R2.1 D4 (no case-folding, no guessing). Changing the format later is a schema migration; the schema version stays 1 in this item.
- **D2 — Parse policy mirrors the catalogue.** `TryParse` trims, matches Ordinally, and never throws; `Parse` throws `ArgumentNullException` on null and `FormatException` on malformed text. Both error paths have positive tests in the same commit (AGENTS.md validator rule).
- **D3 — No cross-row uniqueness validator here.** Duplicate/missing-ID policy is R2.5 (all-errors validation) and repair is R2.10. This item proves single-ID well-formedness, generator uniqueness, and operation preservation only.
- **D4 — No Office production code.** Excel moves whole table rows on sort/insert/move/delete, so preservation in live Excel is inherent to storing the ID as a cell value; R2.3 adds no adapter calls. The Required Office gate is manual F5 evidence (steps below), not a new `OfficeIntegration` test; row-insertion commands are R2.8.

## Acceptance tests

- **Automated** — `dotnet test tests/GanttCreator.Core.Tests` (all green, including the new `GanttRowIdTests`):
  - generation: well-formed (`TextLength`, `Prefix`, round-trip); 1,000 generated IDs unique; first character Excel-text-safe;
  - well-formedness: 100-value round-trip (`New` to `Value` to `TryParse` to equal);
  - validator positives: `TryParse` rejects malformed shapes (null, empty, whitespace, missing/wrong prefix, short/long, non-hex, uppercase, embedded whitespace) with no throw; `Parse` throws `ArgumentNullException` on null and `FormatException` on malformed text;
  - preservation: synthetic rows survive middle/top/bottom insert, Ordinal sort by an unrelated key, head/tail move, and head/tail/middle delete with the ID-to-row pairing intact and IDs distinct;
  - culture invariance under `tr-TR` (generation, round-trip, uppercase rejection).
- **Automated** — `dotnet test tests/GanttCreator.Architecture.Tests`: Core stays Office-free (no new references).
- **Office host (Required)** — manual F5: initialise a blank workbook (R2.2 path), enter 3–5 synthetic rows with generated IDs, save, sort by `Description`, insert a row in the middle; every `Id` cell travels with its row and uniqueness holds. **Not run in this commit** (no Office code changed; requires a human Excel session) — recorded as deferred evidence that blocks marking R2.3 done.
