# Work item — R9.6

> Documentation-first row; its "code" is a validated mapping example.

> **Guide status**: Authored (Tier B — binding contract) 2026-09-21 ·
> upgrade to Tier A at Phase 8 exit. Depends on: the final column
> schema (`GanttTableSchema.Default`) + the Type catalogue.

## Outcome

Users migrating from the legacy macro tool have a documented,
**validated** mapping from its workbook columns to `tblGanttData`
columns — documentation checks pass, and a synthetic legacy workbook
example proves the mapping end to end (a human follows it once).

## Context and owed deferrals

Roadmap row: *Document manual recreation/mapping from legacy workbook
columns — Documentation checks and synthetic mapping example
validation — Required: follow the mapping once using a copied
synthetic legacy workbook.*

Phase 9's goal: "make … the transition from the macro tool
understandable." The mapping is **manual recreation** — no automatic
legacy import exists or is implied (the roadmap's out-of-scope list
keeps schedule-file import out).

## Governing contracts

- [`../07-GANTT-ENTITY-GUIDE.md`](../07-GANTT-ENTITY-GUIDE.md) —
  "Required worksheet fields" + the Type catalogue (the target
  columns/values the mapping targets).
- `GanttTableSchema.Default` (the 14 columns) — the mapping's
  authority; no invented columns (`Duration` stays forbidden).
- `AGENTS.md` — the product is not a CPM engine and must not imply
  contractual analysis; the mapping document must keep that framing.

## Step 0 — verify prerequisites

- The final schema/catalogue frozen for this release; the docs
  location fixed (e.g. a `docs/` user-facing page — the exact home
  chosen at Tier-A upgrade; it is *documentation*, checked by the
  repo's doc gates).
- A synthetic legacy workbook shape defined (representative legacy
  columns; **clearly synthetic** — no customer data, no proprietary
  template reproduction).

## Scope

- The mapping document: legacy column → `tblGanttData` column, value
  conventions (dates as domain values; Type display names from the
  catalogue; IDs are generated not imported), and an explicit
  limitations section (what cannot be mapped: any CPM-derived fields,
  dependency logic — the product does not compute them).
- A synthetic mapping example (a legacy-shaped sample + the expected
  `tblGanttData` result) validated by a test that builds the expected
  table and asserts the documented mapping rules mechanically where
  possible (column order, display-name values).
- Documentation checks: the doc gates (links, status) + a review
  checklist that a human followed the mapping once.
- `docs/REPO-MAP.md`, `docs/STATUS.md`, status line.

## Exclusions

- No automatic legacy import (out of scope by the roadmap); no
  proprietary template reproduction; no CPM/dependency fields; no
  new schema.

## Design decisions (behavioural)

- **D1 — Manual, documented, validated.** The deliverable is the
  document + the synthetic example; the automated gate validates the
  example's target table mechanically and the doc gates validate the
  document; the human gate follows the mapping once.
- **D2 — Honest limitations.** The document states what cannot be
  migrated and why (no calculation semantics exist to import) — the
  product-boundary framing, never an implied CPM promise.
- **D3 — Synthetic only.** The example uses invented data; no
  proprietary template re-creation (AGENTS.md data/font rules).

## Acceptance tests

- **Automated**: the synthetic example builds the expected
  `tblGanttData` (column/display-name assertions); doc gates green.
- **Office host (Required, human)** — follow the mapping once using a
  copied synthetic legacy workbook; record the walkthrough + host
  builds.

## Stop conditions (item-specific)

- The mapping would require a schema change → stop (the schema is
  frozen; a change is a migration with its own ADR).
- A legacy column implies calculation semantics → stop; the
  limitation note is the answer, not a feature.

## Risk and rollback

Main risk: over-promising migration completeness — D2's limitations
section is the guard. Rollback: `git revert`.
