## Design decisions (behavioural)

- **D1 — One translation, once.** Each primitive's points translate
  to the staging origin by a single vector (add origin; snap once at
  the R4.3 boundary); no per-primitive scaling or re-layout.
  **Verified seam, 2026-11-18:** the export scene is already built at
  a zero origin (`PanelCellGrid`'s `originTopPt` defaults to zero for
  export compositions, and `SheetCoordinates` is false on an export
  request so no live half-stroke inset applies), so staging is exactly
  one vector added at the `OfficeShapeRequest` boundary — the
  `SceneShapeRenderer` → `ExcelShapeWriter` path needs a staging
  offset seam, not a second geometry pass. Staged shapes never enter
  the ADR-0052 host-owned resize classes; they are temporary and
  deleted, never reconciled.
- **D2 — Bounds equality is the contract.** The composed set's
  bounding box equals the R6.1 export bounds within
  `GeometryMath.Epsilon` (the documented tolerance); a shape outside
  the bounds fails the test (**positive test** with a stray-shape
  fixture).
- **D3 — View discipline.** Staging never scrolls/activates corrupts
  the user's view: view state (scroll, zoom, selection) is captured
  and restored around the operation (the R4.2 scope); the live gate
  proves real content and view survive.
- **D4 — The staging origin needs a value, not just a rule (open
  decision, named 2026-11-18).** The architecture states the rule —
  deterministic, same worksheet, outside the working view — but no
  number exists anywhere. Tier-A upgrade fixes one: **proposal** — a
  fixed offset to the right of the measured chart union (so it can
  never collide with the table or the plot at any column width),
  snapped at the R4.3 boundary, recorded in this file and the entity
  guide's export section. A proposal is not a decision; the owner
  confirms the value before R6.2/R6.3 implement it.
- **D5 — A coalesced automatic refresh during staging must be safe
  (added 2026-11-18).** Chart-affecting worksheet edits schedule a
  coalesced refresh (R5.11/ADR-0050), and nothing suspends the
  scheduler while a composition is staged. Safety comes from R6.2's
  D4 staging identity, not from suspending refresh: the reconciler
  ignores staging-tagged shapes, so a refresh that fires mid-staging
  reconciles the live chart and leaves the staging set alone
  (**positive test**: schedule a refresh during staging; staging
  shapes survive; the live chart reconciles).

## Implementation record (2026-11-18)

- **Files.** Core: `StagedEnvelopeCheck.cs` (the bounds-equality contract, with
  `StagedEnvelopeResult`), the additive `GanttTableAppearance.BodyFill` /
  `BodyTextColour` token reads, and `ExportBoundsRefusal.AnchoredRequest` + its guard
  in `ExportBoundsResolver`. Office: `ExcelSceneBuildRequestFactory.CreateExport` (plus
  the `CreateCore` extraction both modes delegate to), `ExportPanelTheme.cs`, and
  `EditablePanelStagingComposer.ComposeFullScene` (plus the shared `Stage` loop).
  Tests: `StagedEnvelopeCheckTests`, the anchored-request and export facts in
  `ExportBoundsResolverTests` / `ExcelSceneBuildRequestFactoryTests`,
  `FullSceneStagingComposerTests`, the shared `StagingSchemeWriters` fake (extracted
  from `ShapeStagingOwnershipTests`), and the live
  `FullSceneStagingIntegrationTests`.
- **D4 closed by R6.2's record.** The origin value was already fixed as
  `StagingOriginFor(chartBounds) = (Right + 20pt, Top)`; R6.3 reuses it verbatim and
  the live gate judged the margin on the host. The staged set landed beside the chart
  with no view disturbance, so no ADR path is opened.
- **D1 enforced, not assumed.** `ComposeFullScene` re-stamps every translated request
  with `HostOwnsExtent = false`; the contract test proves the fixture's band and
  delineator ARE host-owned before staging, and the live gate asserts
  `Placement = xlMove` on every staged shape.
- **Two measured corrections from the live gate (2026-11-18, Excel
  16.0.20527.20196 x64).**
  1. *Export geometry.* Composed from the live measured top, the export chart's bands
     landed at Y = −28pt and the host clamped every one to 0 (18 shapes outside the
     envelope). `CreateExport` now converts the measurements to export coordinates:
     zero-origin grid, `ChartPaddingPt.Uniform`, and a plot top of
     `chrome + year + period (+ title when present)`. A factory fact pins the positive
     plot top so the defect cannot return.
  2. *Host precision.* Excel stores shape geometry in single precision
     (514.3622047pt requested, 514.3621826pt read back, ≈2.2e-5pt). The exact
     `GeometryMath.Epsilon` equality remains pinned on the translated requests; the
     live read-back asserts the same equality within
     `HostOwnedGeometry.GeometryMatchTolerancePt` (the documented "above float
     rounding" tolerance). This is a recorded host-precision fact, not a widened scene
     tolerance or a padded bound.
- **D5 proved at both levels.** The contract scenario runs the real
  `ShapeReconciler.Plan` against a live-scheme writer while a staging-scheme composer's
  shapes exist on one modelled sheet; the live body runs the real `Reconcile` while the
  staged set exists. Both converge the live chart and leave every staged shape in
  place. The remarks record the fidelity limit: staging writes no cells, so it cannot
  itself schedule a refresh.
- **D3 measured, not extended.** The live body wraps the staging operation in
  `ExcelApplicationStateScope` and asserts scroll row, scroll column, zoom and the
  selection address are unchanged afterwards. The measurement shows no disturbance, so
  the R4.2 scope was not extended (the plan's option (a) outcome).
- **Gates observed.** Core 2128/2128; Office contract 1514/1514; AddIn 810/810;
  Release build 0 warnings / 0 errors; the live full-scene body 1/1 in 16 s on the
  reference host. `verify-quick.ps1` and `verify-office.ps1` are reported in the
  handoff; the wrapper's 780 s clock remains the pre-existing R6.2/R6.7 caveat.
