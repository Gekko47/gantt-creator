# R8.9b — Custom width: ribbon, live readouts and persistence

- **Status:** Complete (2026-11-26), width-only
- **Implements:** [ADR-0072](../adr/0072-custom-export-canvas.md) (custom width),
  [ADR-0073](../adr/0073-additive-settings-schema-repair.md) (schema 29 repair)
- **Depends on:** R8.9a (the keys and the in-place repair), R4.7H D7 (the preset is the
  width budget), R6.1 (export bounds), R8.2–R8.8 (PNG)
- **Owner decisions:** 2026-11-26 — the custom width is the whole composition width;
  the page presets and margin maths are ignored while Custom is active; **a custom
  height cannot be entered** because it cannot be honoured without forcing a fixed
  ratio; the live plot width and height are shown for every mode; `SizeHeightCm` reads
  live from the plot; width and height are shown in centimetres only.

## Outcome

The Size group offers **Custom** with one width box in centimetres. The width is the
whole composition width: the data table keeps its measured column widths and the plot
takes whatever they and the frame chrome leave, with `marginPt = 0`. The ribbon shows
the live plot width and the measured plot height for presets and Custom alike. Every
export reproduces the live composition at its own size.

There is no height input, no ratio, no export canvas, no letterbox and no scaling.

## Scope delivered

- `CustomSizeCm` is the validated **width** (1.0–200.0 cm band, finite checks, points
  conversion) with `ClampWidth`/`FromClampedWidth` for every read path.
- `SizePresets.Custom` builds the runtime preset from the width on both axes; the
  preset height is explicitly **not a page** and nothing consumes it. `All` and
  `ByKey` stay fixed-only.
- `ExcelSceneBuildRequestFactory` resolves `SizePreset = Custom` from `SizeWidthCm`
  alone, clamps an out-of-band stored width, and zeroes the margin. The reserved
  height can no longer refuse the mode.
- AddIn: `SizeCustom` item (RibbonX control ids are global across the tab, so the item
  cannot reuse the margin dropdown's `Custom` id; the stored settings value stays
  `Custom`), `edtSizeWidthCm` with a `cm` unit, `GetMarginEnabled`, and the
  `edtMarginCm` gate ANDed with `!IsCustomSize`. Margin controls are disabled, not
  hidden; stored values survive.
- `RibbonStateService.SetSizeWidthCm` clamps to the band **and** to the workable
  minimum, commits, computes the new plot width from the measured panel, mirrors the
  height and persists. `SetCustomSizeMode` pre-fills from the current composition
  width. `PlotRangeProjection.ReadCustomPreset` clamps, so the mode never collapses.
- One panel measurement (`MeasurePlot`) feeds the plot-width readout, the workable
  minimum and the `SizeHeightCm` mirror; the readouts are refreshed on activation,
  workbook change, refresh, preset/margin/size change and column-visibility change.
- The height readout and the `SizeHeightCm` mirror are the measured live plot height,
  never a stored page dimension.
- Withdrawn in this row: `ExportCanvas`, `ExportCanvasPlacementPlanner`,
  `ExportBounds.Canvas`/`CanvasPlacement`,
  `ExportBoundsRefusal.ContentExceedsCanvas`/`InvalidExportCanvas`,
  `SceneBuildRequest.ExportCanvas`, the height edit box, the custom readout and the
  three canvas refusal messages.

## Decisions

| # | Decision | Rationale |
| --- | --- | --- |
| D1 | The width is the whole composition width. | The table cannot change column width, so the plot absorbs the difference. |
| D2 | A too-narrow width is raised to the workable minimum. | The user should not be able to type a value the renderer must refuse. |
| D3 | An out-of-band stored width is clamped at the read. | Refusing would show no preset while the workbook says Custom. |
| D4 | No custom height. | A typed height needs a row resize or a scale; neither is a size control. |
| D5 | `SizeHeightCm` is a measured mirror. | The row cannot be removed (append-only repair), so it carries the truth instead of a dead default. |
| D6 | Selecting Custom pre-fills from the current width. | A 16:9 user keeps the width they were looking at. |
| D7 | The live width and height are shown for presets too. | A wider measured table shrinks the plot inside the same page; the user should see it. |
| D8 | The readouts are centimetres only. | Owner ruling; the ribbon shows no point value. |
| D9 | The size item id is `SizeCustom`, not `Custom`. | RibbonX ids are global for the whole tab: `Custom` is already the margin item, and a duplicate aborts the entire custom UI load. |

## Follow-ups

- Run `verify.ps1` on the clean tree and `verify-office.ps1` for the v28 upgrade and the
  custom width path.
- If the size table validates `SizeHeightCm` as a user value anywhere in future,
  remember it is a mirror: it must be written from the measurement, never read as an
  input.
- Any new ribbon control must take a globally unique id; the uniqueness test only sees
  `Ribbon.xml`, so a control built entirely in code still needs a distinct constant.
