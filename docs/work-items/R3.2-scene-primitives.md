## Design decisions

- **D1 — Namespace and folder.** `src/GanttCreator.Core/Scene/`,
  `namespace GanttCreator.Core.Scene` (the `Logging/` precedent).
- **D2 — Primitive set is exactly the architecture's list.**
  `ScenePrimitive` (abstract sealed-hierarchy record: `PrimitiveId`,
  `OwnerId` (`GanttRowId`), `ZLayer`) with `SceneRect` (`RectD Bounds`,
  resolved style tokens), `SceneLine` (`PointD From/To`, stroke token,
  width token), `ScenePolygon` (ordered `PointD` list — milestone
  diamonds are four-point polygons; no special diamond kind), `SceneText`
  (text, `RectD TextBounds`, typography token, alignment), `SceneGroup`
  (group metadata: group id + ordered child `PrimitiveId`s — the export
  composer's grouping substrate, Phase 6). Layout-scene entities such as
  bands and headers own their rows' IDs or a documented chart-frame
  owner id; the guide's `GanttCreator.` ownership prefix belongs to the
  Excel shape layer (Phase 4), not the scene.
- **D3 — Stable role-derived primitive IDs.** `PrimitiveId` is a
  deterministic string of owner + role (for example
  `<rowId>:bar`, `<rowId>:label`, `<rowId>:delineator-line`) — the
  entity guide's splitter `Both` case ("two scene text entities with
  stable role-derived IDs") generalised. No `Guid` after row creation.
- **D4 — Z-order exactly the guide's table.** `ZLayer` enum with the 11
  layers and their documented members; `ActivitySubtypePriority`
  encodes the layer-40 rule (baseline 0, baseline-procurement 1,
  planned 2, planned-procurement 3, actual 4, actual-procurement 5,
  custom 6, delay 7) so `GanttScene` can order layer 40 deterministically
  by (subtype priority, lane, stack, `SortOrder`, stable ID).
- **D5 — `GanttScene`.** Immutable record: `ChartBounds`/`PlotBounds`
  (`RectD`), `IReadOnlyList<ScenePrimitive>` already ordered
  deterministically, `IReadOnlyList<SceneWarning>` (owner id, code,
  message — non-exported indicators per entity guide §26). Constructor
  validates: no primitive with non-finite/negative geometry enters the
  scene (checklist B) — a typed refusal, not a throw.
- **D6 — Deterministic serialisation.** `SceneSnapshot.Serialize(
  GanttScene)` → canonical JSON: fixed member order, invariant culture,
  no indentation, styles as `#RRGGBB` — and `Deserialize` with strict
  validation (unknown fields, non-finite numbers, negative extents
  reject). This is the Phase 3 exit artifact ("deterministic scene
  snapshot") and R3.12's validator input.

## Implementation steps (in order)

1. `ZLayer` + `ActivitySubtypePriority` with XML docs quoting the
   entity-guide table (source-of-truth citation in remarks).
2. `ScenePrimitive` base + the five sealed records per D2/D3.
3. `SceneWarning` + `GanttScene` per D5 (constructor guard with typed
   refusal outcome).
4. `SceneSnapshot` per D6 (serialize/deserialize + strict reader).
5. Tests: primitive equality/ID stability; z-order sort pins (layer
   ascending; layer-40 subtype rule; lane/stack/sort/ID tiebreaks);
   grouping (child ids resolve; group order stable); serialization
   round-trip (serialize → deserialize → identical scene);
   **determinism: the same primitive set shuffled ≥3 ways serializes
   byte-identically** (checklist B); strict-reader positives (unknown
   field, `NaN`, negative extent each reject — **positive tests**);
   scene-constructor refusal positives.
6. Docs: REPO-MAP, STATUS, status line. One commit: `feat: R3.2 …` —
   Checklist: B, E, G, I.
