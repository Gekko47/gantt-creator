## Design decisions (behavioural)

- **D1 — Final hierarchy roles (owner ruling 2026-10-10).**
  `Splitter`/`Spacer` are standalone top-level only
  (`MayOwnChildren=false`, `MayBeChild=false`, `ParentId` stays blank —
  still `NotUsedByType`). Milestones (all four) are leaves: top-level or
  child, but never own (`MayOwnChildren=false`, `MayBeChild=true`).
  Activities, procurement, delay events, `CustomActivity` do both.
  `CriticalInterval` and `Delineator` are child-only, never own.
  `ParentIdIsRelevant` follows `MayBeChild`, so `Delineator` gains a
  meaningful `ParentId` (collapse-only; rendering stays `PlotGlobal`).
- **D2 — Promote = move down to group bottom, then clear, then
  resequence (owner ruling 2026-10-10).** The promoted child's table
  content moves to the bottom of its own sibling run; its `ParentId` is
  cleared; the remaining children's `SiblingOrder` run is resequenced
  densely to close the gap. A row that owns children cannot be promoted
  (`HasChildren` refusal — no cascade). A `CriticalInterval` can never be
  promoted. IDs, schedule data, `LaneId` are untouched.
- **D3 — Demote = nearest eligible parent above (owner ruling
  2026-10-10; amended 2026-10-11).** The scan walks body order
  upward, skipping `Delineator` rows and every non-owner type
  (splitter/spacer/milestone/critical/delineator). A candidate
  is accepted only when the selection lands directly beneath its
  existing child run — every row between them is already the
  candidate's child — because Excel's outline groups only the
  contiguous block directly beneath a parent (`OutlineGroupPlanner`
  anchors a group at `parentRow + 1`). A separated landing
  refuses with `LandingNotAdjacent`: the demotion would write a
  `ParentId` the outline can never show, and no parent further up
  can be adjacent either. A candidate the selection extends but
  that is at capacity (7) refuses with `ParentUnavailable` for
  the same reason. Depth-3 candidates (a child) are skipped.
  No eligible row above, or an already-a-child selection, refuses
  with a simple-English warning and moves nothing. Critical rows
  demoting under a non-span refuse with a span warning and move
  nothing. No physical row move on demote — `ParentId` rewrite
  plus `SiblingOrder` tail assignment in the new run.
- **D4 — `SiblingOrder` authority (new; none exists today).** Verified
  2026-10-10: no engine derives or writes `ParentId`/`SiblingOrder` from
  row position. R5.3 defines it: dense `0..n` within each sibling run and
  the top-level run; the R5.3 Core planner computes it, the R5.3 Office
  mutator is its sole writer; Refresh never rewrites it. The user never
  enters either value.
- **D5 — Guard-first, typed refusals, execution-time eligibility.**
  Protection guard runs before any workbook/table access; refusals
  (`NoActiveWorkbook`, `TableMissing`, `TargetProtected`, plus planner
  refusals) mutate nothing (**positive tests**). Buttons stay gated on
  `HasActiveWorkbook && SheetInitialised`; a wrong-kind selection
  (promote a parent, demote a child) warns in simple English with the row
  number instead of greying.
- **D6 — Command surface.** Thin ribbon callbacks through the boundary;
  success is silent-or-count-only per R2.2/R2.6; messages live in
  the AddIn-layer `ParentChildRefusalTranslator` (one table shared
  by both verbs), never in callbacks.
