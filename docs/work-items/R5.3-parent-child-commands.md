## Design decisions (behavioural)

- **D1 — Splitter parenting is a display grouping.** Setting a row's
  parent to a `Splitter` (or clearing it) reorders/groups for display;
  it never changes `Id`, never touches geometry directly, and is
  visible only after Refresh. Critical-interval `ParentId` semantics
  (span parent) are untouched and separately validated (R2.5).
- **D2 — Lane reassignment preserves identity.** Changing `LaneId`
  rewrites exactly that cell (bulk write); the `Id` never changes;
  lane ordering then follows R3.4 D2 and the effective stack is re-derived
  from row/parent-child display position on Refresh. No generated value is
  written to the visible `StackIndex` compatibility cell.
- **D3 — Guard-first, typed refusals.** All commands run the R2.7a
  protection guard first; refusals (no workbook, no table, protected,
  invalid parent target) mutate nothing (**positive tests**).
- **D4 — Command surface.** Thin ribbon callbacks through the
  boundary; success is silent-or-count-only per the R2.2/R2.6
  discipline.
