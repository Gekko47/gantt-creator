## Step 0 — verify prerequisites (re-verified 2026-09-26 against landed code)

- R4.1/R4.2 landed; the Phase-3 primitives this row converts are
  `SceneRect` (with `Bounds`) and `SceneLine` (with `From`/`To`), both
  deriving from `ScenePrimitive` (`PrimitiveId`, `OwnerId`, `ZLayer`,
  `EntityType`, `LaneOrder`, `StackIndex`, `SortOrder`) —
  `src/GanttCreator.Core/Scene/SceneRect.cs`, `SceneLine.cs`,
  `ScenePrimitive.cs`, landed in R3.2 `e244d3c`. `ScenePrimitive.CreateId`
  is the one id factory, so the shape name has a single source.
- The one rounding boundary exists and is the only one:
  `GeometryMath.SnapToDisplayPrecision` (returns `float`) with
  `GeometryMath.Epsilon = 1e-6` and `ApproximatelyEqual` as the
  comparison — `src/GanttCreator.Core/GeometryMath.cs`, R3.1 `b5314c7`.
  Renderers must not pre-round: the scene values are already in points.
- **The Office shape kind for a scene line is still unprobed, and D3's
  "fixed at Tier-A upgrade" is therefore not yet answerable from
  documentation.** Probe the installed
  `Microsoft.Office.Interop.Excel.dll` for the line/connector members
  and their `Left`/`Top`/`Width`/`Height` versus `BeginX`/`BeginY`/
  `EndX`/`EndY` behaviour, record the row, and stop if exact endpoints
  cannot be expressed. Do not pick a shape kind from memory.
- **The chart's negative origin is a real placement case, and how the
  host handles it is still unprobed.** Entity guide §1 now records a
  *provisional* rule: a renderer translates the chart bounds to a zero
  origin and carries the delta, because `ChartBounds` is derived by
  expanding the content union by `ChartOuterPaddingPt` and so starts at
  minus one padding whenever the content starts at the origin. Excel
  cannot express a negative shape offset, so the placement must be
  computed. **Probe obligation for this row:** establish, against the
  installed interop assembly and a live shape, (a) whether a negative
  `Left`/`Top` is rejected, clamped, or silently re-anchored, and (b)
  which cell the host anchors a shape to when its offset is zero. Then
  confirm the implementation translates by one uniform delta across
  every primitive kind and carries that delta into the export bounds
  (R6.1). Do not infer the host behaviour from the rule - the rule is
  what the host must end up doing, not evidence that it does.
- The `GanttCreator.` ownership tag member is created by R4.1 D2; this
  row only *writes* it. The scene-side inputs are `OwnerId` and
  `PrimitiveId` (R3.14 decision, 2026-09-26).

## Design decisions (behavioural)

- **D1 — Geometry from the scene, snapped once.** Left/Top/Width/
  Height derive from the primitive's point geometry; the port's
  internal `SnapToDisplayPrecision` call is the only rounding; tests
  assert within `GeometryMath.Epsilon` of the scene values (the
  documented tolerance).
- **D2 — Name = stable scene primitive ID; tag = `GanttCreator.`
  prefix.** Both set at creation and preserved on update; the pair is
  the reconciliation key (R4.7) and the ownership filter (R4.8).
- **D3 — Lines as connectors/shapes with exact endpoints.** The Office
  shape kind for a scene line is **still an open probe**, not a settled
  decision: line versus connector behaviour differs, and neither may be
  chosen from memory. The contract either way is exact From/To points
  within `GeometryMath.Epsilon`. Record the probe result here before
  implementing; if a kind cannot hold both endpoints exactly, stop for
  the spike-plus-ADR path.
- **D4 — No recalculation.** The renderer never recomputes a date, a
  lane position, or a colour from the row data — only translates
  primitives (entity-guide rule; a contract test asserts no
  table-read occurs during rendering).

## Stop conditions (item-specific)

- Geometry mismatch beyond tolerance on a live host → stop with the
  evidence (unit-system mismatch, e.g. points vs pixels — record and
  resolve via the documented boundary, never a local fudge factor).
- A shape kind the PIA cannot express with exact points → stop;
  spike + ADR path.

## Risk and rollback

Main risk: unit-system confusion (Excel shape geometry is in points,
but `Left/Top` variants differ per shape kind) — the live gate exists
precisely to catch it early. Rollback: `git revert`.
