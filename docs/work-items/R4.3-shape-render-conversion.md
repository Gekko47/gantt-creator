## Design decisions (behavioural)

- **D1 — Geometry from the scene, snapped once.** Left/Top/Width/
  Height derive from the primitive's point geometry; the port's
  internal `SnapToDisplayPrecision` call is the only rounding; tests
  assert within `GeometryMath.Epsilon` of the scene values (the
  documented tolerance).
- **D2 — Name = stable scene primitive ID; tag = `GanttCreator.`
  prefix.** Both set at creation and preserved on update; the pair is
  the reconciliation key (R4.7) and the ownership filter (R4.8).
- **D3 — Lines as connectors/shapes with exact endpoints.** The
  Office shape kind for a scene line is fixed at Tier-A upgrade after
  a PIA probe (line vs connector behaviour differs); the contract is
  exact From/To points within tolerance either way.
- **D4 — No recalculation.** The renderer never recomputes a date, a
  lane position, or a colour from the row data — only translates
  primitives (entity-guide rule; a contract test asserts no
  table-read occurs during rendering).

## Acceptance tests

## Stop conditions (item-specific)

- Geometry mismatch beyond tolerance on a live host → stop with the
  evidence (unit-system mismatch, e.g. points vs pixels — record and
  resolve via the documented boundary, never a local fudge factor).
- A shape kind the PIA cannot express with exact points → stop;
  spike + ADR path.

## Risk and rollback

Main risk: unit-system confusion (Excel shape geometry is in points,
but `Left/Top` variants differ per shape kind) — the live gate exists
precisely to catch it early. Rollback: `git revert`.
