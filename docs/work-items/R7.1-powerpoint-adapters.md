## Outcome

The narrow PowerPoint application/presentation/slide adapter ports and the ownership
rules for their COM proxies exist in `GanttCreator.Office` — every proxy the add-in owns
is tracked and released exactly once in reverse order, nothing it does not own is touched
or terminated, and the adapter is statically typed against the PowerPoint PIA. Pinned by
fake-adapter lifecycle, ownership and source-shape tests.

## Design decisions (behavioural)

- **D1 — Typed interop, primitive ports.** The adapter uses the typed PowerPoint PIA;
  the port signatures use only primitives, `RectD`/`SizeD`, enums and records. No
  interop type crosses a port boundary (CS0433 discipline). No `dynamic`; no
  `Microsoft.CSharp` reference in the Phase-7 files.
- **D2 — Ownership is explicit, testable and non-destructive.** The tracker records
  every owned proxy; release happens in reverse order through the tested ownership
  helper using `Marshal.ReleaseComObject`; **never** `Marshal.FinalReleaseComObject`,
  never a force release of a shared root, and never `Quit` or `Close` on a
  pre-existing PowerPoint or presentation. If the adapter ever subscribes to a
  PowerPoint event, it owns exactly one connection and detaches it exactly once, the
  `ExcelApplicationAdapter` pattern.
- **D3 — STA only.** Every adapter member documents the STA/main-thread requirement; no
  async wrappers, no `Task.Run`.
- **D4 — Read, never activate.** The adapter resolves the active presentation and slide
  through `Application.ActiveWindow` / `View.Slide`; it never calls `Activate` on a
  slide, window or presentation. A missing or non-document window is a typed R7.2
  outcome. A PowerPoint-specific architecture scan guards the rule (the existing
  worksheet scan cannot see a `slide` receiver).
- **D5 — The port cannot save.** The transfer surface has no `Save`, `SaveAs`, `Close`
  or `Quit` member. R7.6's ownership proof is structural, not a sequence hope.

## Stop conditions (item-specific)

- The package check is unresolved or the new dependency is not approved → stop; record
  the evidence; do not ship a `dynamic` fallback.
- A port member would need an interop type in its signature → stop (CS0433 discipline).
- A required operation can only be reached by activating a slide/window → stop; record
  it; the human decides.
- A file would need `FinalReleaseComObject` or `Quit` to pass a test → stop; the test is
  wrong, not the ownership rule.
