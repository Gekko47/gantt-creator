## Design decisions (behavioural)

- **D1 — Birth-registration.** Every temporary shape registers with
  the lifecycle at creation (R6.2's D3 hook); cleanup walks the
  registry, never a sheet scan (a sheet scan could catch unowned
  shapes — forbidden).
- **D2 — `finally` cleanup, order-deterministic.** Cleanup deletes in
  reverse creation order (group first, then children per the host's
  requirements — probed at Tier-A upgrade); every failure point
  (create, style, group, copy, delete) leaves **zero** temporary
  shapes and restored state.
- **D3 — The ADR design is implemented literally.** Simple delete
  path: delete in `finally` after the copy verifies. Fallback path:
  the short-lived staging workbook is created, used, and removed
  after materialisation — never left behind (a post-operation
  zero-residue assertion covers both paths).
- **D4 — Failure points are injected, not imagined.** Each checklist-K
  point gets a harness injection; the assertion is the observed
  operation sequence + zero residue + restored state.
