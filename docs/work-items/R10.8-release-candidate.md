## Outcome

The release candidate is tagged only after a human go/no-go review —
commit, version, checksums, evidence links, and a clean tree verified,
with all gates and known limitations explicitly accepted.

## Scope

- The verification checklist: tag target commit hash; `VersionInfo`
  matches the release version; checksums match R10.2's manifest;
  evidence links resolve (manifest + run records); working tree clean.
- The go/no-go record: the human's acceptance of every gate and every
  known limitation (a checklist with explicit yes/no per item — no
  blanket approval).
- The tag (only after acceptance, and only when the human asks for
  it in that session).

## Exclusions

- No tagging without the human's explicit go; no gate re-runs beyond
  the checklist (a re-run that changes results restarts the gate); no
  late fixes (a finding at this stage routes to a new item + restarts
  verification).

## Design decisions (behavioural)

- **D1 — The checklist is the gate.** Each item verified from
  artifacts (not memory); any ✗ stops the tag.
- **D2 — Limitations are accepted item by item.** Each open
  KNOWN-LIMITATIONS row gets an explicit accept/defer decision with
  its owner/expiry; blanket "looks fine" is not an acceptance.
- **D3 — Agents verify, humans decide.** The agent assembles and
  checks the evidence; the go/no-go and the tag are human acts
  (AGENTS.md tagging rule).

## Acceptance tests

- **The checklist run** — every item verified with its artifact
  referenced; results recorded in this file.
- **Office host (Required, human)** — the go/no-go review; the D2
  per-limitation decisions recorded; the exit demonstration
  cross-referenced (R10.6).
- **The tag** — created only after D2's record, on the human's
  instruction.

## Stop conditions (item-specific)

- Any checklist item ✗ → no tag; fix/route and restart per the
  scope-change protocol.
- A limitation lacks an accept/defer decision → no tag (D2).
- No explicit human go → no tag (D3).

## Risk and rollback

The tag is the irreversible-ish act; rollback discipline is "do not
tag until true" (deleting/re-tagging is itself a reviewed act). The
checklist + D2 exist to make the first tag the right one.

## Definition of done

The checklist complete with artifacts referenced; the human's per-item
acceptance recorded; the tag created (when instructed) on the verified
commit; STATUS updated (the roadmap's final row).
