## Design decisions (behavioural)

- **D1 — The matrix is closed, typed and complete.** Cases:

  | Axis | Cases |
  | --- | --- |
  | PowerPoint process | not running (starts), running (attaches) |
  | Presentation count | none, one, many |
  | Active presentation | editable, read-only/password-protected, protected view, none |
  | Presentation window | has a document window, has no window |
  | Active view | slide, notes page, normal, slide sorter, outline, thumbnails, master |
  | Slide show | none active, a slide show window is active |
  | Slides | none, one, many; active slide present or missing |

  Each case maps to exactly one typed outcome: `Proceed` with a resolved presentation
  and slide, or a named refusal the command translates to one actionable message. The
  view cases are not optional: `Shapes.PasteSpecial` is documented for slide and notes
  views, and a sorter/outline/master paste must be refused before the call, not after a
  host error. The allowed set is slide, notes page and normal (the probe confirms whether
  the reference build treats normal as slide view); sorter, outline, thumbnails and
  master views are refused.
- **D2 — The decision table is Core-pure.** The Office fact gatherer reads the host and
  calls the table; every branch is testable without a host. The table is the one
  authority for "proceed or refuse" so R7.6 never re-derives a case.
- **D3 — The user-visible policy.** Starting PowerPoint and creating a presentation are
  announced (never silent). Attaching never alters the user's session state beyond the
  transfer itself. A presentation is created only when the button contract says so and
  the decision table's `CreatePresentation` case is reached.
- **D4 — Never activate.** The active slide is read from `Application.ActiveWindow` /
  `View.Slide`. A missing or non-document window is a typed outcome, not a prompt to
  activate something. The PowerPoint-specific architecture scan from R7.1 guards this.
- **D5 — No ownership of a pre-existing host.** `StartedByUs` is true only when the
  pre-call process snapshot had no `POWERPNT` and the call produced one. A pre-existing
  process is never quit, closed or terminated; only the adapter's own RCW reference is
  released at the end.

## Stop conditions (item-specific)

- The button contract (create-new-presentation behaviour) is undecided → stop (Step 0).
- A case cannot be detected without mutating user state or activating a slide/window →
  stop; record; the human decides.
- A required case has no typed outcome because the typed PIA cannot express it → stop;
  record the probe; do not fall back to `dynamic`.

## Risk and rollback

Main risk: attach/start flakiness on real hosts — the live gate runs each case
deliberately; R7.5 owns busy-retry. Rollback: `git revert`.
