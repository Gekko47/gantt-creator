## Outcome

A code-signing hook signs the packaged artifacts without secrets in
the repository or build config: local and CI runs work
secret-free (signing is opt-in via an environment-injected
certificate), controlled verification checks the chain and timestamp,
and Excel loads the signed candidate under production-like Trust
Center policy.

## Scope

- `scripts/` — the signing hook: a step that signs when the
  environment provides the certificate (path/password via env vars or
  the runner's certificate store) and **skips cleanly with a clear
  message** when absent (the secret-free contract).
- The verification step: chain validation + timestamp presence
  (`signtool verify /pa /all` class checks) — flagged as a controlled
  step (runs when signing runs).
- Docs: the operational note (how the certificate is supplied in
  CI/local — env var names, never values) + `tool-versions.psd1` pin.
- `docs/REPO-MAP.md`, `docs/STATUS.md`, status line.

## Exclusions

- No certificate procurement execution by an agent (D-G5 is a human
  procurement); no secrets committed anywhere; no signing of
  non-release builds; no Trust Center changes on user machines.

## Design decisions (behavioural)

- **D1 — Secret-free by construction.** The build never requires
  secrets; the signing step activates only when the environment
  supplies the certificate. A missing certificate produces a clear
  "unsigned build" message — never a silent unsigned "release".
- **D2 — Verification is part of signing.** A signed artifact is
  verified (chain + timestamp) immediately; an unverifiable signature
  fails the step — never shipped on hope.
- **D3 — Release gating.** R10.8's tag requires the signed+verified
  candidate; the unsigned path is for development only (recorded).

## Acceptance tests

- **Automated**: the secret-free contract (build with no certificate →
  clean unsigned message; **positive test**: a bogus certificate path
  → clear failure, not a silent skip); the tool pin.
- **Office host (Required)** — Excel loads the signed candidate under
  production-like Trust Center policy (signed/untrusted-location
  behaviour observed and recorded); the chain/timestamp verification
  output recorded; host builds recorded.

verify rule plus env-only secrets are the guard. Rollback: `git
revert`.
