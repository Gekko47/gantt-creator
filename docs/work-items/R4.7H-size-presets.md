## Outcome

Output size is a first-class preset contract with A4, Presentation 16:9 and
Presentation 4:3 defined exactly; text columns keep their measured widths; the plot
takes the remaining width from one authority; and insufficient remaining width
refuses Refresh with an actionable error rather than resizing user text.

## Scope

- New `src/GanttCreator.Core/SizePreset.cs` — `SizePreset`, exact dimensions,
  orientation, and the three presets
- New `src/GanttCreator.Core/Scene/PlotGeometryResolver.cs` — the **single**
  authority deriving plot bounds
- `src/GanttCreator.Core/Scene/SceneBuildRequest.cs` — carry the resolved preset
  and plot bounds
- `tests/GanttCreator.Core.Tests/SizePresetTests.cs`, `PlotGeometryResolverTests.cs`

## Exclusions

- **No Ribbon size selector** — R5.2 consumes this contract.
- No scale selection (month/quarter/year) — R5.2.
- No PNG width controls — R8.7 consumes this contract.
- No mutation of worksheet column widths by a preset. Ever.

## Design decisions

- **D1 — One authority derives `PlotBounds`.** From the preset width, the measured
  text-panel width, the approved margins/borders, the date range and the scale.
  No command, renderer or Ribbon callback derives it independently — the same rule
  ADR-0023 applied to panel bounds.
- **D2 — The formula is fixed:**
  `PlotWidth = PresetWidth − TextPanelWidth − Margins/Borders`. Everything the
  preset does not consume becomes plot width.
- **D3 — Text and data columns retain their measured widths.** A preset never
  resizes a user text column to make itself fit. This is a hard product rule, not
  a preference: the user's readable column widths are the input, not the output.
- **D4 — Insufficient remaining width refuses.** A typed
  `InsufficientPlotWidth` refusal naming the shortfall, surfaced before any shape
  mutation. It never silently shrinks the text panel, the plot, or the font.
- **D5 — Title and time-header bands use the same composition geometry** as the
  plot, so a preset produces one coherent frame rather than a plot sized
  independently of its header.
- **D6 — Presets carry exact dimensions and orientation**, not approximations. A4
  is portrait or landscape as declared; 16:9 and 4:3 carry exact ratios.
- **D7 — Preset dimensions are a settings/catalogue contract** and join
  ADR-0029's schema bump where they add a `tblGanttSettings` key.

## Acceptance tests

- **Automated** — `dotnet test tests/GanttCreator.Core.Tests`:

## Status (2026-09-30) — IMPLEMENTED in Core; the caller lands with R4.8A

The preset model and the single plot-bounds authority are built and tested. The
**caller** — the factory that resolves bounds for a real workbook — is R4.8A's
`ISceneBuildRequestFactory`, which is this row's one intended production caller and
is why `PlotGeometryAuthorityTests.Only_the_caller_surface_invokes_the_resolver`
currently asserts **at most one** rather than exactly one.

What is true:

- `src/GanttCreator.Core/SizePreset.cs` — `SizePreset`, `SizeOrientation`,
  `SizePresets` with **A4 portrait, A4 landscape, Presentation 16:9, Presentation
  4:3**, exact dimensions, derived aspect ratio, and `ValidateCatalogue`.
- `src/GanttCreator.Core/Scene/PlotGeometryResolver.cs` — the **single authority**
  (D1), the fixed formula (D2), the untouched measured panel (D3), and the typed
  `InsufficientPlotWidth` refusal carrying the shortfall (D4).
- `SceneBuildRequest` gained `Preset` so a caller, a diagnostic and a test can all
  name the budget. It is **not** re-read to derive the plot a second time.
- `tests/GanttCreator.Architecture.Tests/PlotGeometryAuthorityTests.cs` — the guard
  that makes D1 structural rather than a convention.

**Decisions worth recording:**

- **A4 landscape is derived as the exact transpose of portrait.** Re-declaring the
  two orientations separately would let them drift; a landscape page that was not the
  transpose prints on the wrong orientation.
- **The aspect ratio is derived, never stored.** A hand-maintained ratio field would
  eventually disagree with its own dimensions and nothing would notice until print.
- **`ByKey` returns null for an unknown key rather than the default.** Silently
  substituting A4 for an unreadable stored setting would render a chart the user
  never asked for. The caller decides whether to fall back and can report that it did.
- **`PlotGeometryOutcome.Succeeded` is `Geometry.Succeeded`, not a null check.**
  This was a real bug the tests caught on the first run: the insufficient-width
  refusal deliberately returns a **populated** geometry so the caller can report the
  shortfall, and a bare `Geometry is not null` reported that refusal as a **success**.
  Three tests failed at once. The doc comment now says why the null check is wrong.

**The architecture guard was proven to fire, not just to pass.** A deliberate probe
file performing the inline subtraction was dropped into `GanttCreator.Office`, the
suite failed naming the file, and the probe was removed. A guard that has only ever
passed is not evidence of anything.

## Step 0 — verify prerequisites

- `SceneBuilder` already takes **measured** panel geometry as an input and never
  measures or defaults it, and derives chart bounds from the frame geometry rather
  than being supplied them. This row extends that discipline to plot width; re-read
  both before adding a second source.
- R8.1's `ExportSize` already owns width/unit parsing and aspect calculation for
  the PNG. Reuse its rounding and safety limits rather than writing a second
  aspect calculation.

## Stop conditions

- A preset cannot be made to fit without resizing a text column → **stop**. D3 is
  a product rule; the answer is D4's refusal, not a resize.
- A second `PlotBounds` authority appears anywhere → stop; that is the defect this
  row exists to prevent.

## Risk and rollback

Main risk: a second plot-geometry authority creeping into a renderer or command.
Mitigated by D1 and by an architecture test that fails if plot bounds are
constructed outside the resolver. Rollback: `git revert`.
