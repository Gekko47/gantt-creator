# Work item — R2.1

## Outcome

`GanttCreator.Core` owns the workbook schema contract as pure, immutable,
Office-free code: the canonical `tblGanttData` column names (13 required
columns in the documented order plus the optional `SortOrder`), the single
code-owned `EntityTypeCatalog` — all 16 user-selectable row Types with their
full contract metadata from the entity guide (exact display name, entity kind,
date mode, default style key, colour-capability flags, required-style flag,
allowed label positions) — and the current workbook schema version. The
catalogue parses and formats Type display names exactly (Ordinal, trimmed
input, no case-folding, no guessing). No worksheet is created, no cell is
read, no row is validated against user data, and nothing is rendered.

### Decisions recorded here

- **D1 — Full-catalogue scope.** R2.1 defines the complete per-type contract
  metadata (date mode, kind, default style key, colour capability, required
  style flag, allowed label positions) so the "single code-owned catalogue"
  invariant is complete from day one. The deterministic catalogue hash and
  materialisation to `_GanttCreatorConfig` remain in R2.9.
- **D2 — Capability naming.** The guide's "outline" maps to the `Stroke`
  flag, matching the `StrokeColour` column semantics ("per-row outline, hatch,
  critical, or delineator colour override"). Guide wording maps as:
  "Fill" → `Fill`; "Fill + outline" → `Fill | Stroke`; "Hatch + outline" →
  `Hatch | Stroke`; "Stroke" → `Stroke`; "none" → `None`; "style-defined" →
  `StyleDefined`.
- **D3 — `Custom Activity` labels are style-resolved.** Its allowed-label set
  is empty in the catalogue and `RequiresStyleKey` is true; the permitted
  subset is resolved from its required named style (R2.9 style tables). The
  catalogue never invents the subset.
- **D4 — Parse policy.** `TryParse` matches Ordinal on `Trim`-ed input.
  No case-folding, no guessing, never throws; unknown text returns `false`.
  Display names are part of the workbook schema; renaming or localisation is
  a schema migration (schema-version bump).
- **D5 — Initial schema version 1.** Any change to column names/order or to
  catalogue display names or contract metadata is a schema-version bump.
- **D6 — Enum/display-name split.** Display names contain spaces and hyphens
  and cannot be enum identifiers; the enum carries the code identity
  (PascalCase members) and the catalogue owns the exact workbook display
  names.
- **D7 — Column order.** The optional `SortOrder` column is appended after
  `Visible`; R2.2 materialises the header row in this order.

## Exclusions

- Worksheet or table creation, plot anchor, `_GanttCreatorConfig` creation or
  visibility (R2.2).
- Cell-value reading into DTOs, date-system handling (R2.4).
- Row-level validation of user data and error reporting (R2.5, R2.6).
- Versioned settings/style/metric tables on the configuration sheet (R2.7).
- Row add commands (R2.8); catalogue materialisation, `GanttCreator.TypeOptions`
  named range, in-cell dropdown, and catalogue hash (R2.9).
- Custom-Activity style resolution (R2.9 style tables).
- Rendering, Ribbon, PowerPoint, PNG, any new NuGet dependency.

## Acceptance tests

- **Automated** — `dotnet test tests/GanttCreator.Core.Tests` (all green,
  including the new `EntityTypeCatalogTests`, `GanttTableSchemaTests`,
  `GanttSchemaVersionTests`):
  - round-trip: for each of the 16 Types, `Format` → `TryParse` → same member;
  - verbatim display-name fidelity: the 16 exact guide strings, in guide order;
  - verbatim metadata fidelity: a table-driven test replaying the guide table
    (dates read, default style, colour capability, allowed label positions);
  - validator positives: duplicate enum member, duplicate display name, empty
    display name, duplicate column name, empty column name — each throws;
  - parse rejection: unknown text, case variant, embedded whitespace, empty,
    null → `false`, no throw;
  - schema: exact 13 required column names/order, `SortOrder` optional last,
    header-list round-trip;
  - schema version: stable positive int, culture-invariant surface;
  - culture invariance of all catalogue surfaces under a culture with
    different case-mapping/number behaviour (e.g. `tr-TR`).

## Risk and rollback

Main risk: metadata drift between the guide table and the code — mitigated by
the verbatim display-name and metadata-fidelity tests. Rollback: `git revert`
of the single commit; the change is a pure addition with no consumers yet.

From `AGENTS.md`: acceptance criteria have passing automated tests; format,
analyzers, Release build, unit tests, and coverage thresholds pass; no warning
suppressed without a written reason; no test weakened or deleted; public
behaviour documented (XML docs, CS1591); no Office dependency added to Core;
workbook still one visible sheet + one VeryHidden helper (untouched here);
active task, decision log, and known limitations current; diff contains no
unrelated refactor.
