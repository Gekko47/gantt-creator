## Design decisions

- **D1 — Diamond geometry (§20).** Centre = `(DateToX(Start),
  slotCentreY)`; four polygon points at ±`MilestoneSizePt/2` on both
  axes (tip-to-tip width *and* height); z-layer 60; role-derived ID
  `<rowId>:marker`. `Finish`/`LaneId`/`StackIndex` are never read for
  geometry (R2.5 already warns `NotUsedByType` — defence in depth is
  not added here).
- **D2 — Boundary and clipping.** A milestone date inside the inclusive
  range always renders (edge dates included — the point maps onto the
  edge X exactly); a date outside the range emits no marker and one
  warning per event (the coordinate-rules policy; same warning channel
  as R3.6).
- **D3 — Labels via the shared planner.** Milestone labels use
  `LabelPlanner` with the §22 milestone rank (above span labels);
  positions `Left`, `Right`, `Above`, `Below`, `None`; explicit → style
  default → `Auto` → fallback + warning. Same-date milestones on one
  slot centre deterministically (subtype priority then lane/stack/
  sort/ID) with the §9 ambiguity warning.
