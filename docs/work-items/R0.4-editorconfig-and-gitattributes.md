# R0.4 — `.editorconfig` and `.gitattributes`

> Block 0, R0.4 from `docs/03-ROADMAP.md`. Builds on R0.2 (Directory.Build.props).

## Outcome

The repository has a single authoritative `.editorconfig` that:

- Sets C# language conventions (var preferences, brace style, using
  directives, naming, file header rules).
- Configures .NET analyzers so they run with the same severity
  locally and on CI.
- Aligns code formatting across Visual Studio, VS Code, Rider, and
  `dotnet format`.

And a `.gitattributes` that:

- Normalises line endings to LF for source code, PowerShell, YAML,
  JSON, and Markdown.
- Keeps CRLF for files that require it (none currently; documented
  for future).
- Marks generated files as such so they can be excluded from
  diffs and blame.
- Marks large/binary files so Git LFS can be configured later
  without a follow-up.

The `NoWarn` list in `Directory.Build.props` is reviewed. Rules that
the placeholder `UnitTest1.cs` files trigger are documented; the
list will be tightened in R0.5 once the placeholders are replaced.

## Scope


## Risk and rollback

Risk: editorconfig rules could trigger reformatting of existing code
in bulk, which would dwarf the actual change in the diff. Mitigation:
the rules chosen match the code already in the repository. If a rule
mismatches existing code, the diff is reformatted in a follow-up
commit, not silently. Rollback: `git revert <commit>`; the editorconfig
goes with the revert.

## Notes

- The `.gitattributes` for Markdown deliberately keeps `lf`. Some
  Markdown renderers (GitHub in particular) normalise either way,
  but LF is the canonical form. CRLF in Markdown causes diff noise
  on Windows-only edits.
- The `NoWarn` list in `Directory.Build.props` is `$(NoWarn);CA1515;
  CA1812;CA1052;CA1063;CA1305;CA1840;CA2254`. These are the rules
  the xUnit placeholder `UnitTest1.cs` violates. R0.5 replaces the
  placeholders; after that, the `NoWarn` list is reviewed in a
  dedicated commit to remove rules that no longer apply.
