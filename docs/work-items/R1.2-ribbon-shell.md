# Work item — R1.2

## Outcome

The Add-in assembly carries a `GanttRibbon : ExcelRibbon` class that returns a
minimal, valid RibbonX document declaring one **Gantt Creator** tab. Excel-DNA
auto-discovers and registers the class (no `.dna` file change), and automated
contract tests prove the XML namespace, control IDs, and callback contract — all
without Excel. User-reported manual verification confirms that Visual Studio was
used to edit and test the implementation, the minimal Gantt Creator ribbon was
created, and no bugs were found. This records R1.2 as a successful implementation
based on that manual Office-host verification.

Decision recorded here (verified 2026-09-12 against the installed
`ExcelDna.Integration` 1.9.0 assembly): Excel-DNA auto-registers any non-abstract
class inheriting `ExcelDna.Integration.CustomUI.ExcelRibbon` via
`AssemblyLoader.IsRibbonType` → `GetExcelAddIns` instantiates it with
`Activator.CreateInstance` and flags `IsCustomUI=true`; `DnaLibrary.LoadCustomUI`
then calls `ExcelComAddInHelper.LoadComAddIn`. No `.dna` file is required — the
auto-generated one (currently a bare `<ExternalLibrary>`) stays correct. The
`ExcelRibbon.GetCustomUI(string RibbonID)` override must not call the base
implementation, because the base reads `DnaLibrary.CustomUIs` (empty for us and
`null` outside Excel).

## Acceptance tests

- **Automated** (`tests/GanttCreator.AddIn.Tests/GanttRibbonTests.cs`, 7
  `[Fact]`s):
  1. Reflection contract — `GanttRibbon` is public, `[ComVisible(true)]`,
     `ExcelRibbon`-derived, and has a public parameterless constructor (required
     by `Activator.CreateInstance`).
  2. `GetCustomUI("Microsoft.Excel.Workbook")` returns the RibbonX XML.
  3. `GetCustomUI` with any other id returns `null` (guard positive test).
  4. The XML parses; the root is `customUI` with the Office 2009/07 namespace
     (`http://schemas.microsoft.com/office/2009/07/customui`).
  5. Exactly one `tab`, with deterministic id `tabGanttCreator` and label
     `Gantt Creator`.
  6. Callback contract — a pure `ValidateCallbacks` helper confirms every
     callback attribute in the real XML (`onLoad`→`OnLoad`) resolves to a public
     method on `GanttRibbon` with a compatible signature (`()`,
     `(IRibbonControl)`, or `(IRibbonUI)`).
  7. Positive test for the validator — a deliberately broken XML fixture
     (`onAction='DoesNotExist'`) is reported unresolved, proving the contract
     test catches violations (AGENTS.md: every validator ships a positive test).
  - Proven by: `dotnet test tests/GanttCreator.AddIn.Tests -c Release` and
    `pwsh ./scripts/verify-quick.ps1`.
- **Office host** (`Required` per `docs/03-ROADMAP.md`): F5 in Visual Studio
  loads the x64 XLL; Excel shows one Gantt Creator tab with no ribbon errors.
  This gate is demonstrated manually in Visual Studio and cannot be automated.

## Risk and rollback

Risk: the `GetCustomUI` override returning the resource must remain independent
of `DnaLibrary`; the override never reads `DnaLibrary`, so it is safe to
unit-test outside Excel after a `RibbonID` guard. Rollback: revert the R1.2
implementation and resource-follow-up commits. This removes `GanttRibbon.cs`,
`GanttRibbonTests.cs`, `RibbonResources.resx`, `RibbonResources.Designer.cs`,
`RibbonResources/Ribbon.xml`, the `STATUS.md` pointer, the
`GanttCreator.AddIn.csproj` resource metadata, and the architecture note;
verify that no new references or dependencies remain.

## Notes during implementation

- `ExcelRibbon`, `IRibbonUI`, `IRibbonControl` verified in the installed
  `C:\Users\rossj\.nuget\packages\exceldna.integration\1.9.0\lib\net6.0-windows7.0\ExcelDna.Integration.dll`
  (2026-09-12): `ExcelRibbon` is in `ExcelDna.Integration.CustomUI`,
  `GetCustomUI` is `public virtual string GetCustomUI(string RibbonID)`,
  `IsRibbonType` matches any non-abstract descendant, `IRibbonUI`/
  `IRibbonControl` are in the same namespace.
- The Excel-DNA `GetCustomUI` entry point runs on the Excel main STA thread; no
  marshalling is introduced here.
- The RibbonX document is stored in `src/GanttCreator.AddIn/RibbonResources.resx`
  (a `ResXFileRef` to `src/GanttCreator.AddIn/RibbonResources/Ribbon.xml`) and read
  through the committed `src/GanttCreator.AddIn/RibbonResources.Designer.cs`
  accessor — the Excel-DNA CSfull pattern. It is **not** a C# string literal: an
  earlier in-line constant triggered a genuine `dotnet format` vs
  `EnforceCodeStyleInBuild` disagreement (IDE0055) on multiline string wrapping.
  Storing the XML as a resource removes the construct entirely.
  The `src/GanttCreator.AddIn/GanttCreator.AddIn.csproj` carries the
  `NeutralLanguage` property (CA1824) because the assembly embeds resources.
  This pattern is now the standard for embedded XML/HTML/document text
  (`docs/02-ARCHITECTURE.md` § Ribbon and commands).
- Office gate (F5, tab visible, no ribbon errors): **Successful user-reported
  verification** — Visual Studio was used to edit and test the implementation,
  Excel displayed the minimal Gantt Creator ribbon, and no bugs were found.
  Requires Visual Studio against desktop Excel.
