## Outcome

The Ribbon knows which sheet the user is on. When the Gantt sheet is not the active sheet every
chart command is greyed, and the recovery surface — Initialise, Repair, Validate, Diagnostics,
Open log — stays available from any sheet. Entering the Gantt sheet re-reads the workbook, so
the gate is current, and makes the **Gantt Creator** tab the active tab. Every chart refresh
does the same, so a refresh can no longer leave the user looking at the Table Design tab.

- **The gate is a reader fact, not a ribbon guess.** `GanttTableReadOutcome.ActiveSheetIsGanttSheet`
  is true when the workbook's active sheet is the worksheet that carries `tblGanttData`; a
  table-missing refusal falls back to the Gantt label on the active sheet, so the repair
  commands keep their context.
- **Entering the sheet refreshes state, not the scene.** A sheet activation re-reads the
  workbook and invalidates the Ribbon; it does not re-render, because a sheet change is not a
  chart-affecting edit.
- **Tab activation is never selection-driven.** `ActivateGanttTab` runs at the end of every
  refresh and on sheet activation only, and only in `Ready` mode with the Gantt sheet active.
- **Expand all / Collapse all gain the `HasGroups` fact** from the rows the last successful
  read returned, so a flat table shows two greyed buttons instead of two silent no-ops.

No command, menu item, keytip, group or icon was removed.

## Design decisions

- **D1 — Gate on sheet identity, not on the sheet label.** Initialisation can adopt an
  existing visible sheet named anything, so "the Gantt sheet" is the worksheet that owns
  `tblGanttData`. The label is only the fallback when the table is missing.
- **D2 — Five controls are exempt.** Initialise, Repair, Validate, Diagnostics and Open log
  stay enabled on any sheet: a greyed recovery surface with a broken workbook is the one
  state the user cannot escape from.
- **D3 — Fail open on an unknown fact, fail closed on a known one.** The snapshot defaults
  are the permissive direction (matching `IsEnabled`'s documented fail-open rule) so a
  transient probe failure cannot grey the whole tab; the live reader always supplies the
  measured value, so the gate is exact wherever it matters.
- **D4 — One subscription, one ownership rule.** `SheetActivateSubscription` mirrors
  `SheetChangeSubscription`: attach failure degrades to inert, the first dispose disables
  callbacks, teardown never throws, and the shared root event interface is never released.
- **D5 — `ActivateTab` is the only supported mechanism.** RibbonX cannot create a contextual
  tab and cannot pin one; a static hide of Table Design was rejected as globally harmful
  (ADR-0058). `ActivateTab` while the ribbon is collapsed signals S_FALSE and changes
  nothing, which is why no collapse probe is attempted.

The walk, for a future retest:

1. Two visible sheets in one workbook; on the non-Gantt sheet every chart control is grey and
   Initialise, Repair, Validate, Diagnostics and Open log are live.
2. Click into the Gantt sheet: the tab becomes **Gantt Creator** and the controls enable.
3. Edit a table cell with Table Design selected: the coalesced refresh runs and the tab
   returns to **Gantt Creator** without a visible flicker loop.
4. Collapse the ribbon, click into the Gantt sheet: nothing throws and the tab strip is
   unchanged (S_FALSE).
5. Close and reopen the workbook: no double subscription, no failed detach in the log.

## Risk and rollback

- **Risk:** a stale active-sheet fact leaves the tab usable on another sheet. Mitigated by
  re-reading on every activation and every refresh; the commands still validate at execution.
- **Risk:** `ActivateTab` on every refresh fights a user who deliberately chose another tab
  while staying on the Gantt sheet. Accepted by owner ruling D-4; the refresh is the user
  acting on the chart.
- **Rollback:** delete the `SubscribeSheetActivated` call in `SubscribeToSheetChanges`, the
  `ActivateGanttTab` calls, and the `ActiveSheetIsGanttSheet` term in `RibbonState`; the
  reader fact is inert on its own.

## Notes during implementation

- `ActivateTab` fired zero times in the first two guard tests because `Ok([])` with no
  configuration is `NeedsRepair`, not `Ready` (R5.17b). The tests now pass
  `configurationPresent: true`, which is also what makes the negative case meaningful: the
  only reason not to activate is the sheet fact.
- `SqlServer`-style COM comparison was avoided: two RCWs for the same sheet are not guaranteed
  to be reference-equal, so the owner worksheet is compared by name, which Excel keeps unique
  within a workbook.
