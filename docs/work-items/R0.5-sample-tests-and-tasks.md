# R0.5 — Sample tests, OfficeIntegration trait, and `.vscode/tasks.json`

> Block 0, R0.5 from `docs/03-ROADMAP.md`. Builds on R0.4 (analyzers
> and `.editorconfig`).

## Outcome

Each of the six test projects has at least one non-trivial sample
test that exercises the project's purpose. The placeholder
`UnitTest1.cs` files are deleted. The `OfficeIntegration` xUnit
trait is applied to at least one test in
`GanttCreator.Office.IntegrationTests`, and the existing
`scripts/verify-quick.ps1` and `scripts/verify.ps1` filter is proven
to skip those tests. `.vscode/tasks.json` mirrors `verify-quick.ps1`
so VS Code users can run the gate from the palette.

The `NoWarn` list in `Directory.Build.props` is tightened: rules
that the xUnit `UnitTest1.cs` placeholders triggered are removed
because the placeholders are gone.

## Scope

- Delete the 6 `UnitTest1.cs` placeholders.
- Add one sample test class per test project:
  - `GanttCreator.Core.Tests`: a pure-domain value-object test that
    uses no Office/Excel/Skia/clipboard references.
  - `GanttCreator.Raster.Tests`: a width/unit parsing test (no
    golden images yet; those land in R8.x).
  - `GanttCreator.Office.ContractTests`: a fake-adapter test that
    exercises the adapter contract via a small in-memory fake.
  - `GanttCreator.Office.IntegrationTests`: two real-Office tests
    tagged `[Trait("Category","OfficeIntegration")]` that assert
    Excel and PowerPoint COM interop types are registered, each
    with a clear failure message if Office is not installed.
  - `GanttCreator.AddIn.Tests`: a test that loads the AddIn
    assembly and asserts the expected `IExcelAddIn`-related types
    are present.
  - `GanttCreator.Architecture.Tests`: keep the existing
    `CoreBoundaryTests.cs`; just remove the placeholder. The
    `CoreBoundaryTests` file is the sample.
- Add `.vscode/tasks.json` with one task per verify script.
- Tighten the `NoWarn` list in `Directory.Build.props` to remove
  rules that no longer apply.

## Exclusions

- No coverage thresholds. R3.x.
- No mutation tests. R3.x.
- No golden image tests. R8.x.
- No `[Trait("Category","OfficeIntegration")]` on tests that don't
  actually need Office. The trait is for tests that fail on a
  machine without Microsoft 365 installed.

## Acceptance tests

- **Automated**:
  - `dotnet test` discovers and passes all six test projects.
  - `pwsh ./scripts/verify-quick.ps1` → PASS (the OfficeIntegration
    trait is excluded).
  - `dotnet test --filter 'Category=OfficeIntegration'` runs the
    trait tests.
  - The `NoWarn` list in `Directory.Build.props` is shorter than
    before R0.5 (at least two rules removed).

- **Visual Studio / Office**: Test Explorer discovers all six test
  projects and the trait filter works. (Manual check; the
  `Required` gate is met by the fact that `verify-quick.ps1` runs
  the full suite without Office and passes.)

## Risk and rollback

Risk: the sample tests pass locally but may fail on a clean CI
machine that lacks Office. Mitigation: the OfficeIntegration trait
is excluded from `verify-quick.ps1` and `verify.ps1`.
`scripts/verify-office.ps1` is the *automatic* verification path
and is the self-hosted runner policy (ADR-0001). Tests can also
be run explicitly via `dotnet test --filter 'Category=OfficeIntegration'`
or the VS Code `test-all` task. Rollback: `git revert
<commit>`; the placeholders come back, the trait goes away.
