## Step 0 — verify prerequisites (Tier A, revised 2026-11-21)

- R7.1–R7.6 land first; the Office harness's process-ownership sweep (the L13
  fixture-to-shell PID handoff) exists — `OfficeFixture` records the processes it owns
  and `verify-office.ps1` sweeps them.
- **Fix the fixture before the soak runs.** `PowerPointFixture.Initialize` uses
  `Activator.CreateInstance`, which returns the running instance when PowerPoint is
  already open; `DisposeAsync` currently sets `Saved = true`, closes the presentation and
  calls `Quit()` on it. A developer with an unsaved deck open would lose it. Replace the
  late-bound `dynamic` calls with the typed PIA and `new Application()`. The typed
  fixture must:
  1. snapshot the pre-existing `POWERPNT` PIDs and presentations;
  2. adopt only the PIDs created by its own call (`StartedByUs`);
  3. create only a test-owned presentation and slide;
  4. close/quit **only** when `StartedByUs` and only the test-owned presentation;
  5. never touch a pre-existing presentation, window or application.
- **Write the owned-PID manifest.** `OfficeFixture.RecordOwnedProcessId` writes
  `GANTTCREATOR_OWNED_PIDS_PATH` with PID + start time. `PowerPointFixture` has no
  equivalent today. Add the same record (or a shared `OwnedProcessManifest.Record`) for
  each PowerPoint PID the fixture actually starts, so `verify-office.ps1`'s sweep can
  attribute an orphan after a test-host timeout.
- **Split the gate.** The routine `verify-office.ps1` selects
  `Category=OfficeIntegration` and has a **780 s** deadline. The soak is tagged
  `[Trait("Category", "TransferSoak")]` **only** (not `OfficeIntegration`) and runs
  through a dedicated `scripts/verify-transfer-soak.ps1` with its own **measured**
  deadline (measure the 25-transfer run, then set the bound with headroom). Do not raise
  the routine 780 s to fit the soak, and do not add the soak to `verify.ps1`.
- **Record the reference host** (Windows build, Excel build, PowerPoint build, bitness)
  and the timing distribution with the result.

## Design decisions (behavioural)

- **D1 — Counters, not impressions.** Record exact values: Excel/PowerPoint process PIDs
  alive at end vs the owned set (zero unowned orphans); `GetProcessHandleCount` and
  `WorkingSet64` per owned PowerPoint process, sampled per iteration; shapes per slide
  (cumulative only where intended); staging residue (zero every iteration); timings
  (median + max). The handle-count/memory trend must be flat within a recorded
  tolerance across iterations 1→25. There is no public .NET live-RCW counter; do not
  claim one.
- **D2 — Cleanup asserted every iteration.** Zero staging residue after each of the 25
  transfers (not just at the end); a residue at any iteration fails the run loudly.
- **D3 — Exit evidence.** The demonstration run recorded with host builds; the matrix
  subset completed (slide sizes; the PowerPoint-side failure rows); the Phase-8 guides
  upgraded to Tier A with refresh dates; the manifest tiers updated.
- **D4 — The soak is its own category.** `TransferSoak` tests are excluded from the
  routine `OfficeIntegration` run; the dedicated script runs them with the same fixture,
  manifest and watchdog. A soak body that also carries `OfficeIntegration` is a defect
  (it would enter the 780 s gate).
- **D5 — The fixture is non-destructive.** It touches only what it created. A
  pre-existing PowerPoint is observed, never closed, saved or terminated.

## Stop conditions (item-specific)

- A pre-existing PowerPoint or presentation is touched by the fixture → stop; fix the
  ownership model before continuing.

  ownership before anything is killed.
- A soak body is tagged `OfficeIntegration` and enters the routine gate → stop; the
  category split is wrong.
