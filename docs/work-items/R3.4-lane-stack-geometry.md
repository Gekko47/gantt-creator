## Design decisions

- **D1 — §9 formulas verbatim.** The builder assigns effective stack values from row/parent-child display position and maps distinct effective values to consecutive visual slots; `slotHeight = max resolved rectangle height or milestone size in that slot`; `contentHeight = topPadding + sum(slotHeight) + max(0, stackCount − 1) * StackGapPt + bottomPadding`; `laneHeight = max(LaneHeightPt, contentHeight)`; slot centre = lane top + top padding + preceding slot heights/gaps + half current slot height. Events are never compressed (growth only). Sparse effective compatibility values are compacted; visible schema-v1 values are ignored.
- **D2 — Deterministic input order.** Lane order remains `SortOrder` with blank fallback, then row order, then stable `Id`; lanes appear in first-appearance order of that sequence. Within each lane, effective stack order is `RowNumber` (extended by R5.3 parent/child display order), then stable `Id`, and receives consecutive values `0…n`. `SortOrder` is not the stack-position source. `GanttEvent.StackIndex` is compatibility data and is never read.
- **D3 — Splitter and spacer lanes.** A `Splitter` consumes one
  fixed-height lane (`SplitterHeightPt`, spanning data panel + plot,
  no date geometry); a `Spacer` consumes `SpacerHeightPt` with no
  foreground shapes. Both take their position in the lane sequence from
  D2's ordering like any other row.
- **D4 — Same-stack overlap is preserved, warned, never moved.**
  Events sharing a slot share its centre; deterministic z-order comes
  from R3.2's layer-40 rule; a non-blocking ambiguity warning is
  emitted (entity guide §9 Validation) through `SceneWarning`.
- **D5 — Shuffled-input proofs without a new dependency.** "Property
  tests" = xUnit `[Theory]` over ≥3 fixed shuffles plus seeded-RNG
  permutations (deterministic seed recorded in the test). No FsCheck —
  a new dependency needs human approval.
- **D6 — Defensive guards.** Builder rejects null/empty input, malformed lane identity, duplicate effective event identity, invalid metrics, and non-finite/negative resolved heights with typed refusals and **positive tests**. A negative visible compatibility value is already rejected by R2.5 and never reaches layout; the geometry model separately rejects any negative effective index handed to it.

## Stop conditions (item-specific)

- The §9 formulas in the current entity guide differ from D1's quote →
  stop; the guide is authoritative.
- A consumer needs lanes compressed or events moved to avoid overlap →
  stop (§9 forbids it; ambiguity is warned, never resolved silently).
- Lane ordering other than D2 is requested → stop for the product
  decision recorded in D2/ADR-0012.
- Implementation reads `GanttEvent.StackIndex` for geometry → stop; ADR-0012
  makes the visible value compatibility-only.

## Risk and rollback

flagged as a stop-point; mitigated by making ordering a single small
type (`LaneOrdering`) that a later row could amend in one change.
Rollback: `git revert`; no consumers until R3.5+.
