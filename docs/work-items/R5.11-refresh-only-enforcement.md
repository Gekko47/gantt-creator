# Work item — R5.11: coalesced automatic refresh and delta reconciliation

> The legacy filename is retained for existing references; the Refresh-only
> contract in this guide is superseded by this revision.
>
> **Guide status**: Revised planning contract 2026-10-31; Tier A upgrade
> and implementation evidence remain due. Depends on R4.7/R4.8A/R4.9,
> R4.10 performance evidence, and the Phase-5 edit/settings commands.

## Outcome

Chart-affecting edits trigger a debounced, coalesced automatic refresh;
selection/navigation, cancelled commands, and refusals before mutation do
not. Every
refresh reads and validates the complete table/configuration and builds a
complete desired scene before mutation. Content-aware delta reconciliation
reduces Excel shape writes to changed entities and required create/delete/
z-order operations. Explicit Refresh remains a full validation and repair
pass. Blocking validation errors leave existing shapes untouched. Excel
shape writes are not transactional: a host failure after mutation begins is
reported as incomplete, invalidates the delta cache, and requires full
reconciliation to repair.

## Current-state review

- The current `docs/STATUS.md` records a debounced worksheet-change scheduler
  but only `Id` and `Type` trigger refresh; dates, descriptions, style fields,
  and broader command/settings changes remain to be wired.
- The current working-tree `GanttRefreshOrchestrator` changed-row path returns
  before complete scene construction/reconciliation and validates only the
  changed subset. It is unsafe for shipping partial refresh because it can
  miss duplicate IDs, hierarchy, and other cross-row findings.
- `ShapeReconciler` plans around stable IDs but does not compare canonical
  payloads to skip unchanged writes. Content-aware signatures remain needed.
- Verify `RefreshSheetCommand` dirty/cache reset behavior after both success
  and failure; preserve dirty state until a complete render succeeds.
- Engine metadata remains in the visible table. Moving activity/engine rows
  to `_GanttCreatorConfig` violates the product invariant.
- Replace the manual-only rendering statements in `AGENTS.md`, architecture,
  entity guide, and older work-item references. Historical Office evidence
  remains historical and is not rewritten as new behavior.

## Trigger and non-trigger matrix

| Change | Refresh behavior | Invalidation expectation |
| --- | --- | --- |
| Type, description/label text, dates, row visibility, per-row fill/line/label/date-label/style key | Schedule after commit; coalesce bursts | Changed entity plus label-collision neighbors; dates/visibility may affect range/layout |
| Insert/delete, delineator create/edit/delete, parent/child, promote/demote, move/reorder, expand/collapse | Schedule once after successful command transaction | Recompute hierarchy, lane order, geometry, and affected projections; structural/order changes may be full-scene |
| Plot range, scale/time scale, title, chart chrome, theme/style catalogue, metrics, chart labels | Schedule after successful settings commit | Recompute affected style resolution, frame, headers, labels, and/or all scene geometry |
| Selection, focus, navigation, Ribbon invalidation | Never render | Refresh capability state only |
| Dialog typing, cancel, validation refusal | Never render | Preserve chart/settings; update current validation/refusal state |
| Write fails before mutation | Never render | Preserve chart/settings; surface one concise failure |
| Write fails after mutation may have started | Do not treat as successful; mark dirty and schedule a full read/validation/reconcile from actual workbook state | Report incomplete write/refresh; do not claim rollback or success |
| Explicit Refresh | Always full read, validation, and scene build | Full reconciliation independent of cache |

Successful writes enqueue only after the table/config mutation completes. Do
not render inside worksheet callbacks or while a modal editor has an
uncommitted value. If an Excel event arrives during a refresh, mark dirty and
run one follow-up pass from the latest workbook state after the current pass
finishes; do not recurse or drop the change. A command write that fails after
mutation may have begun also leaves dirty state and requests one full
revalidation of actual workbook contents.

## Initialization and empty-state contract

After successful first-time Initialize, create one valid empty chart frame
and title once. Repeated Initialize neither duplicates the frame nor clears
schedule data or user content. When the table later has no renderable events,
reconcile to a valid empty state by removing stale owned event shapes while
retaining the frame/title. Initialization, workbook switch, cache miss, or
integrity repair forces a full reconcile.

## Delta-refresh design

1. Capture a bounded change batch and classify it by table column, command,
   or successful setting edit. Coalesce by workbook and managed sheet; do
   not retain an unbounded event history.
2. Read the complete current table/configuration. Normalize and validate all
   rows, stable IDs, hierarchy, style references, and cross-row constraints.
   Blocking findings must be known before shape mutation.
3. Build the complete desired scene using the Core scene/layout model. The
   first optimization is host reconciliation, not incremental Core building.
4. Compare stable scene IDs and deterministic canonical payload signatures
   (geometry, text, style, and z-order inputs) with the last successful
   in-memory snapshot. Create missing IDs, update changed payloads, delete
   removed owned IDs, and apply z-order only where the desired order differs.
   Never touch unowned shapes.
5. Commit cache state only after complete success. A failure after any host
   mutation invalidates the cache; preserve dirty state and repair with a
   full reconciliation. Never persist scene snapshots/fingerprints to the
   config sheet.
6. Preserve Excel application state and selection through tested adapter
   ownership boundaries. COM work stays on Excel's STA/main thread.

Incremental Core scene construction is a later optimization only if R4.10
proves scene building is material. It requires a tested dependency graph:
row-local labels can affect neighbor layout; style edits affect all rows
resolving that style; structural/order edits change hierarchy and lanes; and
theme, metrics, plot/date range, and time scale can affect the whole scene.
Row numbers are never persistent identity.

## Error prevention and feedback

- Disable commands/property controls when workbook, selection, capability,
  or mutation state proves the action unavailable. Recheck at execution
  because Ribbon state can become stale.
- Dropdown/data validation is preventive UX, not a correctness boundary;
  paste can bypass it. Full table validation remains authoritative.
- Blocking validation retains the last rendered chart and identifies the
  affected row/field through the validation/warnings surface. Ordinary edits
  must not produce repeated modal windows.
- A host write failure after mutation begins is visibly marked incomplete;
  retain dirty state, invalidate delta state, and repair on a later coalesced
  pass or explicit full Refresh. Do not claim rollback unless tested
  compensation restored the shapes.

## Scope and exclusions

- AddIn/Office: trigger classification, bounded coalescing, Excel-STA
  scheduling, cache lifecycle, and content-aware reconciliation.
- Core: expose deterministic payload equality inputs only if the existing
  immutable scene model does not already provide them.
- Tests: trigger/non-trigger matrix, coalescing, full-validation-before-write,
  payload delta correctness, no-op writes, structural invalidation, empty
  initialization, cache fallback, partial-write failure, idempotence, and
  unowned-content preservation.
- No incremental Core builder until profiling justifies it; no event log,
  scene cache, or activity data on `_GanttCreatorConfig`; no direct shape
  formatting from edits; no modal-per-edit workflow.

## Acceptance criteria

- Every chart-affecting source has an explicit tested trigger; selection,
  navigation, cancellation, and pre-mutation refusal have non-trigger tests.
- Every render validates the full current inputs and builds the complete
  desired scene before the first shape mutation.
- Delta output matches a full reconcile; unchanged payloads produce no shape
  writes; creates/deletes/changes/z-order are correctly planned. Failure
  invalidates cache and the next attempt performs a full repair.
- First Initialize creates the empty chart exactly once; later empty state
  removes stale owned event shapes while retaining the empty frame.
- Blocking invalid data preserves the last chart with actionable non-modal
  feedback. A host failure after mutation is marked incomplete and repaired
  by full reconciliation; tests do not claim rollback unless proven.
- Performance evidence records environment, duration, and operation counts;
  truncated inputs/artifacts do not count as a valid 1,000-event run.

## Stop conditions

- Complete validation/build-before-write cannot be preserved.
- A trigger needs an unapproved schema, dependency, Office-version, or
  security-model change.
- Delta reconciliation cannot prove equivalence with a full reconcile;
  fall back to full writes and use measured evidence before redesign.
- Empty-chart presentation conflicts with the entity guide; resolve before
  implementation.
