## Step 0 — verify prerequisites (Tier A, revised 2026-11-21)

- R7.1/R7.2 land first; R6.6's verified copy is the precondition — the measured drawing
  pair must be on the clipboard before paste (`StagedShapeCopier`).
- **The paste result is measured, not assumed (ADR-0066 D2/D3, R6.7):** on PowerPoint
  16.0.20527.20196 `PasteSpecial(ppPasteShape)` returned a range of **5 items = the
  group plus its 4 flattened children**, bounds 340 × 190 pt, and ungrouped to 4
  editable children. The validator must expect **the group plus its flattened
  children** — a single-item expectation is wrong.
- **Production scale is an owed measurement.** The landed composition stages ~80 shapes
  on the reference fixture (R6.8) and the copy benchmark records 340 primitives. Before
  fixing the expectation, repeat the `ppPasteShape` probe with the production-sized
  staged group and record the returned range structure. The expected production form is
  `1 + N` where `N` is the staged child count; a host that returns a different form at
  scale is a stop condition, not a reason to widen the validator to "any range".
- The typed PIA is used throughout: `Shapes.PasteSpecial(PpPasteDataType.ppPasteShape)`
  and a typed `ShapeRange`; no `dynamic`, no `Microsoft.CSharp`. The enum values are
  the measured `ppPasteShape` (11) and `msoGroup` (6) expressed through the PIA enums.
- `PasteSpecial` itself can raise: Microsoft Learn documents an error when the clipboard
  has no data and a failure when the source content is partially downloaded. Those are
  **stage failures** (D4), not paste-validation failures.

## Design decisions (behavioural)

- **D1 — Validate count, bounds, type and group identity.** The returned `ShapeRange`
  must be non-null, non-empty, with **exactly one** `msoGroup` shape, a count equal to
  `1 + expectedChildCount`, and finite, strictly positive bounds. Each violation is a
  distinct typed failure with a positive test. The group is located by `Shape.Type ==
  PpShapeType.msoGroup`, never assumed to be index 1.
- **D2 — Success is the validated result.** The stage's success output carries the
  validated facts (group reference, child count, bounds) forward; R7.4 positions the
  validated group; nothing downstream re-queries PowerPoint state it can avoid.
- **D3 — Non-throwing is not success.** A return without a valid `ShapeRange` is a
  failure even when no exception was thrown (the `AGENTS.md` rule, positively tested).
- **D4 — `PasteSpecial` errors are classified before validation.** A missing clipboard
  payload, a partial document and a host refusal are mapped to their own typed stage
  failures; the validator only sees a returned range.
- **D5 — Tolerance is the repository's, not a new one.** PowerPoint exposes
  `ShapeRange.Width`/`Height` as `Single`; compare bounds and aspect with
  `HostOwnedGeometry.GeometryMatchTolerancePt` (0.01 pt) and record the measured delta.

## Stop conditions (item-specific)

- The production-scale paste form differs from `1 + N` with one group → record evidence;
  the human decides whether the form is stable enough to support. Do not widen the
  validator to make a build pass.
- A supported build returns an unexpected-but-valid shape form → record evidence; widen
  only with the human's nod.
- `PasteSpecial` behaves differently from the typed signature → stop with the probe
  evidence; do not return to `dynamic`.

## Risk and rollback

Main risk: build-specific paste quirks and a scale-dependent range form — the
production-scale live gate exists for this. Rollback: `git revert`.
