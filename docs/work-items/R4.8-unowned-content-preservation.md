## Step 0 — verify prerequisites (re-verified 2026-09-26 against landed code)

- R4.1–R4.7 landed. The ownership filter is the `GanttCreator.` tag
  written by R4.1 D2 and it is the **only** mutation key (R4.3 D2 /
  R4.7 D1). The scene-side inputs are `OwnerId` (kinds `Row`, `Chart`,
  and the shared `Rows` set — ADR-0017) and the role-derived
  `PrimitiveId`; neither is the tag itself, so this row's preservation
  proof must exercise the *tag filter*, not the scene fields (R3.14
  decision, 2026-09-26).
- **The cell-comparison machinery already exists and must be reused:**
  `src/GanttCreator.Office/ExcelValue2Matrix.cs` is the R2.6/R2.4
  bulk-`Value2` reader, and the contract tests already assert
  no-mutation on read paths with it
  (`tests/GanttCreator.Office.ContractTests/GanttTableReaderTests.cs`,
  `ValidationReporterTests.cs`). D1's "byte-compare `Value2` matrices"
  discipline is a landed pattern, not a new invention.
- The sheet-count rule has a landed precedent to mirror:
  `IWorkbookInitialiser`/`ExcelWorkbookInitialiser` (R2.2) already
  refuses a workbook that is not the expected structure, and the
  `xlSheetVeryHidden` config-sheet discipline is pinned by the R2.7/R2.9
  tests. "No extra worksheets, ever" must hold on every refresh path.
- R4.7's membership-sensitive shared owner (ADR-0017) means a
  same-date deduplicated delineator's id changes when its row set
  changes: that is an owned removal plus an owned creation, never an
  unowned mutation.

## Design decisions (behavioural)

- **D1 — Sentinels, not assumptions.** The contract fixtures plant
  unowned shapes (with and without user names), user cells (values +
  formats), and a non-active sheet; refresh runs; every sentinel's
  `Value2`, formula, format, name, position, and the active-sheet
  identity are asserted unchanged. Deletion candidates that match by
  *geometry overlap* but lack the ownership tag are never touched
  (**positive test**).
- **D2 — No extra worksheets, ever.** Every refresh path asserts the
  sheet count and identities are unchanged (test-strategy rule).
- **D3 — Active worksheet is never switched.** The refresh path never
  activates another sheet; a contract test asserts zero
  activate-operations (**positive test**).
- **D4 — Failure paths preserve too.** Each injected failure point
  (checklist K) leaves sentinels unchanged and state restored.

## Acceptance tests

## Stop conditions (item-specific)

- Any refresh path must touch an unowned object to succeed → stop;
  the design is wrong, not the test.
- A host behaviour reformats cells as a side effect of shape
  operations (e.g. table auto-format) → stop with evidence; scope-
  change path.

## Risk and rollback

Main risk: indirect mutations (selection side effects, table
  auto-expansion) — the sentinel matrix exists to catch exactly
  these. Rollback: `git revert`.
