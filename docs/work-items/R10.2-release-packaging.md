## Outcome

Release packaging is deterministic: two clean Release builds produce
identical artifacts (or every binary variance is explained and
recorded), checksums are published, and the packaged XLL — not a
developer output — loads in Excel.

## Exclusions

## Design decisions (behavioural)

- **D1 — Two-build comparison is the gate.** Clean tree → build →
  hash → clean → build → hash → compare; every difference is either
  eliminated or explained in the committed variance list (with the
  mechanism, e.g. PE timestamp).
- **D2 — The packaged XLL is the tested artifact.** The R10.5/R10.6
  gates and the R10.4 rehearsal load the packaged output — a
  developer `bin/` XLL never counts as the release artifact.
- **D3 — Checksums are produced, not computed by hand.** The
  pipeline emits the manifest; R10.8 verifies against it.

## Acceptance tests

- **Automated**: the comparison harness green (two builds equal or

  produced; the locked-restore test extended if the inventory
  changed.
- **Office host (Required)** — load the packaged XLL (not a developer
  output) on the reference machine; confirm the add-in runs; record
  host builds.

## Stop conditions (item-specific)

- A binary variance cannot be explained → stop; an unexplained
  variance is a supply-chain risk (record and investigate, never
  waive).
- Determinism requires pinning a tool the pipeline does not control →
  stop; that is a tooling decision.

## Risk and rollback

Main risk: determinism chasing (a rabbit hole) — bounded by D1's
explain-every-variance rule. Rollback: `git revert`.
