## Design decisions

- **D1 — Beside `PointD`, root namespace.** All four types live in
  `namespace GanttCreator.Core` as single-file immutable types, matching
  the landed `PointD` layout (the Phase 3 note's "beside it").
- **D2 — Exact equality; tolerance only in predicates.** Value-object
  equality is exact (record equality on doubles), mirroring `PointD`.
  Geometric *predicates* (`Contains`, `IntersectsWith`) compare with
  `GeometryMath.Epsilon` — the documented tolerance for Excel `Single`
  geometry. Two policies, two homes, never mixed.
- **D3 — One snap boundary.** `GeometryMath.SnapToDisplayPrecision(
  double)` → `float` is the **only** point→display translation in the
  solution; layout never rounds. Raster pixel mapping stays in
  `GanttCreator.Raster` (architecture formula; R8.1 residual). Nothing
  else may call `Math.Round` on geometry.
- **D4 — `ColourHex`.** Parses exactly `#RRGGBB` (implicit alpha `FF`)
  and `#RRGGBBAA`; `ToString` round-trips the parsed form; anything
  else rejects with `FormatException` (never throws on `null` input —
  `TryParse` mirrors `GanttRowId`'s Ordinal/trim/never-throw contract).
  This is the domain value object; R2.5's cell-text validation code is
  unchanged and separately owned.
- **D5 — Extent guards.** `SizeD`/`RectD` reject negative width/height
  and non-finite values (`NaN`, `±Infinity`) with documented
  `ArgumentException`/`ArgumentOutOfRangeException`; zero extents are
  legal (empty lanes, suppressed bands).

## Implementation steps (in order)

1. `GeometryMath`: `Epsilon` (documented value, e.g. `1e-6`),
   `ApproximatelyEqual(double, double)`, `SnapToDisplayPrecision(double)`
   → `float`; XML docs stating the single-boundary rule.
2. `SizeD`, `RectD` (members `X/Y/Width/Height` plus `Left/Right/Top/
   Bottom` derived; `Contains(PointD)` and `IntersectsWith(RectD)` use
   `Epsilon`); guards per D5.
3. `ColourHex` per D4 (`Parse`/`TryParse`/`ARGB`/`ToString`).
4. Tests in the four new files: equality pins mirroring `PointDTests`;
   boundary cases (zero legal, negative rejected); conversion
   round-trips (`#0F0F0F` ↔ values; alpha default and explicit);
   invalid-number matrix (`NaN`, `±Infinity`, `1e999` string for
   `ColourHex`); **a positive test for every guard**; one culture test
   (`tr-TR` / `de-DE`) proving no culture-dependent formatting anywhere.
5. Docs: REPO-MAP (Core row gains the value objects), STATUS, status
   line. One commit: `feat: R3.1 …` — Checklist: A, B, G, I.
