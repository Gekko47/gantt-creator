# Work item — R5.12

> **Guide status**: Authored (Tier B — binding contract) 2026-10-09 ·
> Depends on: R3.5 (frame/band primitives), ADR-0035 (label width is
> bounded by available space), ADR-0040 (the explicit-format ruling).

## Outcome

On the Month scale, the user chooses the period-label format — `MM` (`01`)
or `MMM` (`Jan`) — as two `Month` rows of the Plot Time Scale dropdown itself,
group. The chosen format is emitted verbatim by every visible interval, so
the band is uniform, and it is stored and recalled by Refresh. No automatic
step-down exists: the selected form is used as-is. A period label is shown
only when its interval is at least as wide as the label **measures** at the
shared text seam, so the shorter `MM` survives on narrower intervals than
`MMM` (revision 12, ADR-0041); the **year** band keeps the fixed
`MinimumHeaderLabelWidthPt` floor, and a period whose measurement is
unavailable falls back to it.

## Context and owed deferrals

This row was first authored as the automatic MMM→MM fit ladder (ADR-0039):
when the Month scale selected `MMM`, a period label measuring wider than its
interval stepped down to `MM`. The owner rejected that on review — a
per-interval ladder makes the band non-uniform (some months at `MMM`, some at
`MM`) and is not reliably observable in live use. A three-character month at
the 8pt measuring seam measures narrower than the 18pt
`MinimumHeaderLabelWidthPt` suppression floor, so the step-down window is
effectively empty: any interval wide enough to escape suppression already
fits `MMM`, and anything narrower is suppressed before the ladder runs. The
ladder code and tests were reverted; ADR-0039 is superseded by ADR-0040.

`PeriodLabelFormat` is already a stored, culture-independent setting with a
closed-set parser and an exact compatibility matrix (`Month` permits
`MM`/`MMM`); the config reader/writer already round-trip it. The row only
adds the user surface and removes the one behaviour that fights it — the
persist path currently re-derives the format from the scale and would clobber
a user-chosen `MM`.

## Explicit exclusions

- No catalogue token, schema version, or format-enum change — so no migration
  and no `Initialise` remedy. (ADR-0041's measured-fit gate is a `BandSequence`
  behaviour change with no new setting, token, or scene member.)
- The reverted `FrameBandsBuilder` **ladder** is not reintroduced: measured-fit
  changes only the show/hide decision, never substitutes one form for another.
- No Quarter/Week abbreviation forms and no year-band change; each would need
  its own owner ruling. (Measured-fit applies to all scales uniformly, but
  introduces no new forms and the year band keeps the fixed floor.)
- No period-header-sized (9pt) measurer and no font-family pin: the shared 8pt
  seam is reused, matching the title's existing treatment; the residual is
  recorded, not closed, in this row.
- No per-scale format memory: one stored setting, normalised on a scale switch.
