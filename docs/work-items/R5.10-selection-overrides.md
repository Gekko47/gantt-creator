## Outcome

per-entity property controls; fill/line (and label-position, per
R5.5) edits write the row's `FillColour`/`StrokeColour`/
`LabelPosition` cells — never the generated shapes — with capability

proven by selection-context, capability, colour, label-position,
inheritance, and persistence tests.

## Design decisions (behavioural)

- **D1 — Exactly one expanded visible entity row enables controls.**
  Selection facts: zero rows → disabled; multiple rows → disabled;
  header row → disabled; collapsed roll-up → disabled; one expanded
  entity → enabled per capability. The truth table is pinned.
- **D2 — Capability gating per Type.** Fill requires the type's fill
  capability; stroke requires stroke; `Critical Interval` offers
  neither fill nor label override; `Custom Activity` gates come from
  its style (R2.9 registry). Unsupported writes refuse with the
  actionable message (**positive tests**).
- **D3 — Table write only; blanks inherit.** Edits write exactly the
  target cell; clearing writes blank (inherit the style default);
  `#RRGGBB` validated before write (**positive test** for bad
  format).
- **D4 — Persistence through Refresh.** The live gate edits a
  rectangle fill and a diamond label position, Refreshes once, and
  confirms the shapes reflect the overrides — the Phase-5 exit
  demonstration's core path.

## Stop conditions (item-specific)

- A control would touch a generated shape → stop (the row-cell write
  is the only path).

  the narrow port with the human.

## Risk and rollback

Main risk: selection races (selection changes mid-command) —
commands re-read selection facts at execution and refuse on change
(pinned). Rollback: `git revert`.
