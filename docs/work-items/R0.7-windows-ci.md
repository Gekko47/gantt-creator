# R0.7 — Windows CI for restore, format, build, unit tests, and artifacts

> Block 0, R0.7 from `docs/03-ROADMAP.md`. Builds on R0.6 (verify
> scripts and coverage settings).

## Outcome

A GitHub Actions workflow at `.github/workflows/ci.yml` runs the
non-Office quality gate on `windows-latest` for every push and pull
request. The workflow performs, in order: locked restore, format
check, Release build with warnings-as-errors, AddIn publish (packed
XLL artifact), and the non-Office unit-test suite. The packed XLL is
uploaded as a build artifact. A deliberate-failure switch on
`workflow_dispatch` proves the annotation gate on demand.

Office-integration tests are excluded from CI by policy:
`[Trait("Category","OfficeIntegration")]` is filtered out, per
`docs/adr/0001-self-hosted-office-runner.md`.

## Scope

- `.github/workflows/ci.yml` with steps mirroring
  `scripts/verify-quick.ps1` (same commands, one step per gate so a
  failure annotates the exact gate):
  1. checkout, setup .NET 10 SDK, cache NuGet keyed on
     `**/packages.lock.json` (per docs/05-GIT-QUALITY.md: cache only
     packages, keyed by lock files);
  2. `dotnet restore --locked-mode`;
  3. `dotnet format GanttCreator.slnx --verify-no-changes --exclude tests`
     — tests/ is excluded to match the documented policy that
     `tests/Directory.Build.props` sets `EnforceCodeStyleInBuild=false`
     for xUnit conventions (CA1707 snake_case, IDE0011 braceless if);
  4. `dotnet build GanttCreator.slnx -c Release --no-restore -warnaserror`;
  5. `dotnet publish src/GanttCreator.AddIn/GanttCreator.AddIn.csproj
     -c Release --no-build` (artifact producer for
     `AddInAssemblyTests`, traceable per docs/08-TEST-CHECKLIST.md
     section G);
  6. `dotnet test GanttCreator.slnx -c Release --no-build --filter
     'Category!=OfficeIntegration'`;
  7. upload `publish/` output as artifact with `if-no-files-found: error`;
  8. `workflow_dispatch` input `deliberate_failure` runs a step that
     emits `::error::` and exits 1, proving the annotation gate.
- Concurrency group cancels superseded runs on the same ref.
- `timeout-minutes`, minimal `permissions: contents: read`.

## Exclusions

- No Office integration in CI (self-hosted runner policy, ADR-0001).
- No golden-image comparison (R8.x).
- No per-project coverage-threshold enforcement (deferred to R3.x per
  docs/04-TEST-STRATEGY.md; verify.ps1 records the thresholds).
- No package-vulnerability or SBOM jobs (R10.x).
- No repository-hygiene/secret-scan job (R0.7 scope is restore,
  format, build, tests, artifacts; hygiene lands with a later
  hardening item).
- No dependency changes.

## Acceptance tests

- **Automated (local, run before push):**
  - `pwsh ./scripts/verify-quick.ps1` → PASS.
  - `dotnet format GanttCreator.slnx --verify-no-changes --exclude
    tests` → exit 0.
  - YAML is well-formed and every `run:` step's command was executed
    verbatim at least once locally in this work item.
- **CI gate (requires push to GitHub; run by the human or a
  self-hosted runner):**
  - The workflow passes on a push to `stage-inspect`.
  - Dispatching with `deliberate_failure: true` fails the workflow and
    the failed job shows the `R0.7 annotation test` error annotation.

## Risk and rollback

Risk: CI-only environment differences (SDK patch band, runner cache)
make a step fail locally-green code. Mitigation: setup-dotnet pins
`10.0.x` and `global.json` uses `rollForward: latestFeature`; every
command is verbatim from verify-quick.ps1 which passes locally.
Rollback: `git revert <commit>` removes the workflow file; no product
code is touched.
