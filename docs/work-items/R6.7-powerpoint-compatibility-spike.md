## Design decisions (spike protocol)

- **D1 — Measure, then propose.** Per Office build, record: the exact
  clipboard format set present after copy; whether each format
  survives staging deletion (immediately and after a bounded delay);
  whether Excel/PowerPoint paste still materialises the group with
  expected count/bounds; whether ungroup/edit works. The ADR proposes
  the simple delete path (architecture step 7) or the
  staging-workbook fallback **from this evidence only**.
- **D2 — Deterministic assertions, not vibes.** Every claim is a
  recorded assertion (format values, shape counts, bounds within the
  documented tolerance) — reproducible per build.
- **D3 — Human approval gate.** The ADR outcome is approved before
  R6.5 (staging lifecycle) and R6.6 (clipboard) are implemented —
  their designs depend on it.
- **D4 — No orphan Office processes** (the `verify-office.ps1`
  ownership-sweep discipline; the spike runs under the same harness).
- **D5 — PowerPoint paste-target automation route (open decision,
  named 2026-11-18).** The spike's PowerPoint paste assertions need
  PowerPoint automation in the harness. The default route is
  **late-bound COM** (`Type.GetTypeFromProgID("PowerPoint.Application")`
  + `Activator.CreateInstance`), which adds no package; the
  alternative is a `Microsoft.Office.Interop.PowerPoint` test-only
  package, which is a new dependency and needs owner approval under
  the dependency policy before it is taken. The ADR records which
  route was used. No PowerPoint adapter is created in `src/` — that
  is R7.1's.

## Notes — measured evidence (2026-11-18)

**Run.** Three `OfficeIntegration` bodies, all green in 1 m 15 s on the reference
host: `Delete_after_copy_keeps_the_clipboard_materialisable_for_an_excel_paste`
(3 cycles), `Copy_without_delete_is_the_control_arm_and_materialises_an_excel_paste`
(1 control cycle), and `Delete_after_copy_keeps_the_clipboard_materialisable_for_a_powerpoint_paste`
(3 cycles). Raw JSON-lines evidence: `scripts/_artifacts/office-evidence/r6.7-evidence.jsonl`
(git-ignored); the table below is the committed summary.

**Hosts.** Excel 16.0 build 20527 · PowerPoint 16.0.20527.20196 (x64,
O365HomePremRetail). Single-build basis; R10.1/R10.5 re-run on every supported build.

**Format set after copy** — identical immediately, after 2 s and after 10 s, in every
cycle and arm:

```text
DataObject, Preferred DropEffect, InShellDragLoop, Excel 2007 Internal Shape,
Art::GVML ClipFormat, image/svg+xml, PNG, JFIF, GIF, CF_BITMAP, CF_ENHMETAFILE,
CF_METAFILEPICT, Ole Private Data, CF_DIB, CF_DIBV5
```

`GetClipboardSequenceNumber` was unchanged across the windows in every cycle, so the
deletion neither replaced nor withdrew the clipboard content. The expected candidate
"Office Drawing Shape Format" was **not** present; the measured drawing format is
`Excel 2007 Internal Shape` (with `Art::GVML ClipFormat`).
