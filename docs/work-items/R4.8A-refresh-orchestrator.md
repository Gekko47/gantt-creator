## Outcome

workbook state, a testable `ISceneBuildRequestFactory` owns the translation of
that state into scene inputs, every validation and layout step succeeds **before**
any shape mutation, and `RefreshSheetCommand` stays thin.

## Design decisions

- **D1 — The orchestrator is a service, not a command.** `RefreshSheetCommand`
  checks availability, invokes the orchestrator, and presents the outcome. Command
  logic does not live in the callback (AGENTS.md, `02-ARCHITECTURE.md`).
- **D2 — The pipeline order is fixed** and each step has a named owner:
  resolve workbook/sheet/table → validate the mutation boundary → enforce
  hidden/locked column state → read user data and engine metadata → process blank
  and new entities and IDs → validate hierarchy and order → maintain outline
  groups → calculate and write `Duration` → normalise row heights → resolve
  source/render visibility → resolve projection and lane ownership → build the
  style registry → resolve the size preset → resolve plot date range and scale →
  measure text panel and visible row geometry → build the `SceneBuildRequest` →
  build the LiveExcel scene → translate → ownership preflight → reconcile →
  return the outcome.
- **D3 — All validation, layout and scene construction completes before any shape
  mutation.** A failure in any of them leaves the last valid chart untouched. This
  is the architecture's existing refresh contract, now enforced at one seam.
- **D4 — `LiveExcel` is an explicit composition profile that supplies no data
  panel.** The live sheet's real cells *are* the panel, so a duplicate panel would
  cover the user's data. `EditableExport`, `PowerPoint` and `Raster` are separate
  profiles. The profile is chosen in code, not by a caller remembering to pass the
  right theme.
- **D5 — The factory is separately testable.** It owns visible-row geometry,
  projections, plot bounds, preset, date range, scale, styles, metrics and the
  composition profile, and **none of that logic is scattered through Ribbon
  commands or renderer classes**.
- **D6 — The mutation-ownership boundary is enforced preflight.** If Refresh
  cannot complete without changing unowned content — an unrelated sheet, shape,
  name, cell, or outline group — it refuses and reports the conflict rather than
  proceeding.
- **D7 — Bulk reads and writes where practical**, per REV5 §22 instruction 12.
- **D8 — Application state and selection are restored** on every path, success or
  failure, by the existing five-setting `ExcelApplicationStateScope` (ADR-0020).

## Acceptance tests

- **Automated**:
  - orchestrator tests run **without Excel**, asserting step order and that a
    failure at each injected step produces zero shape mutations
  - the factory produces the exact `SceneBuildRequest` for a given workbook and
    configuration state
  - the `LiveExcel` profile emits **no** data-panel primitives
  - a mutation-boundary conflict refuses with a typed, actionable refusal
  - `RefreshSheetCommandTests`: the command performs no orchestration, invokes the
    orchestrator exactly once, and presents the outcome
  - application state is restored on success and on every injected failure
- **Office host (Required)**: a full Refresh on a representative
  construction-delay workbook — parents, children, critical intervals, milestones,
  delineators, collapsed and expanded — with the host build recorded.

## Step 0 — verify prerequisites

- **All seven R4.7 rows must have landed.** This row composes their contracts; if
  it needs one that does not exist, that is a stop condition, not something to
  invent here.
- R4.9's guide names the exact files for the command; the orchestrator is new and
  its seams must not duplicate `IGanttTableReader`, `IShapeWritePort`,
  `IPanelGridMeasurementPort` or the config ports.
- ADR-0020's five-setting state scope and ADR-0019's ownership carrier are landed
  and are reused, not reimplemented.

## Stop conditions

- **A needed contract does not exist → stop.** This is the row where
  "integration, not architecture invention" is tested; inventing a contract here
  defeats the entire pre-R4.9 sequence.
- Any validation that must run *after* shape mutation → stop; D3 is the
  architecture's existing rule.
- A COM failure mid-reconciliation → return an explicit partial-refresh outcome.
  Do not re-open transactional Refresh here; REV5 §16 defers that until R4.10
  evidence exists.

## Risk and rollback

Main risk: the orchestrator absorbing logic that belongs to a builder, producing a
second authority. Mitigated by D5 and by an architecture test. Rollback:
`git revert`.
