# R5.6e — The chart's border encloses the title and the visible table

**Status:** delivered (owner ruling 2026-10-21; owner visual sign-off 2026-10-21) —
commit `c10c220`, ADR-0048.
**Parent:** `R5.6-style-theme-settings.md`. **Siblings:** `R5.6a-named-style-presets.md`,
`R5.6b-chart-title-settings.md`, `R5.6c-theme-dialog-modernisation.md`,
`R5.6d-theme-dialog-and-chrome-fixes.md`.
**Governing:** `docs/07-GANTT-ENTITY-GUIDE.md` §§1, 10; ADR-0030, ADR-0043, ADR-0046,
ADR-0047, **ADR-0048**; `docs/00-PONYTAIL.md`.

## 1. Outcome

The live chart's **outer border** encloses the **chart title** and the **visible data
table** as well as the plot, as **one rectangle**:

- the top and bottom rules run from the table's first column to the plot's last;
- a **vertical rule** closes the rectangle at the start of the visible table.

The frame's top and bottom are **unchanged** — the chart's own margins, two cells below
the Gantt (ADR-0047 D2) — and the table's own cells are **not** painted over.

## 2. Root cause

The live title is an owned textbox placed in the **table's own columns** (ADR-0043), so
the title and the table sit to the **left** of the plot. The frame was drawn on the
chart's own content rectangle, and for a live chart that rectangle is the **plot**:
`SceneBuilder` unions a panel's bounds only when a panel was drawn, and a live request
supplies none — the worksheet's own cells *are* the panel (R4.8A D4) — so the frame
fell back to `plotBounds` alone.

The border therefore enclosed neither the title nor the table, and the two read as
unrelated objects.

## 3. Owner decisions (2026-10-21)

| # | Decision | Answer | Consequence |
|---|----------|--------|-------------|
| D1 | The frame's **bottom** edge: extend straight to the table's start, or stop at the table's last row and step up to the chart's bottom at the plot? | **Both straight to the start.** | The frame is **one rectangle**, not a step: the chart's own top and bottom, the plot's right, the table's first column on the left. |
| D2 | The table's own visuals (Excel's table style)? | **The frame is drawn like the right-hand rule; the table's own visuals are removed later.** | This change draws the rule and leaves the table's own borders alone. The overlap is deliberate and temporary; removing the table's visuals is a **separate, later** step, because the add-in rewriting a user's table style on every Refresh is a decision of its own. |
| D3 | The top rule crossing the columns between the table and the plot? | **Yes — it has to, accepted.** | The rule is drawn at the chart's top margin row, above the title, from the table's first column to the plot's last. |

## 4. What was implemented

1. **Core — `FrameBandsRequest.DataPanelBounds`** (`ChartFrameGeometry.cs`): an optional
   rectangle, "the visible data table's rectangle, when the chart's outer border must
   enclose it as well as the plot". Null leaves the border on the chart's own rectangle,
   which is what the **export** compositions do.
2. **Core — `FrameBandsBuilder.AddOuterFrame`**: the four `chart:frame:*` rules are drawn
   on `Union(chartBounds, dataPanelBounds)`. **Only the border** uses the union — the
   background, the bands, the grid lines and the closing line keep the plot's rectangle,
   because a background over the table would paint the user's own cells.
3. **Core — `SceneBuilder.LiveDataPanelBounds`**: for the `LiveExcel` profile the
   rectangle is built from the **measured** `PanelCellGrid` — the left edge is the panel's
   origin (the same number the live title textbox is placed at), the right is the origin
   plus the measured column widths, the top is the header row's top and the bottom is the
   last body row's bottom. The export profiles pass null.
4. **Docs**: ADR-0048; entity guide §1 (the frame's geometry) and the §10 equivalence
   row; `docs/DECISIONS.md`.

### A deviation from the plan, and why

The plan proposed a **refusal** when the table's first column did not match a code
constant. That was **dropped**: the measured origin is the truth of where the table is,
so a constant would be a **second** authority for the same fact, and a check would fail
the whole refresh for a table that is legitimately placed. The frame following the
measurement is the stronger guarantee. ADR-0048 records the rejection.

## 6. Owner sign-off

The owner confirmed on 2026-10-21, against a live workbook, that the border now reads
as one rectangle around the title, the table and the plot. That is the visual evidence
the automated gates cannot supply.

## 7. Exclusions

- No change to the background, the bands, the grid, the closing line, the plot geometry,
  the lane anchoring, the title's text/placement/size, the visible table's cells, the
  table's own Excel style, or the export compositions.
- No workbook schema, catalogue, token or dependency change.
- **The table's own borders are still drawn.** Removing them is a later, separate work
  item (D2), and it is a new host mutation — the add-in writing cell borders over a
  user's table on every Refresh.
