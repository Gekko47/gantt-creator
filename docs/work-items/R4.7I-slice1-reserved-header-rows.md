# Work plan — R4.7I slice 1: the reserved rows and the header row

> **Parent row:** [R4.7I](R4.7I-live-chart-vertical-anchoring.md).
> **Decision:** [ADR-0030](../adr/0030-live-chart-vertical-anchoring.md) D4/D5/D6.
> **Checklist:** B, L, N, I. **Status: not started.**
>
> **This is slice 1 of R4.7I and it is deliberately ordered first.** It changes the
> workbook's *layout*, so every later slice measures against it. Doing the measured
> origin (D3) before the rows exist would mean measuring a layout that is about to
> move.

## Outcome

Initialise writes a reserved row above `tblGanttData` carrying the table title and
the year band, and normalises the table's header row to `PeriodBandHeightPt` so the
period band's bottom is the header's bottom — which is the first body row's top.
After this slice the sheet has the vertical structure ADR-0030 specifies, and the
plot-anchoring slices have something stable to measure.

## Why this slice is not just "insert a row"

A reserved row moves the table down by one, and **the codebase hardcodes the header
row at worksheet row 1 in three independent places.** Each was found by reading
source, not by running it:

| Site | Current code | Consequence of a reserved row |
| --- | --- | --- |
| `ExcelWorkbookInitialiser.GetHeaderRange` (`:1007`) | `target.Cells[1, 1].Resize[1, columnCount]` | Header must be written at the reserved row + 1 |
| `ExcelWorkbookInitialiser.BuildAnchorRefersTo` (`:933`) | `$"='{escaped}'!${col}$1"` | Anchor must point at the **header** row, now row 2 |
| `ExcelConfigIntegrityChecker.BuildPlotAnchorRefersTo` (`:168`) | same `$1` literal | Must agree with the initialiser or Repair reports a false `PlotAnchorDisagreement` |
| `ExcelPlotAnchorRepairer.BuildRefersTo` (`:106`) | same `$1` literal | Third copy; must agree too |

**The anchor is the trap.** It is defined as *"the cell one column right of the
table's last column, on the header row"* (`02-ARCHITECTURE.md:90`). If the initialiser
writes `$O$2` and the checker still expects `$O$1`, Repair reports a disagreement on
every healthy workbook — a **false** integrity finding created by the fix. All three
copies must move together, which means the row number cannot stay a literal in any of
them.

**There are already three copies of `ToA1Column`** (initialiser, checker, repairer).
This slice collapses them to one Core helper rather than editing three literals in
step, because a fourth copy is what caused the divergence to be possible.

## Scope

- New `src/GanttCreator.Core/GanttSheetLayout.cs` — the **single authority** for the
  live sheet's vertical layout: the reserved-row count, the header row index, and the
  anchor's A1 address. Pure, Office-free, deterministic.
- `ExcelWorkbookInitialiser` — write the reserved row and the table title; build the
  header at `layout.HeaderRowIndex`; build the anchor through the Core helper
- `ExcelConfigIntegrityChecker`, `ExcelPlotAnchorRepairer` — use the same Core helper
- `ExcelRowHeightNormaliser` — normalise the header row to `PeriodBandHeightPt`
  (D5) and the reserved row to `YearBandHeightPt` (D4), both skipping rows already at
  the token, exactly as the body rows already do
- Tests, plus the rollback paths below

## Design decisions

- **D1 — One Core layout authority, no row literals.** `GanttSheetLayout` exposes
  `ReservedRowCount = 1`, `HeaderRowIndex`, and the anchor address. Three literals
  edited in step is exactly the arrangement that produced the false-finding risk; one
  helper is what makes them incapable of disagreeing. `PlotGeometryAuthorityTests`
  has a precedent for this shape and a new architecture test should pin it: no
  production file outside the helper may contain the `$1` anchor literal.
- **D2 — The reserved row is written before the header, and rolled back with it.**
  `Initialise` currently has a four-flag rollback ladder (`wroteHeader`,
  `createdTable`, `createdConfigSheet`, `wrotePlotAnchor`) that restores the sheet to
  its pre-command state. A fifth flag — or folding the reserved row into the header
  step — must delete the inserted row on **every** rollback path, or a refused
  Initialise leaves a stray row and a shifted table, breaking the zero-mutation
  guarantee the refusals promise. Inserting the row *last* is rejected: the table's
  own range then depends on it, and a later failure would have to un-insert.
- **D3 — The title is a cell value, not a shape.** It goes in the reserved row
  across the panel columns. ADR-0030 D6 means `SceneBuilder` emits no title primitive
  under `LiveExcel`; the export profile still emits one, and a test must assert both
  so a future "never draw a title" rewrite cannot pass the first test alone.
- **D4 — The normaliser gains the header and reserved rows as targets, not as
  special cases.** `RowHeightNormaliser.Plan` already returns a write set excluding
  rows already at the token. The two new rows join that plan rather than being written
  by a second code path, so "already correct ⇒ no write" holds for them too and a
  normalised sheet stays clean across Refreshes.
- **D5 — An existing workbook without the reserved row is a schema mismatch, not a
  silent repair.** ADR-0029 D6: report, never coerce. The schema version bumps in this
  slice, and the approved repair path (R2.10) restores the layout. The alternative —
  having Refresh insert the row — would make Refresh mutate structure, which the
  orchestrator's D3 validate-before-mutate contract forbids.

## Acceptance tests

- **Core — `GanttSheetLayout`**:
  - the header row index is the reserved-row count + 1, stated as an invariant rather
    than a literal
  - the anchor address names the header row and the column past the last schema
    column, for a sheet name containing an apostrophe (**positive test**)
  - a column index past `Z` produces `AA`, not a broken letter (**positive test**)
- **Core — normalisation**:
  - the header row's target height is `PeriodBandHeightPt` and the reserved row's is
    `YearBandHeightPt`, both read from `GanttCatalogues` and **not** as literals
  - a row already at its token is excluded from the plan (**positive test**)
- **Office contract — initialiser**:
  - the header is written at the reserved row + 1, and the anchor is the **header**
    row — asserted through the Core helper, not a hardcoded `$O$2`
  - **rollback**: forcing a refusal after the reserved row is written leaves the sheet
    with **no** extra row and the table back at its original position
    (**positive test**, same commit)
  - the initialiser's anchor and the integrity checker's expected anchor are
    **equal** — the single assertion that would have caught the false
    `PlotAnchorDisagreement`, and the reason D1 exists
- **Office contract — normaliser**: a header row already at `PeriodBandHeightPt`
  produces no write
- **Architecture**: no `$1` anchor literal outside `GanttSheetLayout`
- **Office host (Required)**: Initialise a real workbook; confirm the reserved row,
  the title cell, the header height, the anchor on the header row, and that Repair
  reports **no** `PlotAnchorDisagreement` on the fresh sheet. Record the host build.

## Step 0 — verify prerequisites

- Re-read ADR-0030 D4/D5 and entity guide §4 together. **If two physically inserted
  rows were intended rather than one, stop** — D5 is the decision to revisit, and the
  guide must be amended in the same change.
- Confirm the table still starts at column A. A reserved row changes only the row
  axis; if any code assumes the table's *left* edge is at `Cells[1,1]`, it is in
  scope for this slice rather than deferred.
- Probe `ListObject.HeaderRowRange.Row` on the live host before trusting it as the
  header's worksheet row. Prefer it over `table.Range.Row`; guessing between the two
  reproduces the class of defect ADR-0019 was raised for. Record the evidence.

## Stop conditions

- **The reserved row cannot be rolled back on every refusal path → stop.** A refused
  Initialise that leaves the sheet altered is worse than the misalignment being fixed.
- A **second** layout authority appears (another row literal, another `ToA1Column`)
  → stop; that is what D1 exists to prevent.
- Anchor disagreement cannot be made structurally impossible between the initialiser
  and the integrity checker → stop and report, rather than shipping a Repair command
  that flags healthy workbooks.
- The header row's height cannot be written without unprotecting the sheet → stop;
  ADR-0008's policy is to refuse a protected target, not to unprotect one.

## Risk and rollback

Main risk: the **false integrity finding** described above — a fix that makes Repair
report every healthy workbook as broken. It is mitigated structurally by D1 and
pinned by the "initialiser anchor == checker anchor" test. Second risk: the rollback
ladder missing a path, leaving a stray row; mitigated by D2 and the rollback positive
test. Rollback: `git revert`.

## Definition of done

From `AGENTS.md` + `08-TEST-CHECKLIST.md` **B, L, N, I**: reserved row and header
height written and measured; one layout authority with an architecture guard; every
validator shipped with a positive test in the same commit; rollback restores the sheet
on every refusal path; no false `PlotAnchorDisagreement`; schema bumped with the
repair path; Release 0 warnings; REPO-MAP, ROADMAP and STATUS current; live gate
recorded with the host build.
