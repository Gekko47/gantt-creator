# Work item — R5.20: the automatic-refresh switch

> **Status**: Implemented 2026-11-16 (code, tests, docs); the Office host gate is owed.
> **Depends on**: R5.11 (coalesced auto-refresh), ADR-0050, ADR-0029 D6, R5.18h (the
> `HiddenColumns` persistence precedent).

## Outcome

The owner can switch the coalesced automatic refresh off from the ribbon, work with only the
explicit **Refresh chart** command rebuilding the chart, and switch it back on. The choice is
written to the workbook's own `tblGanttSettings` row (`AutoRefreshEnabled`) and re-read when a
workbook is opened or switched, so it survives reopening the file. The switch never weakens a
pass that does run: an explicit Refresh is still a full validation and repair pass, and an
enabled automatic pass still reads and validates the complete table before any shape mutation.

## Surface

The Refresh control is now a splitButton (`spbRefresh`): its primary is the unchanged
`btnRefreshSheet` (same id, same gate, same action) and its menu (`mnuRefresh`) holds one
`toggleButton` (`btnToggleAutoRefresh`) — the same control family as the CHART and CELL lock
toggles — whose pressed state is the setting and whose label states it
(*Auto refresh on* / *Auto refresh off*). The primary's supertip no longer promises an
unconditional automatic refresh.

## Pipeline change

One predicate, three call sites, no new refresh path:

- `GanttRefreshScheduler.IsSuspended` = unlocked chart **or** switch off.
- Checked in `ScheduleCommandRefresh`, `OnSheetChanged`, and `OnTimerElapsed` (last-moment
  re-check), exactly where the chart-lock suspension already runs.
- Switching off calls `CancelPendingRefresh`, which discards a pass inside its debounce window
  and clears the sticky command flag, so the first edit after switching back on is not swallowed.
- Switching on schedules nothing: the next chart-affecting edit or an explicit Refresh
  reconciles. The switch itself therefore costs no pass.
- No macro-body re-check was added: `CancelPendingRefresh` bumps the generation the queued
  callback already compares, so an extra guard would be redundant and would change the existing
  chart-unlock race.

## Host report folded in: the toggle restores the add-in tab

Reported from the host on 2026-11-16: pressing the toggle pulled the ribbon to Excel's
contextual **Table Design** tab, because the settings write moves Excel's selection. The toggle
now ends with the same `ActivateGanttTab()` restore every refresh performs (ADR-0058, owner
ruling D-4), which is a no-op unless the surface is Ready on the Gantt sheet, so it cannot pull
the user onto the tab from anywhere else. Pinned by
`RibbonStateServiceTests.The_auto_refresh_toggle_restores_the_add_in_tab`.

## Persistent contract (schema version 25)

- `GanttAutoRefresh.SettingKey = "AutoRefreshEnabled"`, default `TRUE`, one row in
  `tblGanttSettings`; `Format` is the only writer.
- `GanttAutoRefresh.Parse` is fail-open: absent, blank, or unreadable means enabled, so a
  version-24 workbook behaves exactly as it did and a typo cannot silently stop every pass.
- The 28th settings row moves the table's extent to row 98, so `ConfigAnchor` moves A99 → A100
  to keep the blank row Excel's table auto-expand requires (the anchor invariant test enforces
  it).
- The schema version moves 24 → 25 and the pinned catalogue hash moves to
  `272526c2…fe8dd2f0`, because the hash seeds on the schema version. A version-24 workbook
  reports `CatalogueHashMismatch`; the remedy is Initialise (ADR-0029 D6, no migration).
- Seeding happens on the two occasions the workbook is authoritative — the first activation
  read and a workbook change — not on every Refresh. Re-seeding on every pass would undo a
  switch whose persist Excel had refused.

## Accepted trades (documented, not hidden)

While the switch is off, `Duration` (engine-derived), row heights, outline levels, hidden
columns, protection re-arm and the error fills stay unreconciled until a pass, and the Warnings
list keeps the last render's findings. That is the user's stated intent; the menu row states the
state and the primary's supertip names **Refresh chart** as the way back. Sheet activation and a
workbook switch still reconcile (ADR-0058 needs that pass), so "off" is not absolute.

**The ribbon's table projection is not one of these trades (owner ruling 2026-11-27).** It is a
read of the table plus a UI invalidation, not a reconciliation, so it republishes while the
switch is off and while the chart is unlocked. The switch still suspends the render exactly as
this work item states.

## Acceptance tests

- `GanttAutoRefreshTests`: the single stored form, fail-open read (null, blank, `TRUE`, garbage),
  the disabled token, the round trip, and the catalogue row's default.
- `GanttRefreshSchedulerTests`: the switch suspends both scheduling paths and switching back on
  re-enables them; the switch and the chart lock compose independently; the production
  constructor tracks `AutoRefreshPreferences.Shared`.
- `AutoRefreshRibbonTests`: off/on writes exactly one key and the requested value, invalidates the
  toggle, a refused write still applies the switch and is reported, the seed adopts the workbook's
  value (and rejects a null map), the pressed state reads the shared switch, and the label states
  the current state in both states.
- `GanttRibbonTests`: the Sheet group's splitButton shape (large splitButton, primary without
  `size`, menu holding the toggle), the toggle states its state through `getLabel`, and the
  toggle joins the pinned gated-controls set.
- `GanttConfigCatalogueTests` / `GanttSchemaVersionTests`: 28 settings keys, the anchor invariant,
  the schema version, and the re-pinned catalogue hash.

## Gates

`verify-quick.ps1` and the check scripts are reported in the handoff. `verify-office.ps1` is
**owed**: a menu-hosted toggleButton rendering, painting its state and stopping a cell-edit
render is observable only in Excel. `check-ribbon-glyphs.ps1` needs no new asset — a menu row is
not required to carry a picture, and the Size menu already ships without one.

## Exclusions

No per-user or per-machine preference, no second helper sheet, no scene or log data on the
configuration sheet, no change to the delta cache or the render contract, and no change to the
chart lock or cell lock toggles.
