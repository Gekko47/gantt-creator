# R0.3 — Central package management and lock file

> Block 0, R0.3 from `docs/03-ROADMAP.md`. Builds on R0.2 (the
> solution, projects, and central `Directory.Packages.props`).

## Outcome

`dotnet restore --locked-mode` succeeds twice from a clean state. The
second run is the proof: a fresh restore honours the lock file and
produces a deterministic dependency graph. Every CI run and every
local `verify-quick.ps1` run uses `--locked-mode` once the lock file
exists.

## Scope

- `Directory.Build.props`: enable central lock file at the solution
  root.
- `packages.lock.json` at the solution root, generated from a clean
  `dotnet restore` and committed.
- `scripts/verify-quick.ps1`: switch to `--locked-mode` when the lock
  file is present, plain `dotnet restore` otherwise.
- `scripts/test-locked-restore.ps1`: a deliberate two-run-from-clean
  test. Removes every `obj/` directory, runs the lock-mode restore
  twice, asserts both runs exit 0 and the produced `project.assets.json`
  files are byte-identical (or at least, that the second run does not
  trigger a network fetch).
- `docs/work-items/R0.3-central-packages-and-lockfile.md` (this file).

## Exclusions

- No new production packages. R0.3 is about the *lock file discipline*,
  not about adding dependencies.
- No `Microsoft.Windows.Compatibility` shim, no `Microsoft.Extensions.*`.
  Those land in R2.x and R8.x.
- No SBOM yet. SBOM is R10.7.
- No coverage enforcement. Per-project coverage thresholds are deferred
  to R3.x per `docs/04-TEST-STRATEGY.md`.

## Acceptance tests

- **Automated**:
  - `pwsh -NoProfile -File scripts/test-locked-restore.ps1` exits 0
    and reports two consecutive PASS runs from a clean state.
  - `pwsh -NoProfile -File scripts/verify-quick.ps1` exits 0 and the
    restore step reports the use of `--locked-mode`.
  - `git status --short packages.lock.json` shows the lock file is
    committed.

- **Visual Studio / Office**: None. R0.3 is pure infrastructure.

## Evidence commands

```powershell
# 1. Generate the lock file from a clean state
dotnet restore GanttCreator.slnx --force-evaluate

# 2. Confirm the lock file is at the solution root
Test-Path packages.lock.json    # expect True

# 3. Two-run clean test
pwsh -NoProfile -File scripts/test-locked-restore.ps1

# 4. The verify-quick gate now uses --locked-mode
pwsh -NoProfile -File scripts/verify-quick.ps1
```

## Risk and rollback

Risk: a transitive dependency changes between SDK updates and the lock
file prevents a legitimate upgrade. Mitigation: the lock file is
generated from a known-good restore and the discipline says "bump the
lock file in a dedicated commit, never silently". Rollback: `git
revert <commit>`; the lock file goes with the revert.

## Definition of done

- `Directory.Build.props` carries the central lock file policy.
- `packages.lock.json` exists at the solution root and is committed.
- `scripts/verify-quick.ps1` uses `--locked-mode` when the lock file
  is present.
- `scripts/test-locked-restore.ps1` exists and the two-run test PASSes.
- `docs/STATUS.md` records R0.3 as done.
