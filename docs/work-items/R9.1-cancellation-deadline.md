## Outcome

Long non-COM rendering operations gain a cancellation/deadline model
— a cancelled or timed-out operation leaves no partial output and the
host stays responsive — pinned by cancellation/deadline tests and a
live Excel-UI cancel.

## Scope

- `src/GanttCreator.Raster/` (and Core where the scene build is long)

  cancellation at a checkpoint aborts cleanly (no partial file —
  R8.6's atomic writer owns the file side).
- `src/GanttCreator.AddIn/` — the operation wrapper exposing progress/

## Exclusions

- No COM interruption (STA reality); no background threads around COM
  calls; no sleeps; no new UI surfaces beyond the cancel affordance
  the architecture already permits.

## Design decisions (behavioural)

- **D1 — Cooperative checkpoints, named.** Cancellation is polled at
  named checkpoints (per row-band, per primitive batch, pre-encode,
  pre-write); each checkpoint has a diagnostic name (for the timeout
  message).
- **D2 — Deadline with useful diagnostics.** The model carries an
  explicit deadline; exceeding it aborts at the next checkpoint with
  a message naming the checkpoint and elapsed budget — never a silent
  hang, never a sleep-based wait.
- **D3 — No partial output, ever.** Aborting mid-operation must leave
  the workbook/disk unchanged (the atomic writer + staging cleanup
  already guarantee their halves; this row's tests assert the whole
  path).
- **D4 — Host responsiveness.** Between checkpoints the STA returns
  to Excel (the mechanism fixed at Tier-A upgrade — e.g. yielding via
  the host's message loop as the Excel-DNA idiom allows) so the UI
  stays responsive during long renders; the live gate proves it.

## Acceptance tests

- **Automated**: cancellation at every checkpoint → no partial output
  (**positive test** per checkpoint); deadline exceeded → named
  checkpoint + budget in the diagnostics (**positive test**); the D4
  responsiveness contract where unit-testable.
- **Office host (Required)** — live: cancel a long render through the
  Excel UI; confirm the host remains responsive and nothing partial
  remains; record host builds.

## Stop conditions (item-specific)

- Responsiveness would require COM marshaling changes → stop (that is
  an architecture decision, not a local workaround).
- A checkpoint cannot observe cancellation without sleeps → stop;
  redesign the checkpoint.

## Risk and rollback

Main risk: half-cancelled states — the checkpoint discipline + the
no-partial-output tests exist for exactly that. Rollback: `git
revert`.
