# Work item — R2.2

## Outcome

The **Initialise sheet** Ribbon command brings a workbook into the supported
state with one action: a visible worksheet labelled `Gantt Data` containing the
`tblGanttData` table with the exact R2.1 header order, a sheet-scoped
`GanttCreator.PlotAnchor` defined name, and one add-in-managed
`_GanttCreatorConfig` worksheet at `xlSheetVeryHidden`. Nothing else in the
workbook is touched; every conflicting situation is a typed refusal that
mutates nothing.

## Decisions recorded here

- **D1 — Plot anchor.** Initialise writes the **sheet-scoped** defined name
  `GanttCreator.PlotAnchor` referring to the cell one column right of the
  table's last column on the header row (default `$O$1`). The Phase-4 renderer
  always derives the anchor from the live table and treats stored-vs-derived
  disagreement as an integrity finding (R2.10). Sheet-scoped (not
  workbook-scoped) so a future multi-Gantt-sheet extension needs no name
  migration; behaviour is identical for the supported single-sheet workbook.
- **D2 — Header materialisation.** All 14 columns of
  `GanttTableSchema.Default` (13 required + optional `SortOrder` last), per
  R2.1 decision D7.
- **D3 — Refusals.** Typed results, no mutation: no active workbook; target
  already contains `tblGanttData`; `_GanttCreatorConfig` already exists
  (repair is R2.10, "never create another helper sheet" holds by construction);
  target protected (rename/populate impossible). Unexpected COM failures
  propagate to the command boundary.
- **D4 — Hybrid sheet selection, uniform labelling.** The active worksheet is
  adopted when it is blank and renamed to `Gantt Data`; otherwise a new sheet
  labelled `Gantt Data` is created. Deterministic ` (n)` suffix on name
  collision (OrdinalIgnoreCase, Excel's own convention). Existing sheets are
  never modified, hidden, or deleted. Mutation order: read-only checks →
  rename → header row → table → config sheet → defined name; a failure after
  rename leaves at most a renamed blank sheet (cosmetic) and surfaces through
  the command boundary.
- **D5 — Application state.** No state-scope in R2.2 (that is R4.2); initialise
  performs no operations requiring save/restore discipline.
- **D6 — Forward note.** Multi-Gantt-sheet support is a candidate future phase
  requiring an ADR (one-visible-worksheet invariant + compatibility matrix
  change), a schema-version bump (workbook-unique table naming, per-sheet
  config keys), and a workbook-addressed Ribbon model. Not pre-built here; the
  sheet-scoped anchor (D1) and deterministic labelling (D4) leave the door open.

- **D7 — Success is silent.** A completed initialise shows no dialog (the
  renamed/populated sheet is self-evident), mirroring the command-boundary
  contract; only refusals and unexpected failures surface a message.
- **D8 — `imageMso="TableInsertExcel"` (evidence complete 2026-09-19).** The
  button carries the Excel Insert-Table glyph; it shipped label-only in
  `bb4386a` and an F5 run on 2026-09-19 confirmed the missing icon.
  `TableInsertExcel` satisfies **both** bases — the same standard as the
  working `FileOpen`/`Help`:

  1. **Excel idMso table** of `[MS-CUSTOMUI]-250218` (`.microsoft/`,
     git-ignored), row `idMso=TableInsertExcel, control=button,
     label="Table"` — the Excel Insert-Table command.
  2. **Office 2010 Icons Gallery** (`Office2010IconsGallery.docx`, whose
     embedded `customUI14.xml` lists 7344 unique `imageMso` IDs) — present.

  The gallery file reproduces all four documented outcomes, so the membership
  check is validated against known results rather than assumed: `Information`
  absent, `OfficeDiagnostics` present, `Help` present, `FileOpen` present.
  Note the id is `TableInsertExcel`, **not** its UI label `Table` — `"Table"`
  is itself absent from the gallery. An unknown `imageMso` fails silently (no
  error, no log), which is why both bases are checked. Pinned by
  `Ribbon_buttons_use_gallery_verified_imageMso_ids`. Remaining step: the
  operator's F5 confirmation that the glyph renders on the ribbon — the
  evidence is complete, the rendered pixels are not.

## Risk and rollback

Main risks: (a) interop leakage into AddIn (CS0433) — mitigated by the narrow
port and the Architecture boundary tests; (b) destructive write — mitigated by
refuse-unless-verified design and its positive tests; (c) mid-way failure
leaves partial state after rename — documented in D4 as at-most-cosmetic, with
R2.10 repair as the recovery path. Rollback: `git revert` of the single
commit; pure addition with no consumers.

## Notes during implementation

- `Gantt Data` is safe under Excel's naming rules (≤31 chars, none of
  `[ ] : * ? / \`); sheet-name uniqueness is case-insensitive, so collision
  detection is OrdinalIgnoreCase.
- Blankness is measured with `WorksheetFunction.CountA(UsedRange) = 0`; a
  sheet whose only content is a (headerless) `tblGanttData` still trips the
  `TableExists` refusal on the adopt path.
- `refersTo` for the plot anchor is built as `='<escaped sheet name>'!$O$1`
  with `'` doubled inside the name.
