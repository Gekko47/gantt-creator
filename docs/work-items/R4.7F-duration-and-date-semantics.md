## Outcome

`Duration` is calculated in Core from date-only semantics, written back in one
bulk pass on the explicit Refresh, correct for one-day and multi-day inclusive
spans, showing the approved marker for point and structural entities, and never
producing a misleading value from invalid or missing dates.

## Scope

- New `src/GanttCreator.Core/DurationCalculator.cs` — pure calculation, typed
  refusal
- `src/GanttCreator.Core/EntityDateMode.cs` — per-type rules consumed
- New Office port for the bulk `Duration` write
- `tests/GanttCreator.Core.Tests/DurationCalculatorTests.cs`
- `docs/REPO-MAP.md`, `docs/STATUS.md`

## Exclusions

- **No Excel formula.** The add-in writes the value; a formula would be visible in
  the formula bar and contradicts the locked column (ADR-0029 D3).
- No working-calendar engine. This is **calendar-day** duration.
- No rendering of any kind: `Duration` never affects geometry.

## Design decisions

- **D1 — Dates are date-only.** Any time-of-day component is normalised away
  before the calculation, so a workbook carrying date-times does not produce
  off-by-one durations.
- **D2 — Inclusive span:** `DurationDays = (Finish.Date - Start.Date).Days + 1`.
  This matches the entity guide's existing inclusive policy and `Finish` is never
  incremented.
- **D3 — Point and structural rules:** milestones and delineators show the
  approved non-duration marker (`-`); `Splitter`/`Spacer` are blank. Both read
  `Start` only, per the existing milestone/delineator contract.
- **D4 — Invalid or missing dates produce no value and a validation report.** A
  blank cell plus a blocking issue; never `0`, never `-1`, never a carry-over from
  the previous Refresh.
- **D5 — One bulk write.** A single ranged write over the `Duration` column, not a
  per-cell loop, per REV5 §10 and REV6 §11.
- **D6 — `Duration` is calendar-day duration** and is named and documented as
  such. It is not called "working duration", because no working calendar exists.
- **D7 — Calculation is pure and Core-owned.** A pure function over dates is
  testable without Excel, and the Office layer only performs the write.

## Acceptance tests

- **Automated** — `dotnet test tests/GanttCreator.Core.Tests`:
  - a one-day span → 1; a multi-day span → the correct inclusive count
  - a span crossing a month and a year boundary
  - a leap-day span
  - a milestone, a delineator, a `Splitter` and a `Spacer` each produce their
    documented value
  - a critical interval and a child activity each compute from their **own**
    dates, not the parent's
  - a date-time input normalises to its date component
  - missing start, missing finish, and finish-before-start each produce **no**
    value plus a typed report (positive tests)
  - the bulk write issues one ranged write, not N cell writes
- **Office host (Required)**: edit dates and confirm `Duration` updates **only**
  on Refresh. Record the host build.

## Step 0 — verify prerequisites

## Stop conditions

- A working-calendar requirement appears → stop; it is a product decision and
  would change the schema contract.
- A per-cell write proves unavoidable → stop and report the measured cost before
  abandoning the bulk write.

## Risk and rollback

Main risk: an off-by-one from a date-time input. Mitigated by D1 and by a
date-time normalisation test. Rollback: `git revert`.
