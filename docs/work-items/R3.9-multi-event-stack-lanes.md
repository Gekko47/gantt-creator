## Design decisions

- **D1 — One feed.** `LaneEventLayout` groups the deterministically
  ordered events (R3.4 D2) by lane, assigns each to its slot, and hands
  each slot's events (in subtype-priority/sort/ID order) to the bar/
  diamond builders with the slot centre. No builder re-derives slots.
- **D2 — Sequential and overlapping on one line.** Same-slot events
  keep one centre regardless of date overlap; sequential (non-overlap)
  events simply do not intersect; overlapping same-slot events render
  in layer-40 subtype order with one ambiguity warning per colliding
  pair-group (§9: never moved, never hidden).
- **D3 — Cross-stack separation.** Distinct `StackIndex` values place
  events in distinct slots separated by `StackGapPt` (R3.4 formulas);
  the planned/actual same-lane overlap case (§13) pins that neither
  event is shortened, moved, or hidden.
