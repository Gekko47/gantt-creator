## Design decisions (behavioural)

- **D1 — Byte-level assertions.** Tests parse the produced PNG bytes:
  signature, `IHDR` width/height (exact), `pHYs` (x=11811, y=11811,
  unit=1 metre), chunk order, and every chunk's CRC recomputed and
  compared — no reliance on a library's own getters for the pinned
  facts.
- **D2 — Density is exact, not approximate.** `11811` px/m both axes
  (the 300-DPI metre conversion, subject to integer rounding — the
  exact expected integers pinned).
- **D3 — The encoder's own density behaviour is measured first**
  (Step 0 probe); if patching is required, the patch is a documented,
  tested step — never a hope that the library got it right.

## Step 0 outcome and close-out (2026-11-23)

- **Prerequisites verified**: R8.4 landed (the representative render and its
  five baselines are committed); SkiaSharp 4.157.0 pinned by ADR-0071;
  `ExportSize` remains the sole size authority.
- **Encoder probe (disposable spike, deleted after recording)**:
  `SKBitmap.Encode(SKEncodedImageFormat.Png, 100)` produced a PNG with the
  chunk layout `IHDR(13) → sBIT(4) → IDAT(64) → IEND(0)` on a 40×30 solid
  frame (137 bytes) and wrote **no `pHYs` chunk**. The pre-ruled
  post-encode chunk-patcher arm is therefore the selected strategy; the
  stop condition (a full custom writer) was not approached.
- **Spec facts re-read at implementation**: PNG signature (8 bytes); chunk =
  4-byte big-endian length + 4-byte type + data + 4-byte CRC-32 over
  type+data; CRC-32 is ISO-HDLC (reflected `0xEDB88320`, check value
  `0xCBF43926` for `123456789`); `pHYs` data is 9 bytes (x ppu, y ppu, unit)
  with unit `1` = metre and the chunk must precede `IDAT`; 300 DPI =
  11811 px/m by a single rounding of 300 × 100 / 2.54.
- **Landed**: `PngCrc32`, `PngChunkReader` (internal), `PngExportBytes`,
  `PngExportEncoder` (+ internal `ApplyDensity`), `PngCrc32Tests`,
  `PngMetadataTests`, the independent `PngTestSupport` parser/CRC, and the
  `InternalsVisibleTo` entry that lets the tests drive the replace-in-place
  arm.
- **Evidence**: `dotnet test tests/GanttCreator.Raster.Tests -c Release` →
  179/179 on the reference machine (149/149 under the routine
  `Category!=FontProbe` gate); Release build 0 warnings. No Office gate
  (row: None).
