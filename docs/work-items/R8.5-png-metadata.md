## Outcome

The PNG encoder writes the `pHYs` 300-DPI metadata chunk correctly —
exact chunk order, valid CRCs, metre unit, `11811` pixels per metre on
both axes (subject to integer rounding) — pinned by chunk/CRC/unit
value tests.

## Design decisions (behavioural)

- **D1 — Byte-level assertions.** Tests parse the produced PNG bytes:
  signature, `IHDR` width/height (exact), `pHYs` (x=11811, y=11811,
  unit=1 metre), chunk order, and every chunk's CRC recomputed and
  compared — no reliance on a library's own getters for the pinned
  facts.
- **D2 — Density is exact, not approximate.** `11811` px/m both axes
  (the 300-DPI metre conversion, subject to integer rounding — the
  exact expected integers pinned).
- **D3 — The encoder's own density behaviour is measured first**
  (Step 0 probe); if patching is required, the patch is a documented,
  tested step — never a hope that the library got it right.

## Acceptance tests

  density; unit byte; a wrong-density fixture fails the comparator
  (**positive test**).
