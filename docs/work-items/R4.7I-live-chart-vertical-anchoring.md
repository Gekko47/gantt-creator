## Outcome

A live Refresh anchors the chart to the worksheet, not to the paper size. Every
visible lane-owning row's lane Top, Height and Bottom equal its Excel row's
exactly, the chart ends with the last row instead of running off the page, and the
year and period bands occupy reserved space above the plot rather than overlapping
the table's own header.

## Context — the defect this row exists for

Reported live: a bar belonging to worksheet row 2 rendered about 2.4 rows below
that row, and the chart continued roughly 400pt past the last row. Three coupled
defects, each verified against source:

1. `ExcelSceneBuildRequestFactory.Create` set the plot top to
   `TitleBandHeightPt + YearBandHeightPt + PeriodBandHeightPt` = 24 + 18 + 16 =
   58pt — a token sum with no knowledge of the sheet.
2. It set the plot height to `preset.HeightPt − top − chrome`, the **page** height
   (~531pt for A4 landscape), regardless of row count.
3. `GanttRefreshOrchestrator` renders with `ChartOriginDelta.Identity`, so those
   page coordinates reached Excel literally 58pt below row 1, while the first body
   row's real top is the never-normalised header height (~15pt) below row 1.

**The root cause is structural.** `PanelCellGrid` carries widths, per-row heights
and the header height but no absolute sheet position; `LaneMetricsResolver`
resolves a lane height only; `LaneLayoutBuilder` stacks from `plotBounds.Top`. So
ADR-0026 D3's `Excel Top == Scene lane Top` was not merely unmet but
**unrepresentable**. A constant offset correction would have hidden that and left
the height wrong.

## Scope

- `src/GanttCreator.Core/Scene/PanelCellGrid.cs` — carry the measured absolute
  origin (panel left, first body row top)
- `src/GanttCreator.Office/ExcelPanelGridMeasurement.cs` — measure that origin
- `src/GanttCreator.Office/ExcelSceneBuildRequestFactory.cs` — derive the live plot
  top and height from the measurement (ADR-0030 D1/D2)
- `src/GanttCreator.Core/Scene/PlotGeometryResolver.cs` — stop bounding the **live**
  vertical extent by the preset; keep the width formula and the export page check
- `src/GanttCreator.Office/ExcelWorkbookInitialiser.cs` — insert the reserved row
  and normalise the header row (D4/D5)
- `src/GanttCreator.Office/ExcelRowHeightNormaliser.cs` — normalise the header row
- `src/GanttCreator.Core/Scene/SceneBuilder.cs` — emit no live title band (D6)
- `docs/07-GANTT-ENTITY-GUIDE.md` — §4 and §9 already state this contract; amend
  only if the implementation reveals a genuine divergence
- Golden scene regeneration in its own dedicated commit

## Exclusions

- **No change to horizontal placement.** It is already correct: the plot's left edge
  is the measured panel width plus chrome, which lands on the first column past the
  table because hidden engine columns collapse to zero width.
- **No lane auto-growth** in any form. Scaling the lane to fill the preset is the
  defect ADR-0026 D2 removed, not a fix for this one.
- No Ribbon size-preset selector (R5.2), no scale selection (R5.2), no PNG/export
  changes (R8.x). Export composition keeps the title band and the page budget.
- No migration. A pre-ADR-0030 workbook reports a schema mismatch and is repaired by
  the approved path (ADR-0029 D6).

## Design decisions

- **D1 — The measured sheet origin becomes a required input.** `PanelCellGrid` gains
  the panel's absolute left and the first body row's absolute top, measured by the
  Office adapter and validated in Core with a typed refusal. Absent or non-positive
  is refused, never defaulted: a guessed origin is exactly the silent misalignment
  this row removes.
- **D2 — One live authority for the vertical origin.** The plot's top and height
  come from the measurement in the request factory, which is the same single caller
  `PlotGeometryAuthorityTests` already permits. No second derivation appears in a
  renderer, command or callback, and that architecture test keeps enforcing it.
- **D3 — The preset keeps the width budget and loses the live height.** R4.7H's
  `PlotWidth = PresetWidth − TextPanelWidth − Chrome` is untouched. Its page-height
  containment check applies to export composition; a live sheet is as tall as the
  user's row count, and refusing to render 40 rows because A4 is 29 rows tall is the
  same defect wearing a different hat.
- **D4 — The reserved row is written on Initialise and restored by the normaliser.**
  One row above the table at `YearBandHeightPt`, carrying the table title across the
  panel columns. It is add-in-owned state, so ADR-0029's ownership boundary applies
  and a schema bump ships in the same change.
- **D5 — The header row carries the period band.** The header row is normalised to
  `PeriodBandHeightPt`, so the period band's bottom is the header's bottom, which is
  the first body row's top. This is entity guide §4's existing requirement.
- **D6 — No live title band.** The title is the table's own title cell. `ShowTitle`
  keeps its meaning for export composition. `SceneBuilder` emits no title primitive
  under `LiveExcel`, and a test asserts the live scene's primitive set contains none.

## Acceptance tests

- **Automated — `dotnet test tests/GanttCreator.Core.Tests`**:
  - the measured origin is required: a grid with a negative or non-finite origin is
    refused with a typed reason (**positive test**, same commit)
  - plot top equals the first body row's measured top, exactly
  - plot height equals the sum of the measured body row heights, exactly
  - the plot's bottom equals the last row's bottom, exactly
  - for a mixed-height body, each lane's Top/Height/Bottom equal its own row's
  - a `LiveExcel` scene emits **no** title primitive, and an export-profile scene
    still does (**the counterweight**, so a future "never draw a title" rewrite fails)
  - a projection/delineator/critical child keeps the same anchoring as a plain bar
  - **golden regeneration** — human-reviewed, stated reason, dedicated commit
- **Automated — `dotnet test tests/GanttCreator.Office.ContractTests`**:
  - the measurement adapter reports the origin, and a hidden column or unreadable row
    still refuses
  - the factory derives top/height from the measurement; a mutated token-sum
    calculation fails these tests
  - initialisation writes the reserved row and the header height
- **Automated — `dotnet test tests/GanttCreator.Architecture.Tests`**: the existing
  single-authority guard still passes, and the resolver gains no Office reference.
- **Office host (Required)**: refresh a representative schedule; confirm every bar
  sits in its own row, the chart ends with the last row, the year/period bands sit
  above the plot, and a user-dragged row height is restored on the next Refresh.
  Record the host build.

## Step 0 — verify prerequisites

- **R4.7D, R4.7H and R4.8A must have landed.** This row amends contracts all three
  settled; if one is missing, that is a stop condition, not something to reinvent.
- Re-read ADR-0030 D4/D5 and entity guide §4 together. **If the owner intends two
  physically inserted rows rather than one, stop:** D5 is the decision to revisit and
  the guide must be amended in the same change.
- Probe the live host for the absolute origin before relying on a member shape. The
  measured origin is the whole row; `Range.Top` on a header range and on the first
  body row are two different members and guessing between them reproduces the class
  of defect ADR-0019 was raised for. Prefer `ListObject.HeaderRowRange` and
  `DataBodyRange`, verify with a live probe, and record the evidence.

## Stop conditions

- **Exact row/lane equality proves unachievable on the live host → stop** and report
  the measured values. A tolerance is a decision, not an implementation detail.
- Anchoring would require editing a row the add-in does not own → stop;
  ADR-0029's ownership boundary applies.
- A second plot-geometry authority appears → stop; that is R4.7H D1's whole claim.
- The measured origin cannot be obtained without a second measurement port → stop
  and report, rather than widening `ExcelPanelGridMeasurement`'s ownership.

## Risk and rollback

Main risk: the live chart's vertical extent changes from page-shaped to table-shaped,
which is user-visible — a 40-row schedule now renders 40 rows tall where it
previously showed 29 and pushed the rest off the page. That is ADR-0030 D2's intent,
not a regression, and the golden regeneration exists to make the change reviewable.
Rollback: `git revert`.
