## Design decisions

- **D1 — One orchestrator.** `SceneBuilder` composes settings +
  catalogues + validated events + measured grid → `TimeScale` →
  `LaneLayoutBuilder` → `FrameBandsBuilder` → `LaneEventLayout` →
  span/milestone/overlay/delineator/panel builders → ordered
  `GanttScene` + warnings. Single entry point for Phase 4+.
  **The measured panel grid and the panel/plot bounds are `SceneBuilder`
  *inputs*, not things it derives:** `PanelCellGrid` is documented
  input-only ("it never measures"), and `FrameBandsRequest` takes
  `PanelBounds`/`PlotBounds` as caller-supplied. A Phase 4/5 adapter
  measures the live Excel geometry; Core consumes it. Consequently
  `SceneBuilder` must **not** source `PlotBounds` from the
  `FrameBandsBuilder` result — that is caller-supplied input, and the
  frame builder derives bands *within* it. The one derived value is
  `PanelBuildRequest.HeaderBottomPt`, which R3.11 step 2 fixed to
  `PlotBounds.Y - YearBandHeightPt`; `SceneBuilder` supplies that and
  a test asserts the resulting header bottom equals it, so the
  alignment is proven rather than assumed.
- **D2 — One canonical neutral fixture.** `tests/fixtures/reference-gantt.json`
  is the single committed construction-delay input consumed by Core scene
  tests and Office integration tests. `ReferenceSceneFixture` loads and
  normalises it through the landed R2 pipeline; it matches the entity-guide
  minimum plus planned/actual/baseline overlap, critical children, delay,
  procurement, milestones, stacked events, delineators, row overrides,
  warnings, and parent/child identity. Fully deterministic; no randomness and
  no alternate renderer-specific schedule.
- **D3 — Benchmark without a new dependency.** A `Stopwatch` harness
  in `SceneBenchmarkTests` (always runs, never fails on hardware
  variance): asserts correctness at 1,000 deterministic synthetic
  events and records elapsed time to test output; the **250 ms
  judgement is recorded evidence** on the reference machine
  (hardware + elapsed + verdict in this file's Notes), per the
  architecture's "record the reference hardware" rule.
- **D4 — Golden scene snapshot.** The fixture's `SceneSnapshot`
  serialization is committed as
  `tests/golden/scene/reference-scene.json` — a *scene* baseline derived from
  the canonical neutral fixture, not a golden image (no human image review),
  but the same change policy: a stated reason and a dedicated commit for any
  update. Determinism pin: rebuilding reproduces the file byte-for-byte.
- **D5 — The validator reports on a *candidate* scene, not a built one.**
  `SceneValidator` inspects the pre-`TryCreate` primitive list plus bounds and
  returns a zero-throwing `SceneValidationReport`. This is a deliberate
  narrowing of the original step 2/4 wording, and it exists because several
  "broken scenes" the plan named **cannot be constructed at all** against the
  landed model:

  | Invariant named in step 2/4 | Constructible today? | Owner |
  | --- | --- | --- |
  | NaN / `Infinity` on a `SceneRect` | No — `RectD` throws | `RectD` |
  | Negative width or height | No — `RectD` throws | `RectD` |
  | Duplicate primitive ID | No — `GanttScene.TryCreate` refuses `DuplicatePrimitiveId` | `GanttScene` |
  | Unresolved group child / cycle | No — refused as `UnresolvedGroupChild` / `CyclicGroupChild` | `GanttScene` |
  | Non-finite `SceneLine` endpoint | **Yes** — `PointD` performs no validation | **`SceneValidator`** |
  | Non-finite `SceneLine` endpoint | **Yes** — `PointD` performs no validation | **`SceneValidator`** |
  | Label outside chart bounds | **Yes** | **`SceneValidator`** |
  | Duplicate warning (owner, code) | **Yes** | **`SceneValidator`** |
  | Malformed primitive-ID role format | **Yes** | **`SceneValidator`** |
  | Polygon with fewer than 3 points | No — `ScenePolygon` throws | `ScenePolygon` |
  | Non-finite polygon point | No — `ScenePolygon` throws | `ScenePolygon` |
  | Label outside chart bounds | **Yes** | **`SceneValidator`** |
  | Duplicate warning (owner, code) | **Yes** | **`SceneValidator`** |
  | Malformed primitive-ID role format | **Yes** | **`SceneValidator`** |

  So the validator **owns** the four reachable invariants, and each ships a
  positive test in the same commit. The unreachable ones are **not**
  re-implemented and **not** re-tested here: each is already enforced at
  construction, and step 4 cites those existing positives instead of
  duplicating them. This keeps AGENTS.md's rule that
  every new `if (bad) { error }` ships with a positive test satisfiable
  without asserting an unconstructable scene or weakening an existing guard.

## Implementation steps (in order)

1. `SceneBuilder` orchestration (D1) with typed refusals for invalid
   inputs (**positive tests**).
2. `SceneValidator` (D5): over the pre-`TryCreate` candidate primitive
   list — non-finite `SceneLine` endpoint, label containment in chart
   bounds, warning deduplication by (owner, code), and primitive-ID role
   format. Typed report, zero throwing. The unreachable invariants
   (finiteness/negative extent via `RectD`; polygon point count and
   finiteness via `ScenePolygon`; duplicate ID, unresolved child, cycle via
   `GanttScene.TryCreate`) are delegated, not re-implemented.
3. `ReferenceSceneFixture` (D2) + golden snapshot (D4).
4. Tests: validator positives — **one deliberately broken candidate per
   validator-owned invariant (non-finite line endpoint, out-of-bounds
   label, duplicate warning, malformed role) — each detected**, plus a
   zero-findings report over the real built scene. The
   delegated invariants cite the existing `RectDTests` and
   `GanttSceneTests` positives rather than duplicating them. Then fixture
   determinism (build twice → byte-identical; ≥3 shuffles → identical);
   golden-file match; benchmark harness (correctness + recorded elapsed at
   1,000 seeded synthetic events).
5. Record the reference-machine benchmark result in this file's Notes
   (human or self-hosted runner: hardware, elapsed, verdict vs 250 ms).
6. Docs: REPO-MAP, STATUS, status line (+ optional L4 re-date note).
   One commit: `feat: R3.12 …` — Checklist: B, E, G, I.

## Findings raised by R3.12 (not fixed here)

- **R3.5 `FrameBandsBuilder` does not check that its header bands fit inside
  the chart.** Discovered when the R3.12 validator reported a `LabelOutsideChart`
  finding against a scene the orchestrator had itself built: with a plot top of
  20pt and band heights totalling 50pt, the period band is emitted at
  `y = -16`, above the chart's own top edge. `FrameBandsRequest.TryBuild`
  validates that each band height is positive but never that the bands fit above
  the plot within `ChartBounds`, so it silently emits out-of-chart geometry.
  **This is R3.5 behaviour, not R3.12's**, and AGENTS.md forbids opportunistically
  refactoring a neighbouring work item, so it is recorded rather than fixed here.
  R3.12's own fixture uses a plot top that accommodates the bands. The fix
  belongs in a follow-up: either refuse a request whose bands do not fit, or
  report it as a warning the same way a title overflow is.
- **`ScenePolygon`'s fewer-than-three-points and non-finite-point guards have no
  positive test** anywhere in `tests/`. Both are `if (bad) { throw }` validators
  in already-shipped code, and AGENTS.md requires a positive test in the same
  commit as the validator. The guards are correct; only their proof is missing.
- **~72 work items name a non-existent solution path** (`src/GanttCreator.slnx`)
  in their evidence blocks, so those commands cannot run. R3.12's own block is
  corrected; the rest are left alone as unrelated work-item drift.
