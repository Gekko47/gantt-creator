## Design decisions (behavioural)

- **D1 — Two selections, one bounds rule.** Chart-only = the scene's
  `ChartBounds` (§1 union rule) without the data-panel contribution;
  table-plus-chart = the union including the panel grid bounds. Both
  exclude whitespace outside the union; both carry the grouped-export
  bounds the later grouping step will verify against. **Both must carry
  the placement delta from the zero-origin translation** that entity
  guide §1 requires of a renderer. (The 2026-09-27 decision was
  recorded as provisional pending the R4.3 Step-0 probe; **settled:
  R4.3 landed**, and guide §1 now states the uniform translation and
  the delta-carriage rule as binding renderer facts — "The delta must
  be carried into the export bounds.") §1 says empty whitespace outside
  the bounds is not exported, and the padding sits *inside* the
  bounds, so a crop computed from an un-translated `ChartBounds` would
  export a chart missing exactly `ChartOuterPaddingPt` of margin on
  two sides. A bounds test that crops from `ChartBounds` without
  applying the delta is the defect this bullet exists to prevent.
- **D2 — Refusals, not empties.** An empty visible table with
  table-plus-chart selected refuses with the actionable message
  (aligned with §1 "an empty data table … is not a valid export");
  invalid bounds refuse before any composition. **Do not "fix" this
  refusal to match the live path (verified 2026-11-18):** a live empty
  table renders a calendar-year chart (ADR-0050, R5.18j), while §1
  keeps an empty table invalid *as an export* — the refusal is
  export-only by contract, not an oversight.
- **D3 — The model is the contract for R6.3's group-bounds check and
  Phase 8's crop bounds** — recorded so those rows consume, never
  recompute.
- **D4 — The selections ride the existing profile/panel seam
  (verified 2026-11-18).** The two modes are expressed through types
  that already exist: chart-only = a `SceneBuildRequest` with
  `Profile = SceneCompositionProfile.EditableExport` and `Panel` left
  null; table-plus-chart = the same profile with `Panel` set.
  `SceneCompositionProfiles.DrawsDataPanel` fails closed on
  unrecognised profiles and `SceneBuilder` already refuses a live
  request carrying a panel (`LiveProfileCarriesPanel`), so the
  selection model adds no second authority — it chooses whether
  `Panel` is supplied.
- **D5 — Zero visible columns degrade, not refuse (ADR-0065).**
  Table-plus-chart with every user column hidden is a supported
  workbook state (R5.22): the measured grid sums to zero width, the
  panel contributes no bounds, and the export bounds equal the
  chart-only bounds. ADR-0065 D4's wording — "an export composition
  with no panel has nothing to overlap" — is the ruling this pins. A
  bounds test covers the zero-column case so a later change cannot
  turn it into a refusal or a phantom-width panel.
- **D6 — Collapsed rows shrink the panel, never the Gantt (roadmap
  Phase 6 note, revision 10).** A collapsed outline group's child rows
  measure zero height (`PanelCellGrid` accepts zero-height rows by
  design, ADR-0034), so the panel bounds shrink to the visible
  parent/top-level rows, while every render-visible child shape and
  label still composes (children draw on their parent's lane via the
  R4.7B projection). A bounds test pins the collapsed case in both
  selection modes.

## Amendment 2026-11-18 — R6.2 consumes the scene

R6.2's panel composition needs the scene the bounds were read from, and the resolver was
building it and then discarding it. `ExportBoundsOutcome` gained an additive
`GanttScene? Scene` member (default `null`, so refusals and every existing caller are
unchanged), making the resolver the single build authority for both the bounds and the
composition rather than forcing a second `SceneBuilder.TryBuild` of the same request.
No R6.1 pin needed an edit; `ExportBoundsResolverTests` gains two facts —
`The_resolved_scene_is_the_scene_the_bounds_were_read_from` (the carried scene equals a
direct export build, identifiers in order) and `A_refusal_carries_no_scene`.
