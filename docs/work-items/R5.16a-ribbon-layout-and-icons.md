# Work item — R5.16a ribbon layout, grouping and icons

> **Guide status**: landed 2026-11-12. Extends [R5.16](R5.16-ribbon-first-run-and-data-group.md)
> (surface and modes) and [R5.9](R5.9-ribbon-completion.md) (icons, keytips, presentation
> contracts). Plan: [ribbon-compact-layout-and-context-plan.md](../../plans/ribbon-compact-layout-and-context-plan.md).
> The live-host render check is owed; see "Office host gate".

## Outcome

The Gantt Creator tab fits without a horizontally scrolled group, every control carries its
own verified glyph, and the groups read as subjects rather than as leftovers: **Data**,
**Outline**, **Labels**, **Style**, **Chart**, **Size**, **Sheet**, **Diagnostics**.

- **Ordering is merged into Outline** — Promote/Demote, Up/Down, Expand all/Collapse all in a
  two-wide, three-storey grid. Promote/Demote are Excel's own outline group/ungroup
  operations, so "Outline" is the native name for the subject.
- **Plot Area and Plot Time Scale are merged into Chart** — one row per date (caption, box,
  inline `Auto` checkbox) plus the scale row.
- **Plot Size becomes Size** — the four preset buttons become one dropdown that also shows
  the stored preset, and the two permanently-disabled width/height edit boxes become
  `labelControl` readouts.
- **"Style and Theme" becomes Style**; the Labels captions shorten to Description / Date /
  Style.
- **`grpPlaceholder`, labelled "Gantt Creator", becomes `grpSheet`, labelled Sheet**, laid out
  as a 2 × 2 grid.
- **The Data group keeps its owner-tooled five large controls.** Only the two labels change
  (**Repair**, **Elements**) and each control gets its own glyph.
- **Every control has a distinct `imageMso`**, and a test now rejects a duplicate.

No command, menu item, keytip or split-button structure was removed.

## Design decisions

- **D1 — Groups are subjects, not leftovers.** One label per subject; three storeys maximum;
  frequency descending left to right so Excel's right-to-left group collapse sacrifices
  Diagnostics and Sheet before Data.
- **D2 — Presets are one dropdown.** The item ids are the durable `SizePreset` keys, so the
  dropdown is a projection of `SizePresets.All`; a workbook with no preset reads as no
  selection (-1), never a phantom item.
- **D3 — Read-only output is a label, not a disabled input.** Excel's `editBox` has no
  read-only attribute, so the old shape was a greyed input that read as broken.
- **D4 — One glyph per control.** Duplicates are a test failure, not a style preference. Menu
  items are exempt because a dropdown may legitimately repeat a glyph (the two landscape
  presets share the landscape orientation icon).
- **D5 — Icons are verified, never guessed.** An id must be in the Office 2010 Icons Gallery
  and in the `[MS-CUSTOMUI]` idMso table; `check-ribbon-icons.ps1` enforces both and
  self-tests its own validator before checking the ribbon.

## Stop conditions

- A control cannot be given a distinct, verified glyph → stop for the owner; do not duplicate
  a glyph and do not ship a blank one.
- The host renders `CalendarInsert` blank → swap it for the recorded Excel-block fallback in a
  one-line change with the pin updated.

## Risk and rollback

Main risk: pinned XML lists and the group ids were renamed, so a stale pin would fail loudly
rather than silently. Rollback: `git revert` this row; the previous ribbon is a single commit.

## Live-host defect found and fixed (2026-11-13)

Selecting a Size raised `Custom UI Runtime Error in GanttCreator.AddIn Add-In / Callback
signature mismatch: "OnSizeChange"`. Two defects in one handler:

- **Arity.** `dropDown.onAction` calls `(control, selectedItemId, selectedIndex)`; the
  handler was `OnSizeChange(IRibbonControl control)`. A wrong arity compiles, passes every
  offline test, and fails only in the host.
- **Wrong source for the preset.** The handler read `control.Id`, which is the dropdown's own
  id (`ddnSize`), never the chosen item id, so even a matching signature would have applied
  nothing.

Fixed: the callback is now `OnSizeChange(IRibbonControl, string selectedId, int selectedIndex)`
and the preset comes from `SizePresets.ByKey(selectedId)`; the injectable seam is
`OnSizeChange(control, selectedId, RibbonStateService)`. The two routing tests now pass the
item id explicitly and assert the control id is ignored, so the old mistake cannot come back
silently.

**New gate:** `RibbonCallbackSignatureTests.Every_declared_callback_has_the_signature_excel_calls`
parses the shipped `Ribbon.xml` through `GetCustomUI`, classifies every callback attribute by
the element that carries it (`onAction` on a button, a toggle, a checkbox and a dropdown are
four different contracts), and requires a method with exactly the parameter list Excel
passes. Two positive controls prove the validator accepts the canonical dropdown action and
rejects the seam-shaped one. Observed: the gate reported this single violation on the
pre-fix tree and none after it.
