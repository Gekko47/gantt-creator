# Work item — R5.16a ribbon layout, grouping and icons

> **Guide status**: landed 2026-11-12. Extends [R5.16](R5.16-ribbon-first-run-and-data-group.md)
> (surface and modes) and [R5.9](R5.9-ribbon-completion.md) (icons, keytips, presentation
> contracts). Plan: [ribbon-compact-layout-and-context-plan.md](../../plans/ribbon-compact-layout-and-context-plan.md).
> The live-host render check is owed; see "Office host gate".

## Outcome

The Gantt Creator tab fits without a horizontally scrolled group, every control carries its
own verified glyph, and the groups read as subjects rather than as leftovers: **Data**,
**Outline**, **Labels**, **Style**, **Chart**, **Size**, **Sheet**, **Diagnostics**.

- **Ordering is merged into Outline** — Promote/Demote, Up/Down, Expand all/Collapse all in a
  two-wide, three-storey grid. Promote/Demote are Excel's own outline group/ungroup
  operations, so "Outline" is the native name for the subject.
- **Plot Area and Plot Time Scale are merged into Chart** — one row per date (caption, box,
  inline `Auto` checkbox) plus the scale row.
- **Plot Size becomes Size** — the four preset buttons become one dropdown that also shows
  the stored preset, and the two permanently-disabled width/height edit boxes become
  `labelControl` readouts.
- **"Style and Theme" becomes Style**; the Labels captions shorten to Description / Date /
  Style.
- **`grpPlaceholder`, labelled "Gantt Creator", becomes `grpSheet`, labelled Sheet**, laid out
  as a 2 × 2 grid.
- **The Data group keeps its owner-tooled five large controls.** Only the two labels change
  (**Repair**, **Elements**) and each control gets its own glyph.
- **Every control has a distinct `imageMso`**, and a test now rejects a duplicate.

No command, menu item, keytip or split-button structure was removed.

## Design decisions

- **D1 — Groups are subjects, not leftovers.** One label per subject; three storeys maximum;
  frequency descending left to right so Excel's right-to-left group collapse sacrifices
  Diagnostics and Sheet before Data.
- **D2 — Presets are one dropdown.** The item ids are the durable `SizePreset` keys, so the
  dropdown is a projection of `SizePresets.All`; a workbook with no preset reads as no
  selection (-1), never a phantom item.
- **D3 — Read-only output is a label, not a disabled input.** Excel's `editBox` has no
  read-only attribute, so the old shape was a greyed input that read as broken.
- **D4 — One glyph per control.** Duplicates are a test failure, not a style preference. Menu
  items are exempt because a dropdown may legitimately repeat a glyph (the two landscape
  presets share the landscape orientation icon).
- **D5 — Icons are verified, never guessed.** An id must be in the Office 2010 Icons Gallery
  and in the `[MS-CUSTOMUI]` idMso table; `check-ribbon-icons.ps1` enforces both and
  self-tests its own validator before checking the ribbon.

## Live-host defect found and fixed (2026-11-13)

Selecting a Size raised `Custom UI Runtime Error in GanttCreator.AddIn Add-In / Callback
signature mismatch: "OnSizeChange"`. Two defects in one handler:

- **Arity.** `dropDown.onAction` calls `(control, selectedItemId, selectedIndex)`; the
  handler was `OnSizeChange(IRibbonControl control)`. A wrong arity compiles, passes every
  offline test, and fails only in the host.
- **Wrong source for the preset.** The handler read `control.Id`, which is the dropdown's own
  id (`ddnSize`), never the chosen item id, so even a matching signature would have applied
  nothing.

Fixed: the callback is now `OnSizeChange(IRibbonControl, string selectedId, int selectedIndex)`
and the preset comes from `SizePresets.ByKey(selectedId)`; the injectable seam is
`OnSizeChange(control, selectedId, RibbonStateService)`. The two routing tests now pass the
item id explicitly and assert the control id is ignored, so the old mistake cannot come back
silently.

**New gate:** `RibbonCallbackSignatureTests.Every_declared_callback_has_the_signature_excel_calls`
parses the shipped `Ribbon.xml` through `GetCustomUI`, classifies every callback attribute by
the element that carries it (`onAction` on a button, a toggle, a checkbox and a dropdown are
four different contracts), and requires a method with exactly the parameter list Excel
passes. Two positive controls prove the validator accepts the canonical dropdown action and
rejects the seam-shaped one. Observed: the gate reported this single violation on the
pre-fix tree and none after it.

**Owner's live pass, 2026-11-13:** "the overall UI looks good as planned". The layout and the
glyph set are therefore observed on the host, not merely built. The one defect the pass found
was the Size dropdown above, and no other error was reported.

### Second live defect: `GetSize` returned -1 (2026-11-13)

On a brand-new blank sheet the host reported `The callback function "GetSize" on control
"ddnSize" returned an invalid value`. `GetSize` returned -1 whenever the workbook named no
preset, and Excel's `getSelectedItemIndex` has no "nothing selected" state: a negative index
is rejected as an invalid value, before the control is even visible. The other two static
dropdowns never hit this because their getters always resolve a real item (the margin and
time-scale defaults).

Fixed: `GetSize` is total — no preset, an unknown key, a thrown probe and an empty catalogue
all resolve to a real index, and a catalogue entry with no matching item is clamped — so every
reachable state names an item.

**Second new gate:** `The_size_dropdown_items_are_the_size_preset_catalogue_in_order` reads the
shipped `Ribbon.xml` and requires the `ddnSize` item ids to equal `SizePresets.All` in order.
That is the invariant behind the index: a preset added to Core without a matching item would
otherwise let `GetSize` report an index the dropdown cannot resolve, which the host rejects in
exactly the same way.

## Auditing for this defect class (2026-11-13)

Both live defects were callback-contract defects that no offline test could see, so the
answer is a second gate rather than a promise to be careful. `RibbonDropdownContractTests`
covers the half a signature check cannot: the values a control is handed.

- **Id round-trip.** For every `dropDown`, each item id read from the shipped `Ribbon.xml` is
  routed through that dropdown's `onAction` and must land on the same index the dropdown
  shows. This is the `control.Id`-instead-of-item-id defect, generalised: a dropdown whose
  ids the handler does not accept looks fine and does nothing.
- **List coherence.** With no workbook, table or selection, every dynamic list must report a
  non-negative count, a selected index that lies inside it, and a non-empty unique id and
  non-empty label for every index the count promises. A list that offers three items and an
  empty id at index two hands Excel a value it cannot resolve — the same class as the -1.
- **Total getters.** `GetSize` is asserted never negative, and
  `The_size_dropdown_items_are_the_size_preset_catalogue_in_order` pins the dropdown to the
  catalogue it projects.

Observed on this tree: all four checks pass, so no defect of this class remains on the axes
they cover. What they cannot reach is host behaviour — rendering, tab activation and COM
event timing — which is why the owner's live pass stays part of the process.

The review method, transferable to the next control: for each `get*` ask whether it can
return null, empty, negative or out-of-range in any reachable state; for each dynamic list ask
whether the count is computed from the same authority as the ids and labels; for each
`onAction` ask whether it accepts the id the getter serves; and for every value Excel must
convert, ask whether the type is exact.

### Sweep finding: the setting writers could not be exercised headlessly (2026-11-13)

The value sweep found a real defect of a different kind. All eight setting writers in
`RibbonStateService` (Auto start, Auto finish, both explicit date commits, time scale, margin,
margin in centimetres, and the size preset) ran their persist through
**`CommandBoundary.Instance`** — a process-wide singleton whose presenter is a modal TaskDialog
and whose `Instance` cannot be replaced.

Observed, not inferred: a contract test that clicks the Auto checkbox hung the test host.
`--blame-hang` killed it after 45 s of inactivity, and the same session then stalled for hours.
Adding the seam below made the identical test pass in 50 ms. That before/after is the evidence;
the branch inside the boundary that presented was **not** identified — two attempts to force it
did not converge, so it is recorded as unknown rather than guessed.

Fixed by a seam, not a behaviour change: `RibbonStateService` now holds
`private CommandBoundary _commandBoundary = CommandBoundary.Instance`, set through
`SetCommandBoundary`, restored by `Teardown`, and the eight writers plus the refusal report call
`_commandBoundary.Run(...)`. Production still reports through the singleton and still shows
exactly one dialog on failure; what changed is that a test can install a capturing boundary
instead of waiting forever for a dialog.

The consequence for the product is worth stating plainly: before this seam, no offline test
could exercise the failure path of any setting write, so a regression in the persist-report
path was invisible to the entire suite. It is now coverable, and the Auto round-trip tests use it.
