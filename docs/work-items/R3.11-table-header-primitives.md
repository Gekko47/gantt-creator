## Design decisions

- **D1 — §23 date labels live here** (they share the display-format and
  planner machinery; no other Phase-3 row names them). **Stop-point:**
  if the product owner prefers §23 elsewhere, move it before
  implementation — do not silently split.
- **D2 — Measured grid is an input.** `PanelCellGrid` carries included
  columns (per the export-inclusion settings), their widths/heights in
  points, and alignment; validated (positive widths, required columns
  once, no zero row count with content). The builder never measures.
- **D3 — Cell primitives.** Per included cell: background `SceneRect`
  (`DataPanelFill`), `SceneText` (body text; dates in the approved
  display format), shared borders as layer-80 lines exactly at cell
  edges; header row per §4 (schema display names, `HeaderFill`,
  `HeaderFontSizePt` bold; **`Description` left-aligned, others
  centred — flagged for product confirmation**, §4's sentence implies
  it). Header bottom aligns exactly with the period-header bottom
  (R3.5 bounds). Panel right edge touches `PlotBounds.Left` with zero
  gap/overlap — asserted, not assumed.
- **D4 — §23 labels.** Start/finish date labels near their bar per
  §23's approved display formats, independent visibility, clipping
  policy, and collision handling through `LabelPlanner` at the
  date-label rank; stable role-derived IDs (`<rowId>:date-start`,
  `<rowId>:date-finish`); same-date start/finish labels resolve
  deterministically.
