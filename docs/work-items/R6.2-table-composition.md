## Design decisions (behavioural)

- **D1 — Scene-driven, cell-free.** Every composed shape comes from a
  scene primitive; zero live cells are included; a contract test
  asserts zero cell writes and zero sheet additions (**positive
  test**).
- **D2 — Exact reproduction.** Shape count = the panel primitive
  count; bounds = primitive bounds (within the documented tolerance);
  texts verbatim; styles from the token mapping (R4.6); z-order per
  the scene (R4.5's one-pass rule). **The collapsed panel is the
  composed panel (roadmap Phase 6 note, revision 10):** the scene
  already projects every source row (`PanelRowProjection`) onto the
  measured grid, where a collapsed group's children measure zero
  height and consume no space — so the staged panel shows the visible
  parent/top-level rows after collapse while the Gantt side still
  carries every render-visible child shape. A composition test pins
  the collapsed case; the panel never re-filters rows itself.
- **D3 — Temporary + owned from birth.** Every staged shape carries
  the temporary/owned marking (the R4.3 tag mechanism + the staging
  lifecycle's collection contract — R6.5 owns the lifecycle, this row
  registers into it).
- **D4 — Staging identity is distinct from live ownership (added
  2026-11-18; feasibility gap in the first draft).** Staged shapes
  land on the **same worksheet** as the live chart, and the live
  renderer names every shape by its primitive id and tags it
  `GanttCreator.Owned.v1:{hash}` (`ShapeOwnershipTag.ForPrimitiveId`).
  Staging shapes reusing those names and that tag would be
  indistinguishable from live chart shapes: Excel permits duplicate
  shape names, so `ExcelShapeWriter.FindShapeByName` and
  `ShapeReconciler` would see ambiguous duplicates, and a coalesced
  automatic refresh during staging would reconcile or delete staging
  shapes mid-operation. Every staged shape therefore carries a
  **staging name prefix** and a **distinct staging ownership tag**
  (proposed `GanttCreator.Staging.v1:{hash}`; exact value fixed in
  this row's ADR-level notes at implementation), and the live
  reconciler is proven to ignore staging-tagged shapes (**positive
  tests**: a refresh during staging leaves staging shapes untouched;
  a staging cleanup leaves live owned shapes untouched).
- **D5 — Zero visible columns compose no panel (ADR-0065).**
  Table-plus-chart at zero visible columns follows R6.1's D5: the
  grid sums to zero width, no panel primitives are emitted, and the
  composition is the chart alone. A composition test pins the
  zero-column case.

## Stop conditions (item-specific)

- Composition would need to read worksheet cells directly → stop
  (scene is the source; measured bounds entered the scene in Phase 4).
- A live cell would remain in the export → stop (the architecture's
  premise).

## Risk and rollback

Main risk: primitive-count drift when R3.11 changes — pins fail
loudly; update together. Rollback: `git revert`.
