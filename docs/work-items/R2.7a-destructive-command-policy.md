## Design decisions (manifest decision D-G2 — human choice on D3 required
before the ADR is accepted; D6 needs explicit acknowledgement)

- **D1 — Destructive means user-data deletion.** A command is destructive
  iff its success path deletes user-authored content (rows of
  `tblGanttData`, user cells). Add-row, per-row property edits, and
  clearing add-in-owned validation notes are mutations but not
  destructive; they never confirm. First destructive consumer: R5.8
  Remove rows.
- **D2 — Confirmation contract.** Exactly one modal confirmation per
  destructive command, using the `DiagnosticsService.TaskDialog` pattern:
  main instruction names the action and the affected row count only
  (never schedule content, mirroring R2.6's count-only summaries);
  default button is Cancel (safe default); Enter never confirms. Dialog
  text is built by Core (`DestructiveCommandPolicy`) so it is
  unit-testable and culture-invariant.
- **D3 — Undo semantics: options for the human (D-G2).**
  - **Option 1 (recommended): no-undo, warned.** The confirmation states
    "This change cannot be undone." Rationale: COM-driven `ListRow`
    deletions do not enter Excel's undo stack (roadmap note); an honest
    no-undo is safer than a partial simulation. Transactional undo is
    explicitly deferred and recorded as a known limitation.
  - **Option 2: add-in-managed transactional undo.** Pre-read the full
    rows (all 14 columns) before deletion; offer an add-in "Undo remove"
    that re-inserts them. Heavier: needs row-position semantics, ID
    collision handling, and its own failure tests; becomes its own work
    item via the scope-change protocol if chosen.
- **D4 — Protected-sheet guard, shared and read-only.**
  `IWorksheetProtectionGuard` probes `ProtectContents` (and workbook
  structure protection where the operation touches workbook structure)
  and returns a typed outcome (`NotProtected` / `SheetProtected` /
  `WorkbookStructureProtected` / `NoActiveWorkbook`). Every mutating
  Office adapter calls it as its first read-only check — extending R2.2's
  `TargetProtected` pattern to all future commands; the guard itself
  mutates nothing. Seams mirror `ExcelWorkbookInitialiser`
  (`internal virtual` over the COM property).
- **D5 — Layering.** Core owns the policy and text (pure); Office owns
  the probe; AddIn owns presentation only. No interop type crosses the
  port (CS0433 discipline).
- **D6 — When the live destructive exercise is recorded.** At R2.7a time
  no destructive command exists yet. Recommended reading of the Office
  gate: R2.7a exercises the protected-sheet refusal live (Initialise on a
  protected sheet — exists today) and the confirmation flow
  contract-tested; the live confirmed destructive command is exercised at
  R5.8's gate, cross-referenced here. **The human must acknowledge this
  split in the ADR** (or direct an earlier destructive command).
