## Design decisions (recorded in memra)

- **D-A — Notes, not cell edits.** Each issue becomes an Excel classic cell **note** (`Range.AddComment`) anchored on the `Field` cell (1-based body row from `GanttRowDto.RowNumber`; column by Ordinal header-name lookup mirroring R2.4). Cells are never written or formatted. Add-in-owned notes carry a leading text sentinel `"Gantt Creator validation:"` (`Comment.Author` is read-only, so ownership is tagged by text); only owned notes inside the body are cleared on each run; user notes are never touched. Multiple issues on one cell collapse into one note preserving `Severity → Row → Field → Code` order.
- **D-B — Pure composer.** `ValidationReportComposer.GroupIntoNotes` groups already-sorted issues into `(RowNumber, Field, text)` entries with no COM, so ordering/ownership tagging are unit-tested without Office.
- **D-C — Summary feedback.** Validate shows one concise summary (counts only, no schedule content): `"Validation complete: N error(s), M warning(s) on tblGanttData."` / `"Validation complete: all rows valid."` A failing presenter degrades to no dialog (CA1012-style, identical to `InitialiseSheetCommand`). Success is **not** silent because a validation pass must confirm it ran.

## Exclusions

- No schema change (stays v1); no new column; no `_GanttCreatorConfig` content (notes live on the visible sheet only).
- No scene/rendering, Ribbon beyond the single Data button, PowerPoint, PNG, new NuGet packages.
- No automatic re-validation on edit; only the explicit Validate command (per "only explicit commands rebuild the chart").
- R2.9 style-registry capability gates on `Custom Activity`/`LabelPosition`/`FillColour` remain deferred; R2.6 surfaces the R2.5 issue text verbatim.

## Risk and rollback

- **Comment read API uncertainty** (`Comment.Text` returning current text for ownership detection) — isolated behind `ReadCommentText` seam; the live integration test asserts read-back equals written text. Rollback if false: switch to `comment.Shape.TextFrame.Characters().Text` without changing orchestration.
- **Partial-failure idempotency**: owned notes cleared before new ones written; a mid-write failure leaves stale-owned absent but some new notes missing — next run repairs; never a wrong cell value.
- Rollback: `git revert` of the single commit; Core untouched, pure addition.
