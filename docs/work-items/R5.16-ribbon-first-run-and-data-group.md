# Work item — R5.16 ribbon first-run surface and Data-group consolidation

> **Guide status**: Authored 2026-11-10 (Tier B — binding contract). Depends on
> R1.2 (ribbon shell), R1.5 (ribbon state service), R2.2 (Initialise), R5.3
> WI-E (the add-child planner), R5.4 (ordering commands), R5.13 (group-aware
> row insert), ADR-0050 (coalesced refresh), ADR-0056 (this item's decision
> record). Full design and sketches: `plans/ribbon-ux-redesign-plan.md`.

## Outcome

A workbook with no add-in configuration shows a first-run ribbon: one large
**Initialise sheet** button in a **Get started** group, plus the **Diagnostics**
group. Nothing else is visible. Once the sheet is initialised the button
disappears and the full ribbon appears without a restart.

The **Data** group becomes five large controls: **Fix** (primary Repair
configuration, arrow Validate), **Add activity** (primary As-Planned Activity),
**Add milestone** (primary As-Planned Milestone), **Additional elements**
(primary Delineator), and **Remove**. The **Add child** label and dropdown are
removed; **Demote to child** is the way to make a row a child.

Insertion becomes selection and location aware. A **Critical Interval** attaches
to the nearest eligible parent and is placed inside that parent's child run; the
menu item is disabled only when the table holds no row that can own it. Every
other entity keeps R5.13's group-join when it lands inside a contiguous child
run, and a row that cannot be a child — or whose candidate parent is rejected —
is appended at the end of the table rather than splitting the run.

## Owner rulings (2026-11-10)

1. Insert-type constraints are cell-selection aware; a constraint is shown
   disabled rather than raised as an error window.
2. Only Critical Interval is added as a child by default. Other entities are
   added as parents, except that an entity inserted inside a group joins it
   (the R5.13 rule is retained, not superseded).
3. No separate Add child option; the user demotes a row instead.
4. Diagnostics stays visible on Get started. This overrides the original
   "nothing else, not even disabled" wording for the no-workbook case.
5. Keytips and icons are required; iconoop.com is preferred for icons, with the
   best Microsoft `imageMso` as the fallback. iconoop.com is unreachable with
   the available tooling, so the fallback applies.

## Explicit exclusions

- No workbook-schema change. `ParentId` already exists; the insert writes it.
- No change to `_GanttCreatorConfig` contents or the visible worksheet contract.
- No second helper worksheet, no schedule data on the VeryHidden sheet.
- No renderer change: the scene remains the only positioning authority.
- No new production dependency, Office permission, or signing requirement.
- Accessibility is not a goal of this item beyond the existing keytip,
  screentip, and supertip rules; keytips and icons are.
- iconoop.com icons are not available to this repository's tooling; no attempt
  to add a network dependency for icon assets.

## Design decisions

- **D1 — Three ribbon modes.** `FirstRun`, `NeedsRepair`, `Ready`. A workbook
  that carries `_GanttCreatorConfig` but has lost its table is **Needs repair**,
  not first run; otherwise Initialise refuses and points at a hidden Repair
  command, which is a recovery dead end.
- **D2 — Visibility is fail-closed, enablement stays fail-open.** An unknown
  group id is hidden; an unknown control id remains enabled. Showing an
  unintended control is the failure this item removes.
- **D3 — Diagnostics is visible in every mode.** It is the only exception to
  the first-run surface and is recorded as an owner ruling, not an oversight.
- **D4 — The menu is a projection.** Item ids are `GanttEntityType` names and
  item labels come from `EntityTypeCatalog`; the union of the three entity
  menus must equal the catalogue partition.
- **D5 — Critical Interval is data-gated, not selection-gated.** The item is
  enabled when the table contains an eligible parent, because the owner's rule
  is "refuse only when none exists".
- **D6 — Critical Interval attaches to the nearest eligible parent.** Search
  upward from the selection first, then downward; place the row after that
  parent's last child so the outline stays valid; refuse when none exists.
  Never create a parent as a side effect.
- **D7 — R5.13 is retained.** Every child-capable type still joins the group it
  is inserted into; the candidate is now validated through `AddChildPlanner`.
- **D8 — Rows that cannot be children append at the end.** Spacer, splitter, and
  any planner-rejected candidate are appended as the last body row, which is
  always possible and cannot split a child run.

## Acceptance tests

Automated (AddIn):

- `IsVisible` true for Get started in `FirstRun` only; true for Diagnostics in
  every mode; false for every other group in `FirstRun`.
- Every group declares `getVisible`; a document missing it fails the validator
  (**positive test**).
- `grpGetStarted` contains exactly one large `btnInitialiseSheet`.
- The Data group contains exactly the four split buttons and `btnRemove`;
  `ddnAddChild` is absent.
- Each split button has one primary button and one menu; the primary
  `onAction` is the declared default.
- The three entity menus partition `EntityTypeCatalog` exactly, with no
  duplicate type.
- `GetEntityMenuLabel` returns the catalogue `DisplayName`, and an empty string
  for an unknown id (**positive test**).
- `OnAddEntityClick` routes every menu id to `AddRowCommand.RunForExcel`.
- Keytips stay unique and 1–3 characters; label-or-`getLabel` coverage passes,
  and a button with neither fails (**positive test**).
- `SheetInitialised` is false when the table read fails with
  `NoActiveWorkbook` (**positive test** on the old expression).
- Critical Interval is disabled for a table with no eligible parent and enabled
  for a table with one (**positive test**); an unreadable table keeps the
  previous value.

Automated (Core and Office):

- `IsEligibleParent` is false for a leaf type, a child parent, and a parent at
  seven children; true for an activity with room.
- `Evaluate` returns each typed refusal with a positive test per branch.
- Critical Interval attaches to the selected activity, or to the nearest
  eligible parent above/below, and lands inside that parent's child run.
- No eligible parent anywhere → `CriticalIntervalRequiresParent` and the body
  row count is unchanged (refusal precedes the insert).
- R5.13 group-join tests keep passing unchanged.
- A milestone at capacity, a spacer, and a splitter inside a group are appended
  as the last body row and the child run is untouched.

Office host gate (**Required**, owed as of `277d7c6`): run
`pwsh ./scripts/verify-office.ps1` first, then walk the procedure below in the
live host. Each step states what must be seen; a step that produces anything
else is a defect, not a variant. Record the outcome against this section.

**Live evidence so far (owner, 2026-11-10).** State 1 is **observed**: with no
sheet initialised the tab shows **Get started** and **Diagnostics** and nothing
else, and the owner reports "the ribbon buttons work as intended". State 2's
swap and the menu/gate/insertion passes below are therefore the outstanding
half, and they must be walked against the build that contains `0e2aad0`.

**State 1 — first run.** Open Excel with a blank workbook (no
`_GanttCreatorConfig`). The Gantt Creator tab must show exactly two groups:
**Get started** with one large **Initialise sheet** button (keytip `I`), and
**Diagnostics** with its two buttons. No Data, Ordering, Outline, Labels,
Style and Theme, Plot Area, Plot Time Scale, Plot Size, or Gantt Creator group
may be visible, and no disabled control may appear anywhere.

**State 2 — ready.** Press **Initialise sheet**. Without restarting Excel the
tab must swap: **Get started** disappears, all nine other groups appear, and
the Data group shows five large controls — **Fix**, **Add activity**,
**Add milestone**, **Additional elements**, **Remove** — each rendering a
glyph. Hover each one to confirm the screentip and supertip text, and confirm
the keytips `R`, `AA`, `AM`, `AD`, `X` reach the primary buttons.

**State 3 — needs repair.** On the now-initialised workbook, rename or delete
the `tblGanttData` table but leave `_GanttCreatorConfig` in place, then
refresh the ribbon. The tab must show the full surface with table-dependent
controls disabled and **Fix** enabled — never the first-run surface, and never
an **Initialise sheet** button that refuses with "use Repair configuration".
Press **Fix** and confirm the configuration is repaired and the table returns.

**Menus.** Open each arrow and add one row per item, confirming the `Type`
column receives exactly the named type: activity arrow (9 items), milestone
arrow (5), elements arrow (3). Confirm **Add activity** alone adds
`As-Planned Activity`, **Add milestone** alone adds `As-Planned Milestone`, and
**Additional elements** alone adds `Delineator`. Confirm the Add child dropdown
is absent and that each menu item's keytip is unique.

**Fix.** On a deliberately damaged configuration, the primary **Fix** button
repairs; the arrow's **Validate** only reports and changes no schedule data.

**Critical Interval gate.** On a table holding at least one activity, open the
activity arrow with a milestone cell selected: `Add a Critical Interval` must
be **enabled** (the nearest activity above/below receives it), and pressing it
must insert a `CriticalInterval` row inside that activity's child run. On a
table with no activity at all (milestones only), the item must be **disabled**
and greyed — visible, not hidden. Confirm the disabled state is not stale after
adding an activity and refreshing.

**Insertion rules.** With a spacer selected inside a contiguous child run, add
a spacer from the elements arrow: it must land as the **last body row** and the
existing group must remain one intact group. Add a second child to an activity
that already has seven children: the row must be appended, not written as an
eighth child.

**Failure to record.** A group that stays visible in the wrong state, a
`getVisible`/`getEnabled` result that does not refresh after a change, a menu
item that adds the wrong `Type`, or a blank/missing glyph is a stop condition:
record the state, the control id, and the observed behaviour before changing
any code.

## Risk and rollback

- The three-state model is the recovery guard for a workbook that has config
  but no table. Rolling it back re-creates the dead end, so a partial rollback
  must keep **Needs repair**.
- Removing Add child removes the only command-scoped child path. The planner
  stays, and the inserter must route through it, or hierarchy validation is
  silently weakened.
- Split buttons and group visibility are XML-surface changes; they are proven
  in the live host, not by XML tests alone.
- Rollback is per commit: the visibility slice, the Data-group slice, the gating
  slice, and the insertion slice are independently revertible.

## Stop conditions

- The nearest-parent rule produces a placement the owner does not accept, such
  as the row moving into the parent's child run.
- A new production dependency, Office permission, or schema change becomes
  necessary.
- The live host shows a split-button, menu-item `getEnabled`, or group
  `getVisible` limitation the customUI schema does not describe.
- The owner asks to keep Add child after all, which reverses owner ruling 3.

## Notes during implementation

- The `splitButton` element has no primary-action semantics of its own; the
  `getEnabled`/`getAction` surface belongs on the inner button.
- `getVisible` on a group is honoured by the host only when the attribute is on
  the group element, not on a child control.
- Menu-item `getEnabled` is cached by the host; prove the selection-independent
  gate in the live host rather than assuming the invalidate is unnecessary.
