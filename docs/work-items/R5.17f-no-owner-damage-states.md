# Work item — R5.17f Damage states with no repair owner

- **Status:** Slices 1 and 2 landed — finding 4 (schedule data on the
  configuration worksheet) and finding 5 (the data table outside the labelled
  Gantt worksheet) now have producers, positive tests, and negative controls.
  Findings 1, 2, 3 and 6 are unchanged; see the implementation records below.
- **Parent:** [R5.17](R5.17-repair-rebuilds-a-missing-data-table.md), sections 11.2–11.3
- **Why separate:** the R5.17a–d family repairs containers and structure. These
  states survive a full refresh, survive Fix, and in two cases are invisible to
  both. Each needs an integrity finding before it can have a repair, so they are
  not recovery-path additions.

## Findings

| # | State | Current behaviour | Why a refresh cannot fix it | Proposed owner |
|---|---|---|---|---|
| 1 | An owned shape whose alternative-text tag was removed or renamed | [`ListOwned`](../../src/GanttCreator.Office/ExcelShapeWriter.cs) never sees it; no refresh or Fix path deletes it | Reconciliation only knows tagged shapes, and deleting an untagged shape is unsafe without an identity proof | Inventory + report; confirm-required cleanup of names that could be ours (L18's over-long name can leave one) |
| 2 | Table shifted off the contract origin (rows inserted above row 3, or the table moved right) | Reader finds the table by name; refresh measures the live table but the title column, plot anchor, and band constants assume the contract origin, so it can render wrong or refuse | The scene layout is derived from a fixed origin; moving it is a schema question, not a presentation one | Integrity finding + manual move route; derive the anchor from the live table before automating |
| 3 | Extra user columns beside the schema columns | R5.17a refuses structure repair when extras exist, which is correct; the plot anchor is derived from schema width | The anchor, title column, and export width all assume exactly the schema columns | Integrity finding; derive anchor and title column from the live table's first/last schema column |
| 4 | Schedule data on `_GanttCreatorConfig` | The catalogue reader validates known tables and does not report unrelated cells | Refresh reads the configuration, not arbitrary cells on it | Detect in the integrity checker; refuse and report, never silently delete user data |
| 5 | `tblGanttData` on a worksheet without the standard label | Reader finds it by name and renders there; no finding | Recovery targets the labelled sheet, so the table is never associated with the chart layout | Integrity finding; offer to rename the sheet or the table after proving identity (same proof as ADR-0057 amendment 4) |
| 6 | A copied Gantt sheet whose table Excel renamed | The copy is ignored; only `tblGanttData` is read | There is no identity for a second chart | Multi-chart gap; blocked by [R5.17e](R5.17e-single-chart-locator-seam.md) and the ADR it prepares |

## Acceptance tests

- Every new finding has a positive test that constructs the damaged state and
  asserts the finding is raised, and a negative test for the healthy workbook.
- A confirm-required cleanup of an orphan shape names the shape and deletes
  nothing until the user confirms.
- The four refresh-boundary tests in R5.17 section 11.4 ship with the finding
  that owns each one.
- No path deletes user data without confirmation.

## Implementation record — slice 1 (finding 4)

Landed:

- [`ExcelConfigIntegrityChecker`](../../src/GanttCreator.Office/ExcelConfigIntegrityChecker.cs)
  raises `ConfigIntegrityFindingKind.ScheduleDataOnConfig` for every table on the
  configuration worksheet that is not one of `GanttCatalogues.ContractTableNames`,
  naming the table in the finding. The kind and its `Refuse` classification already
  existed and had **no producer anywhere**, so this slice is what makes that arm
  reachable rather than a new concept.
- The rule is **table-level, not cell-level**: a stray cell is a note, a table is
  data. A cell-level rule would report every scratch pad on the hidden sheet as
  damage, and the work item's own refusal ("never silently delete user data")
  already forbids repairing either.
- Comparison against the contract table names is case-insensitive, because Excel
  treats table names that way — a catalogue renamed to different case is still the
  catalogue, not schedule data.

Tests:

- `Schedule_data_on_the_configuration_sheet_is_reported_and_refused` — the positive
  case, asserting the finding's `TableName` and that
  `ConfigIntegrityPlan.Classify` returns `Refuse` (the arm's whole purpose).
- `The_catalogue_tables_on_the_configuration_sheet_are_not_schedule_data` — the
  healthy-workbook negative control.
- `One_foreign_table_among_the_catalogues_is_still_reported` — a copied schedule
  lands beside the catalogues, so the scan must not stop at the first contract name.

Interaction recorded, not fixed here: a `tblGanttData` on the configuration
worksheet is also the first table `TryFindGanttTable` meets, so the checker's later
anchor and TypeOptions checks run against the configuration sheet rather than the
Gantt sheet. The finding is raised before that scan and is a `Refuse`, so Fix acts
on nothing; the misleading detail text is a follow-up for the finding that owns the
"table on the wrong sheet" state (finding 5), which is where the target-sheet
question belongs.

## Implementation record — slice 2 (finding 5)

Landed:

- `ConfigIntegrityFindingKind.DataTableOnUnexpectedSheet` is a new finding kind.
  It is raised when the data-table walk finds `tblGanttData` on a worksheet whose
  name is not `GanttWorkbookContract.GanttSheetLabel` (case-insensitive, through
  the contract predicate). The finding names the table in `TableName` and the
  worksheet in `Detail`.
- Classification is **`Refuse`**. Finding 5's proposed owner mentions an offer to
  rename the sheet or the table; a rename is a user-visible identity change that
  can break formulas and other consumers, so this slice reports and changes
  nothing. Fix refuses the whole plan, which is how `ScheduleDataOnConfig` is
  already treated.
- The configuration worksheet is excluded from the new finding: a `tblGanttData`
  there is already reported as `ScheduleDataOnConfig`, and one table must not
  produce two statements about what is wrong with it.
- The sheet-scoped plot-anchor check now runs **only** on the labelled worksheet.
  This closes the interaction recorded under slice 1: the check used to run
  against whichever sheet held the table, so a mislocated table produced a
  "missing anchor" disagreement — and
  [`ExcelPlotAnchorRepairer`](../../src/GanttCreator.Office/ExcelPlotAnchorRepairer.cs)
  writes the name onto that same sheet (`gantt.Names.Add`), so an `AutoRepair`
  finding could have created a defined name on a sheet no other path owns. The
  workbook-scoped TypeOptions check still runs whenever a table was found
  anywhere, because it does not depend on the sheet.

Behaviour change recorded: a workbook whose chart worksheet was renamed now
produces `DataTableOnUnexpectedSheet` and Fix refuses everything, where before it
could auto-repair an anchor name on that sheet. The render is unchanged — the
reader still follows the table by name, so the chart keeps drawing in both
versions.

Tests:

- `A_data_table_on_a_worksheet_without_the_gantt_label_is_reported_and_refused` —
  positive case on a sheet named `Scratch`: asserts the table name, the worksheet
  name in the detail, the `Refuse` classification, and that no anchor
  disagreement is invented.
- `A_data_table_on_the_labelled_gantt_worksheet_is_not_mislocated` — the healthy
  negative control.
- `A_data_table_on_the_configuration_sheet_is_not_also_mislocated` — one table,
  one finding, and no anchor check against the configuration sheet.
- `Classify_maps_each_damage_class` gains the new kind's `Refuse` row.

Fixture defect fixed in the same commit: `ConfigIntegrityCheckerDepthTests` named
its Gantt worksheet `Gantt`, which is not the contract label and is the very
state this finding reports. It now uses
`GanttWorkbookContract.GanttSheetLabel`, so every existing depth test models a
labelled workbook and the new reassignment is the deliberate exception.

## Explicit exclusions

- No new helper sheet, and no schedule data moved to the configuration sheet to
  make it detectable.
- No automatic deletion of untagged shapes.
- No multi-chart support; item 6 is recorded to keep it out of this item.
