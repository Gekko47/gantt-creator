## Scope

- The full-suite run on every matrix row (R10.1's reference machines):
  each gate's result recorded; failures block.
- The signed evidence manifest (format + collection + signing step).
- A runbook entry for the invocation order (what runs where — local

- `docs/REPO-MAP.md`, `docs/STATUS.md`, status line.

## Exclusions

- No new tests (the suite exists; this row runs it completely); no
  gate weakening to achieve green (a failure is a defect); no
  unsupported-machine runs counted.

## Design decisions (behavioural)

- **D1 — Completeness is the matrix × gates product.** Every matrix
  row × every gate either returns a recorded result or the row is
  marked untested **in the manifest** (never omitted silently).
- **D2 — The manifest is signed and checksum-linked.** Each gate
  result links to its artifact/report; the manifest's integrity is
  signed/checksum-rooted so R10.8 can verify it later.
- **D3 — Failures block, always.** A red gate stops the run; the
  two-attempt/route-back discipline applies (no waivers in this row).

## Acceptance tests

- **Automated + Office (Required)** — the complete run: all gates
  green on every supported matrix row; the manifest signed and
  complete; host builds recorded per row.

## Stop conditions (item-specific)

- A gate is missing → stop (build it in its owning row first).
- The manifest cannot be signed → stop; R10.8's integrity check
  depends on it.

## Risk and rollback

Main risk: run-time sprawl (many machines × gates) — the manifest's
completeness table keeps it auditable. Rollback: `git revert`.
