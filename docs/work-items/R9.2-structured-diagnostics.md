## Design decisions (behavioural)

- **D1 — One record per failure, correlated.** Every boundary
  failure writes exactly one structured record carrying the operation
  ID shown (or referenced) in the user message; the correlation is
  pinned by test.
- **D2 — Redaction is verified against real records.** Tests build
  real-shaped log records from actual flows (fixtures of genuine
  message shapes) and assert no schedule content/cell values escape —
  not merely unit-testing `Redactor` in isolation (the R0.8 gap).
- **D3 — Rotation keeps the newest, bounds the disk.** The landed
  rotation policy is exercised end-to-end (size-based, capped count);
  the row verifies, never re-specifies.

## Acceptance tests

- **Automated**: correlation pin (message↔record via operation ID);
  redaction against real-shaped records (**positive tests** with
  schedule-content-looking inputs); rotation bounds; stage/build
  fields present.
- **Office host (Required)** — live: provoke an error; inspect the
  user message (concise, actionable) and the local log record
  (structured, content-free); record host builds.
