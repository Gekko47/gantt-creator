## Design decisions (behavioural)

- **D1 — Explicit local defaults, never Office themes.** Every value
  is an explicit token value stored on `_GanttCreatorConfig`; the
  dialog never binds to Office theme colours; the feature works fully
  offline (offline-dependency tests pin no network/theme access).
- **D2 — Range-validated writes.** Each edit validates against the
  token's range (R2.7) before writing; out-of-range input is refused
  with the token's range in the message (**positive test**); the
  contrast warning (WCAG G18 4.5:1 luminance, computed in Core `ThemeContrast`)
  fires as a non-blocking dialog warning for difficult text/fill pairs and never
  silently replaces the entered colour (entity-guide rule). A separate red-green
  hue advisory warns (non-blocking) since contrast math does not model hue
  perception (Microsoft `Accessible text requirements`). Shipped green/blue/red
  defaults are grandfathered: no warning on open, warning only on a user edit
  that creates a violation.
- **D3 — Round-trip + repair integration.** Values round-trip through
  save/reopen (R2.7 acceptance reused); damaged values surface through
  R2.10's integrity findings, not ad-hoc reads.
- **D4 — Live comparison target.** The Office gate edits
  colours/heights/diamond size and compares the rendered Excel output
  with the approved token values (the entity-guide tables are the
  specification).
