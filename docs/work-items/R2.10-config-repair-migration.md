## Design decisions (ADR-0009 content; the human approves the boundary
before code)

- **D1 — The confirmation boundary (closes L5).** *Auto-repair only what
  is add-in-owned and user-data-loss-free; confirm anything that touches
  user-authored rows; refuse the rest.* Classification:
  - **Auto-repair**: wrong visibility (set `xlSheetVeryHidden`);
    missing/corrupt `tblGanttTypes` or `tblGanttMetrics` (regenerate
    from code catalogues); stale catalogue hash (regenerate built-ins,
    preserve user rows); plot-anchor disagreement (re-derive from the
    live table per R2.2 D1); missing `TypeOptions` name (re-materialise
    per R2.9).
  - **Confirm-required**: migration from an older schema version
    (regenerates built-ins; user styles/settings preserved; stored
    version bumps); missing/corrupt `tblGanttStyles` with possible user
    rows (regeneration restores built-ins; user customs are
    unrecoverable — the confirmation names this); identity repair in
    `tblGanttData` (duplicate-ID later occurrences get new generated IDs
    per R2.5's first-occurrence-canonical rule; malformed/missing IDs
    regenerate — user data cells change).
  - **Refuse**: schema version **newer** than the running add-in
    (message: update the add-in); a second helper sheet or schedule data
    found on `_GanttCreatorConfig` (never auto-delete; a human decides);
    workbook protection blocking repair.
- **D2 — One command, plan-then-act.** Ribbon **Repair configuration**
  runs `Check` → builds the plan (pure Core classification) → auto items
  execute inside one ordered mutation (R2.2 D4 discipline) → confirm
  items each get one R2.7a-style confirmation (counts only, no schedule
  content) → confirmed items execute → one summary (counts of repaired /
  confirmed-skipped / refused). Cancel stops before any mutation.
- **D3 — Migration preserves, never drops.** Older-version migration
  regenerates built-in catalogue rows, preserves every parseable user
  style row and every present settings value (R2.7 D4), bumps the stored
  version, and re-hashes. A user row that fails to parse is quarantined
  in the finding list — never silently dropped (checklist D).
- **D4 — Detection points.** `InitialiseSheetCommand`'s
  `ConfigSheetExists` refusal message points to Repair configuration
  (message change only; behaviour unchanged). Full detection also runs
  inside the command. No open-time hooks (exclusions).
- **D5 — Visible-sheet rule is asserted, not assumed.** Every repair
  outcome test asserts: still exactly one visible Gantt sheet; config
  sheet VeryHidden; no new sheet ever created.

## Stop conditions (item-specific)

- ADR-0009 unapproved → no code.
- Any repair path would delete user rows, drop user styles, create a
  sheet, or leave the config sheet visible → invariant violation; stop.
- A damage class appears that D1 does not classify → default the new
  finding kind to **Refuse** and report; extending the boundary needs an
  ADR amendment, not improvisation.
- The same failure persists after two evidence-led fixes → stop per the
  bounded retry rule.

## Risk and rollback

Main risks: (a) repair itself damaging a workbook — mitigated by
plan-then-act, confirmation for user-data paths, mutation-set tests, and
visible-sheet assertions on every path; (b) migration misclassifying a
user style row as built-in — mitigated by the R2.7 D4 preservation
contract and quarantine positive tests; (c) COM state left changed —
`try/finally` save/restore per architecture rules. Rollback: `git
revert` of the single commit; the command is additive except the one
refusal-message text change.
