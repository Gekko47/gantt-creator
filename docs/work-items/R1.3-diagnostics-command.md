# Work item — R1.3

## Outcome

A Diagnostics button on the Gantt Creator ribbon invokes a `DiagnosticsService`
singleton that gathers four identifiers (add-in assembly version, Excel version,
process bitness, XLL path), writes a diagnostic record to the rolling log, and
shows a Windows TaskDialog with a **clickable hyperlink** that opens the active
log file. The service is usable project-wide for future diagnostics.

### Decision recorded here (to be written as ADR-0006)

- TaskDialog (comctl32.dll) with `TDF_ENABLE_HYPERLINKS` for the diagnostics
  display; no custom WinForms dialog.
- Dialog owner: desktop window (`IntPtr.Zero` / `GetDesktopWindow()`); no Excel
  owner — recorded as a known entity.
- Hyperlink opens the active log **file** (not the folder).
- `DiagnosticsService` is a singleton per Excel session; `DiagnosticsService.Instance`
  is set once at first use and reset by `AddInHost.AutoClose`.
- Identifiers: add-in version, Excel version, process bitness, XLL path — four
  identifiers confirmed adequate at this stage.
- `IRollingLog.LogFilePath` added to Core (read-only, informational) so the
  AddIn layer can display the active log path without owning the log.

## Risk and rollback

Risk: TaskDialog hyperlink handling via P/Invoke may behave differently than
expected on some Windows configurations (e.g., the `TDN_HYPERLINK` notification
may not fire if the hyperlink parsing fails). Mitigation: the hyperlink opens
the file via `Process.Start(new ProcessStartInfo(path) { UseShellExecute = true })`;
a failure to open the file is non-fatal (the dialog already displayed). Rollback:
revert the R1.3 implementation commits. This removes `DiagnosticsService.cs`,
`DiagnosticsService.TaskDialog.cs`, the new tests, the `GanttRibbon` callback,
the Ribbon button, the `IRollingLog.LogFilePath` property, the
`RibbonResources.resx` label, the `STATUS.md` pointer, and the ADR index entry;
the `RollingLog.cs` `LogFilePath` implementation is also reverted.

## Notes during implementation

- `IRollingLog.LogFilePath` is a Core-only addition (read-only property returning
  the full path to the active log file). The AddIn already references Core, so
  the AddIn layer can read it without any new dependency.
- `DiagnosticsService` takes the `IRollingLog` via `SetLog(IRollingLog)` so the
  service does not own the log lifetime (the log is owned by `AddInHost`). The
  service is a singleton; `Instance` is null until first use, and `AddInHost.AutoClose`
  calls `DiagnosticsService.Reset()` to clear the singleton and the injected log
  reference for the next Excel session.
- TaskDialog P/Invoke: `TaskDialog` is in `comctl32.dll`; the hyperlink flag is
  `TDF_ENABLE_HYPERLINKS` (0x00000020); the hyperlink notification is
  `TDN_HYPERLINK` (0xFFFFFD9F). The dialog owner is the desktop window
  (`GetDesktopWindow()`), with `IntPtr.Zero` as a fallback.
- The `OnDiagnosticsClick` callback signature is `(IRibbonControl control)`,
  matching the Excel-DNA `onAction` contract already verified for `OnLoad` in
  R1.2.
- Office gate (F5, click Diagnostics, TaskDialog with hyperlink): **Not run by
  the agent** — requires Visual Studio against desktop Excel.
