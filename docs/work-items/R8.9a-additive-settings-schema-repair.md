# R8.9a — Additive settings schema repair

- **Status:** Complete (2026-11-26)
- **Implements:** [ADR-0073](../adr/0073-additive-settings-schema-repair.md)
- **Depends on:** ADR-0029 (schema-version policy), ADR-0011 (safe repair)
- **Owner decision:** 2026-11-26 — schema 29 is approved, and Initialise is not
  reachable in the current UI flow, so a version-28 workbook must repair in place.

## Outcome

A schema-28 workbook opens, appends the two version-29 settings rows, keeps every
present value, keeps the user's `tblGanttMetrics` and `tblGanttStyles` edits, and
keeps its workbook ID. The user does not run Initialise and sees no data loss.

## Scope

- `tblGanttSettings` gains `SizeWidthCm` and `SizeHeightCm`, appended after the
  existing keys so a version-28 list is an exact prefix.
- `CurrentSchemaVersion` moves 28 to 29.
- A pure `AdditiveSchemaUpgrade.TryPlan` decides whether the bump is a one-step,
  settings-only append. A reorder, extra key, missing middle key, empty set, newer
  workbook, or multi-version gap is refused.
- `SchemaVersionOlderAdditive` is a new `AutoRepair` finding. Structural
  `SchemaVersionOlder` stays `ConfirmRequired`.
- The narrow writer appends defaults and rewrites only `tblGanttSettings` and
  `tblGanttConfig`. The full catalogue writer is never used for this path.
- `SchemaVersionMismatchMessage` names Repair, not Initialise.

Out of scope: the custom-width UI and geometry. Those consume `SizeWidthCm` in the
following row; `SizeHeightCm` is a measured mirror there, not an input.

## Decisions

| # | Decision | Rationale |
| --- | --- | --- |
| D1 | One-step, settings-only bumps repair in place. | The change is provably append-only; the alternative strands the workbook. |
| D2 | Detection requires an exact prefix and a non-empty stored set. | A count-only check would accept a displaced middle key. |
| D3 | Multi-version gaps are refused. | A settings prefix cannot prove that types or metrics did not also change. |
| D4 | The repair writes settings and config only. | The full writer resets `tblGanttMetrics` to code defaults. |
| D5 | The config version and hash are written last and together. | A workbook is never stamped 29 while its settings table is short. |
| D6 | The second run writes nothing. | Idempotence is part of the contract, not an accident. |
| D7 | The structural message names Repair. | Initialise is unreachable; the reachable command is Repair. |

## Acceptance

- `AdditiveSchemaUpgradeTests` accepts a prefix and refuses `NotOlder`, `Newer`,
  `MultiVersionGap`, `ExtraKey`, `EmptyKeySet` and `KeyOrderMismatch`, each with a
  positive test.
- `ConfigIntegrityCheckerTests` reports `SchemaVersionOlderAdditive` for a stored
  version plus a prefix, before the generic hash mapping.
- `ConfigRepairerTests` routes the additive finding to `UpgradeAdditiveSchema` and
  never calls the full writer.
- `ConfigCatalogueWriterTests` proves the narrow repair appends the rows, preserves
  metrics and styles, keeps the workbook ID, and is idempotent.
- `GanttSchemaVersionTests` pins 29; `GanttConfigCatalogueTests` pins the 32-key
  catalogue; `SchemaVersionMismatchMessageTests` names Repair and rejects
  Initialise.
- Non-Office gate PASS: Core 2,302; Office contract 1,767; AddIn 980; Architecture
  142; Raster 127; non-live integration 39.
