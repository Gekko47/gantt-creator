# Work item — R5.22

## Outcome

The analyst can hide every user-visible column of `tblGanttData` and work with the chart
alone, and a single split-button control toggles all six columns between visible and hidden
while its menu keeps the per-column toggles. Zero visible columns is a persisted, repaired,
reopened and exported state, not an error.

## Decisions and guard rulings

| Guard | Verdict | Reason |
|---|---|---|
| `ColumnVisibilityRefusal.LastVisibleColumn` and `AnyAuthoringColumnVisible` | **Drop** | The owner reversed the "one authoring column must stay visible" product rule. Hiding is presentation only; the add-in still reads and writes every cell. |
| Last-column warning branch in `RibbonStateService` | **Drop** | Unreachable once the Core refusal is gone; no dead validator. |
| `ExcelPanelGridMeasurement.Measure` empty-list refusal | **Change** | Zero columns is a real measurement of a fully hidden table. Keep the no-workbook, table-missing and invalid-measurement refusals. |
| `PanelCellGridRefusal.NoColumns` | **Drop** | Zero columns is legal geometry; remove the member and its positive test rather than leave an unreachable refusal. |
| `PanelCellGridRefusal.NonPositiveWidth` | **Keep** | A hidden column passed to the grid is a caller error. Dropping this would treat a `0` width as a real column and move the plot. |
| `NullRequest`, `NoRows`, `NullPanelGrid`, row/cell count checks | **Keep** | Zero/zero still satisfies the cardinality checks; these catch real caller faults. |
| Schema-owned engine visibility in the restorer and recovery | **Keep** | Only the six user columns are the user's choice. |
| `RibbonStateService.MeasuredColumns()` schema-only list | **Change** | It already breaks the Width readout after a single hide. The stored setting must be the authority, matching the Refresh. |
| `RibbonStateService` width computed before the hidden set loads | **Change** | Compute with the candidate hidden set and invalidate `lblPlotWidth`. |
| Selection-gated row commands | **Keep** | A hidden table is still logically selected; the probe kept `B2`. Record the behaviour, do not invent a new selection rule. |
| Columns control gating | **Keep and move to the split button** | Gated on workbook + initialised + Gantt sheet only, so it is always available to restore a fully hidden table. |

## Probe evidence (2026-11-17, Excel 16.0)

`pwsh -NoProfile -File scripts/probe-hide-all-columns.ps1 -Build` opened a synthetic
schema-26 workbook in a private, invisible Excel instance, hid all six user columns by header
name, and read the live host back. The workbook was closed without saving.

- All six columns reported `Hidden = true`.
- Every hidden column reported `Width = 0`.
- The header and body ranges both reported `Left = 14.25`; the origin stayed readable.
- The plot anchor (column T, the 18-column table's next column) moved to `Left = 14.25`, equal
  to the origin, and remained visible at `Width = 48`.
- `DataBodyRange` still existed with 2 rows.
- The active cell stayed on `B2`, the now-hidden cell inside the table; the selection did not
  move to a visible column.
- Freeze panes were `False` and are not exercised by this probe; the Office gate records the
  user-frozen-pane case as a deferred observation, not a supported contract.

## Risk and rollback

The highest risk is the live render path silently depending on a positive panel width in a
place the probe did not cover. The two known places are the title width (the measured sum
becomes zero) and the frame/title geometry; both get facts before the ribbon change lands. A
second risk is a persisted setting that disagrees with the sheet after a refused write; the
compensation path and its fact are part of this work item. Rollback is a normal revert of the
commits; no workbook migration is involved because the schema version and the `HiddenColumns`
key are unchanged.

## Notes during implementation

- The probe's first active-cell attempt selected `A2` because `ListColumn.Index` is
  table-relative; [`probe-hide-all-columns.ps1`](../../scripts/probe-hide-all-columns.ps1) now
  uses `ListColumn.Range.Column`, and the verified run selected and retained `B2`.
- The probe's first synthetic rows mixed `DateTime` and string cells, which PowerShell inferred
  as a `string[]`; the fixture uses all-string cells because it measures visibility and
  geometry, not date typing.
- The live title spans the sum of the measured columns
  ([`GanttRefreshOrchestrator`](../../src/GanttCreator.Office/GanttRefreshOrchestrator.cs)).
  The first cut widened it to the scene plot's right edge at zero columns; the owner observed
  that this overlaps the chart on the live sheet and ruled that the title must be **disabled**
  while no column is visible and re-enabled when any column is shown. The fix now omits the
  title request at zero columns (so the reconciler deletes the owned `ChartTitle`) and restores
  it on the next refresh that finds a visible column. The export title is unaffected.
- The current frame closes on `PanelLeftPt` (the leading gutter's outer edge), which is the
  2026-11-16 owner ruling in the code. ADR-0061 D9 and the entity guide's frame sentence still
  say the frame closes on the table's first visible column; this work item records that drift
  instead of silently changing the geometry.
- Initialise alignment needed no second settings write. A fresh workbook's catalogue write
  already leaves `HiddenColumns` blank, which is the "nothing hidden" presentation the fresh
  table shows. An adopted existing configuration goes through Repair, which re-applies the
  stored set after the table is rebuilt; adding a second write in Initialise would risk a
  half-written configuration for a state the catalogue default already expresses.
- The live all-hidden fact first failed on `DataBodyRange is not null`, and the failure was the
  test's premise, not the feature: a freshly initialised table has a header and no body rows, so
  `DataBodyRange` is null before any hiding happens (the same fact
  `PanelGridMeasurementIntegrationTests` records). The fact now seeds one body row, which is the
  shape the probe exercised, and asserts the body survives the all-hidden apply.
- The reusable seam for the export obligation is
  [`GanttColumnVisibility.VisibleColumns`](../../src/GanttCreator.Core/GanttColumnVisibility.cs),
  which the live measured-column list already consumes through
  [`ExcelSceneBuildRequestFactory.MeasuredColumnsFor`](../../src/GanttCreator.Office/ExcelSceneBuildRequestFactory.cs).
  A future export builder must call the same helper, not restate the filter.
- **Office gate run (2026-11-17, Excel 16.0.20527.20196, x64, `O365HomePremRetail`): 66/69.**
  Both new column-visibility facts passed. The three failures were R5.21 debt, not R5.22:
  `TableGridBorderIntegrationTests` asserted the old five visible columns where schema 26 has
  six (a stale literal), and `Read_returns_locale_invariant_dtos_under_gb_and_us_display_formats`
  compared two `#########` strings because R5.21's 60 px default clips a ten-character date.
  Both are corrected in the follow-up test-only commit, and the build named here is the one the
  human pass must use. The COM-proxy ratchet read **41 forced kills against a ceiling of 38**,
  which is the documented pre-existing per-body chain (R5.20 D4); the ceiling is deliberately
  not raised. The rendered split button, the chart-alone Refresh, close/reopen, Repair and the
  frozen-pane observation remain owed to the human pass.
