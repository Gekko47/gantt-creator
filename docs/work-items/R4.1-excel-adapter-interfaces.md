- **Ownership tag.** Per the R3.14 decision (work-item Notes, 2026-09-26)
  the scene's ownership metadata is `OwnerId` (kind, value, `OwnedRows`)
  plus the role-derived `PrimitiveId` from `ScenePrimitive.CreateId`;
  the literal `GanttCreator.` prefix is written by *this row's* shape
  port, so D2's tag member is defined here, not in Core.
- **PROBED 2026-09-27 against the installed PIA — the PIA members this row
  needed are now facts, not unknowns.** Reflection over
  `Microsoft.Office.Interop.Excel` (ExcelDna.Interop 16.0.0, ADR-0004) and
  cross-checked against Microsoft Learn:
  - **There is no `Shape.Tag` member.** Enumerating all 67 properties of
    `Microsoft.Office.Interop.Excel.Shape` returns no `Tag`; the MS Learn
    Excel `Shape` property list agrees. `Tag` is a *PowerPoint* `Shape`
    member. Excel's writable string carriers are `Name`, `Title`,
    `AlternativeText`, `OnAction`. This falsified D2 as originally written
    and is resolved by [ADR-0019](../adr/0019-shape-ownership-carrier.md);
    the carrier is `AlternativeText` and the tag is the bounded
    `GanttCreator.Owned.v1:{hash}`. **The `GanttCreator.` prefix
    requirement itself is unchanged** — only the member that carries it.
  - **Shape creation.** `Shapes.AddShape(MsoAutoShapeType, Single L/T/W/H)`,
    `Shapes.AddLine(Single BeginX, BeginY, EndX, EndY)`,
    `Shapes.AddTextbox(MsoTextOrientation, Single L/T/W/H)`, all returning
    `Shape`. Every geometry parameter is already `Single`, which is
    D3's boundary observed from the host side. `Shapes.AddFreeform` does
    **not** exist; freeform goes through
    `Shapes.BuildFreeform(MsoEditingType, Single X1, Single Y1)` →
    `FreeformBuilder.AddNodes(...)` / `ConvertToShape()` (R4.5's probe).
  - **`AddLine` takes absolute endpoints.** This partially answers
    R4.3's open line-kind question: a scene line's exact `From`/`To` is
    expressible at creation. `Shape` itself exposes only
    `Left`/`Top`/`Width`/`Height` (all read/write `Single`);
    `ConnectorFormat` carries connection *sites*, not endpoint
    coordinates. R4.3 still owns the line-vs-connector choice.
  - **Z-order is a method, not a settable index.** `Shape.ZOrder` is
    `ZOrder(MsoZOrderCmd)` returning `Void`; `Shape.ZOrderPosition` is
    read-only `Int32`. The port therefore exposes front/back application,
    never index assignment.
  - **Grouping.** `ShapeRange.Group()` returns `Shape`;
    `ShapeRange` also carries `Ungroup`, `Duplicate`, `ZOrder`,
    `Delete`, and `Select`.
  - **`Shapes.Item` is a COM indexed property** (`Item(Object Index)`),
    so it needs an `internal virtual` seam like `GetSheetAt` — CS0855.
  - **Remaining unprobed:** the fill/stroke/pattern members (R4.6's
    obligation, not this row's) and whether `AlternativeText` truncates
    the tag on a live host. The latter is this row's own Step-0
    obligation and is recorded in the evidence ledger below.

## Design decisions (behavioural; exact signatures at Tier-A upgrade)

- **D1 — Two new ports only.** A shape port and a panel-grid port;
  everything else the renderer needs already exists. Each surface is
  primitive-typed (strings/doubles/enums owned by Office or Core) —
  no interop types cross.
- **D2 — Ownership tag rides `AlternativeText`, bounded and
  versioned.** Every shape write carries the ownership tag
  `GanttCreator.Owned.v1:{hash}` in the shape's **alternative text**, where
  `{hash}` is a stable hash of `ScenePrimitive.PrimitiveId`; deletes and
  lookups filter by the `GanttCreator.Owned.v1:` prefix. This member was
  **corrected from `Shape.Tag` after the 2026-09-27 probe**: the Excel
  shape object has no `Tag` member ([ADR-0019](../adr/0019-shape-ownership-carrier.md)).
  The tag is deliberately *not* the full identifier: under ADR-0017 a
  shared owner's identifier is a `|`-joined row list and is therefore
  unbounded, so a truncated tag would break the R4.7 reconciliation key
  and the R4.8 filter at the same time. The shape **name** carries the
  full `PrimitiveId` (R4.3 D2), so name plus alternative text is the
  reconciliation pair. The prefix and the "tag must exist from day one"
  requirement are unchanged; only the member and the boundedness are new.
- **D3 — Geometry enters as `double` points, leaves as `Single` through
  the one boundary.** The port applies `GeometryMath.
  SnapToDisplayPrecision` (R3.1) internally; callers never pre-round.
- **D4 — Fakes are narrow and sequence-asserting.** They record the
  observable operation sequence and values (the test-strategy list);
  nothing more.
