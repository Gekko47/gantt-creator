## Design decisions (behavioural)

- **D1 — Two measurements, one harness.** Refresh (build + reconcile
  1,000 owned shapes, warm) and Validate/report (1,000 rows incl.
  note writes) both measured on the reference machine; host Windows +
  Office builds recorded per the Phase-4 note; results recorded in
  this file's Notes and STATUS.
- **D2 — No-regression threshold, not a budget assertion.** The
  automated test guards a generous upper bound (well above 2 s) to
  catch regressions in CI; the **budget judgement (2 s)** is the
  recorded reference-machine evidence. Threshold changes need a
  stated reason — never "to make it pass".
- **D3 — Only measured bottlenecks.** Every optimisation commit cites
  its before/after measurement in Notes; unmeasured render-path
  "clean-ups" are out of scope.
- **D4 — Exit evidence assembly.** Run and record: the exit
  demonstration (render → re-render idempotent → sentinel content
  unchanged); the matrix subset (zoom ×4, display scale ×3, 1,000
  events, protected-sheet write failures); then upgrade the Phase-5
  Tier-B guides to Tier A (refresh dates in status lines; manifest
  tiers updated) — the manifest's just-in-time obligation.

## Stop conditions (item-specific)

- A budget is exceeded → profile, record, stop for a decision (no
  blind optimisation; the two-attempt rule applies to any fix).
- The threshold must be loosened to pass → stop; that is a regression
  to investigate, not a knob to turn.

## Risk and rollback

Main risk: benchmark noise → mitigated by warm-up runs, repeated
medians, and the recorded-evidence policy. Rollback: `git revert`
(optimisation commits are individually revertible with their
measurements).
