  references and completes them); no CI-hosted host-specific runs.

## Design decisions (behavioural)

- **D1 — Completeness is enumerated, not felt.** The matrix is a
  table (stage × failure × assertions) committed in this file; every
  cell has a test or a documented N/A with the reason — a missing
  cell fails the row's review.
- **D2 — One assertion set, applied uniformly.** Every cell asserts
  the same checklist-K set; deviations are defects, not variants.
- **D3 — Host-specific repeats are recorded per build.** The
  supported-build classes from the R10.1 matrix (built from the
  Phase-4+ host records) each run the observed failure points; the
  results are recorded with builds.

## Acceptance tests

- **Automated — the consolidated matrix**: every stage × failure cell
  green with the D2 assertion set (**positive tests** throughout);
  zero residue everywhere; no extra worksheet.
- **Office host (Required)** — the host-specific repeat on each
  supported build class; workbook/Office state inspected; record
  host builds + results.

## Stop conditions (item-specific)

- A matrix cell exposes a real gap in an earlier row's failure
  handling → stop; route the fix to that row (its matrix must stay
  green), then re-run this consolidated pass.
- A host-specific failure cannot be reproduced safely → record the
  attempt honestly; the L12/diagnose discipline applies (never
  fabricate coverage).
