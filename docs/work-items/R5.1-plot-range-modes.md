## Design decisions (behavioural)

- **D1 — Automatic mode.** Range = min `Start` to max `Finish`(+1-day
  semantics via R3.3) over *valid, visible* lane-bound span events;
  point events (milestones/delineators) participate via their `Start`.
  Empty-data behaviour: refuse with an actionable message (a chart
  needs a range) — never a zero-day invented range.
- **D2 — Explicit mode.** User dates validate through
  `TimeScale.TryCreate` refusals (start-after-finish, default dates);
  boundary dates (single-day range) are legal and pinned.
- **D3 — Warnings are user-facing and count-only.** Mode-change and
  range warnings follow the R2.6 message discipline (actionable, no
  schedule content beyond counts/dates the user themselves supplied);
  they feed R5.8's panel when it lands.
- **D4 — Ribbon state follows the mode.** The state service gains the
  mode facts (existing R1.5 pattern) so controls reflect automatic vs
  explicit without new wiring idioms.
