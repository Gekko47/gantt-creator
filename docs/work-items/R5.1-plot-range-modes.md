## Design decisions (behavioural)

- **D1 — Automatic mode.** Range = min `Start` to max `Finish`(+1-day
  semantics via R3.3) over *valid, visible* lane-bound span events;
  point events (milestones/delineators) participate via their `Start`.
  Empty-data behaviour: refuse with an actionable message (a chart
  needs a range) — never a zero-day invented range.
- **D2 — Explicit mode.** User dates validate through
  `TimeScale.TryCreate` refusals (start-after-finish, default dates);
  boundary dates (single-day range) are legal and pinned.
- **D3 — Warnings are user-facing and count-only.** Mode-change and
  range warnings follow the R2.6 message discipline (actionable, no
  schedule content beyond counts/dates the user themselves supplied);
  they feed R5.8's panel when it lands.
- **D4 — Ribbon state follows the mode.** The state service gains the
  mode facts (existing R1.5 pattern) so controls reflect automatic vs
  explicit without new wiring idioms.

## Landed design (supersedes the earlier button-based proposal)

The R5.1 surface is a **Ribbon group named `Plot Area`** (replacing the
earlier three-button `Plot Settings` group). It is a 6-row, 2-column
surface: labels in column A, controls in column B.

| Row | Label (col A) | Control (col B) |
| --- | --- | --- |
| 1 | `Start Plot Date` | — |
| 2 | `Auto` | checkbox `chkPlotStartAuto` |
| 3 | — | edit box `edtPlotStartDate` |
| 4 | `Finish Plot Date` | — |
| 5 | `Auto` | checkbox `chkPlotFinishAuto` |
| 6 | — | edit box `edtPlotFinishDate` |

- **No Apply button.** Every checkbox toggle and every edit-box commit
  writes the four settings keys (`PlotStartMode`, `PlotFinishMode`,
  `PlotStartDate`, `PlotFinishDate`) to `tblGanttSettings` immediately.
- **Edit-box auto-validation.** On commit the text is parsed against the
  repo default `dd/MM/yyyy` first, then `MM/dd/yyyy`, `yyyy-MM-dd`,
  `M/d/yyyy`, `M/d/yy`, `dd-MMM-yyyy`, then a culture fallback. A valid
  value is normalised to `dd/MM/yyyy` for storage and display. A
  non-date entry is **rejected with no save**: the edit box reverts to
  the previously stored value via `getText`.
- **Auto disables its edit box.** `getEnabled` for each edit box returns
  `!state.Plot[Start|Finish]Auto`; when the matching checkbox is checked
  the edit box is greyed out and its date is cleared.
- **Refresh-only rendering.** The worksheet never re-renders on change.
  Only the Refresh-chart command consumes the stored four keys
  (`PlotRangeResolver` → R3.3 month-snap → scene rebuild).
