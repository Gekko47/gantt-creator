# Work item — R1.1

## Outcome

Loading the packed x64 XLL into desktop Excel runs `AutoOpen` and `AutoClose`,
each writing exactly one structured, redacted record to a local rolling log at
`%LOCALAPPDATA%\GanttCreator\logs` (identifier fields only — version, Excel
version, process bitness, XLL file name; never workbook content). The
behaviour is proven by automated entry-point/log contract tests plus a green
Release build.

## Scope

- `docs/work-items/R1.1-exceldna-entry-point.md` (this file)
- `src/GanttCreator.AddIn/` — new files only: `AddInHost.cs` (the
  `IExcelAddIn` entry point), `AddInIdentity.cs`, `AddInLifecycle.cs`,
  `AddInLogFactory.cs`
- `tests/GanttCreator.AddIn.Tests/` — new contract tests
- `docs/STATUS.md` — active work item pointer

Decision recorded here (approved by the human on 2026-09-12): the log
directory is `%LOCALAPPDATA%\GanttCreator\logs`, with a temp-directory
fallback when `%LOCALAPPDATA%` is unavailable. Log files:
`gantt-creator-addin.log` (+ `.N.log` rotations), written by Core's
`RollingLog` (redacted, size-rotated, failure-latching).

## Acceptance tests

- **Automated** (`tests/GanttCreator.AddIn.Tests/`):
  - `AddInHostTests` — entry-point reflection contract (public class,
    parameterless constructor, implements `ExcelDna.Integration.IExcelAddIn`),
    and AutoOpen/AutoClose behaviour against injected fakes: exactly one
    open record with all four identifiers, exactly one close record, log
    disposed on close, and every source/lifecycle failure degrades without
    propagating (never-throw contract).
  - `AddInLifecycleTests` — one record per call with the agreed
    `open addin-version=… excel-version=… process=… xll=…` shape, missing
    fields normalized to `unknown`, and null-input guards.
  - `AddInLogFactoryTests` — log created under the given base directory,
    temp fallback when the base directory is unavailable, and unwritable
    locations latch `IsFailed` instead of throwing.
  - Proven by: `pwsh ./scripts/verify-quick.ps1` (which includes the
    Release build, format, lint, and packed-XLL publish steps).
- **Office host** (`Required` per `docs/03-ROADMAP.md`): F5 in Visual
  Studio loads the correct x64 XLL (`GanttCreator.AddIn-AddIn64-packed.xll`);
  `AutoOpen` and `AutoClose` breakpoints are hit; Excel bitness matches the
  XLL. This gate is demonstrated manually in Visual Studio and cannot be
  automated.

## Risk and rollback

Risk: Excel-DNA host integration behaves differently from the tested
in-process contracts (e.g. `AutoOpen` running before a workbook exists, or
`ExcelDnaUtil` probes throwing during early load). Mitigation: every probe
and every write is guarded so AutoOpen/AutoClose never propagate; worst case
is a missing log record, not a load failure. Rollback: `git revert <commit>`
removes the four new AddIn source files, the three new test files, and the
STATUS.md pointer; no existing code, schema, or dependency changes are
touched.
