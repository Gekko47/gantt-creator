## Design decisions

- **D1 — Tool (D-G3; human approval required): Stryker.NET** as a
  `dotnet tool` pinned in `scripts/tool-versions.psd1`, installed by
  the gate step (not a csproj PackageReference). Alternatives
  (hand-rolled mutator) rejected: unmaintained, no report format.
  **Stop until approved.**
- **D2 — Changed-code scope, 80%.** The gate runs Stryker against
  `GanttCreator.Core` with `--since` against the recorded baseline so
  only changed files count; threshold 80 per the test strategy. The
  first full-Core run (no `--since`) is the archived baseline.
- **D3 — Gate shape.** `mutation-gate.ps1` wraps install → run →
  threshold judge → report artifact; wired as a `verify.ps1` step (same
  step name in `ci.yml` for parity). The failure exit code is judged
  after capture — **never `-EnableExit`** (the L10 lesson; the
  `pssa-gate` pattern).
- **D4 — Pester guard.** `mutation-gate.Tests.ps1` asserts: the verify
  step exists and runs after the Core test step; the tool version is
  pinned; the threshold constant equals 80; the report path is
  produced by the harness; no `-EnableExit` usage (pattern-matched).
- **D5 — Timing.** The threshold applies **from the next Core change
  after this row lands**; this row archives the baseline and does not
  gate itself retroactively.

## Implementation steps (in order)

1. STOP — human approves D-G3 (tool + pinned version).
2. `tool-versions.psd1` entry + `mutation-gate.ps1` per D1–D3.
3. `verify.ps1` step + `ci.yml` step (same name; parity tests stay
   green).
4. `mutation-gate.Tests.ps1` per D4 (**positive tests** for each
   guard: missing pin, wrong threshold, missing step, `-EnableExit`
   presence).
5. Run the first full-Core mutation run on the reference machine;
   archive the baseline report under the local mutation directory;
   record the score in this file's Notes.
6. Docs: REPO-MAP (verification-commands row gains the step), STATUS,
   status line. One commit: `test: R3.13 …` — Checklist: G, I.

## Stop conditions (item-specific)

- D-G3 unapproved → no install, no step.
- Stryker cannot target the solution layout (e.g. `.slnx` gaps) → stop
  with the evidence; a per-project workaround needs the human's nod.
- The Pester guard cannot run the tool in CI (runner constraints) →
  stop; record it; never silently skip the step in CI (parity).

## Risk and rollback

Main risk: gate-integrity drift (a step that reports PASS without
running — the L10 class) — mitigated by the D4 no-silent-pass guards
and exit-code-after-capture judging. Rollback: `git revert` (removes
the step from both scripts and CI in one commit).
