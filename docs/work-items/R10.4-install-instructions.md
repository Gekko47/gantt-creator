## Scope

- The instructions document (install/update/rollback/uninstall, each
  exact and verifiable; rollback = restoring the previous artifact
  version; uninstall = removing files/registration with no residue).
- Smoke automation where practical (scripted install check: files
  placed, Excel loads, version command reports the right build) —
  scope fixed at Tier-A upgrade by practicality evidence.
- The rehearsal record (the four phases, before/after machine state).
- `docs/REPO-MAP.md`, `docs/STATUS.md`, status line.

## Exclusions

- No new installer technology beyond the chosen mechanism; no
  auto-update service (out of scope); no machine-wide policy changes.

## Design decisions (behavioural)

- **D1 — All four phases, rehearsed.** Install → update (new version
  over old) → rollback (previous version) → uninstall (clean) — each
  phase's state recorded; the rehearsal runs on a clean VM snapshot.
- **D2 — No residual configuration.** Uninstall leaves no add-in
  files/registration; workbook-side `_GanttCreatorConfig` behaviour is
  documented (it is worksheet content, not machine config — the
  uninstall doc says so explicitly to avoid user surprise).
- **D3 — Instructions are version-exact.** The documented steps name
  the artifact, paths, and verification commands for the current
  release; a human follows them once (this row's live gate = the
  rehearsal).

## Stop conditions (item-specific)

  documented scope → stop; the human decides.

  release gate needs it.

## Risk and rollback

Main risk: install instructions drifting from the artifact — D3's
version-exact rule + the rehearsal are the guard. Rollback: `git
revert`.
