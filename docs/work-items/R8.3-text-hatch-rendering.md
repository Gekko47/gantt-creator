### Step 0 outcome (2026-11-23, probed on the reference machine)

The probe (temporary, deleted after this record) fixed the API and
behaviour the implementation consumes. Pinned **SkiaSharp 4.157.0**
(`SkiaSharp, Version=4.157.0.0`).

**API surface (reflection over the installed package).**

- `SKPathEffect.Create2DLine(Single width, SKMatrix matrix)` exists.
- `SKPathEffect.CreateDash(Single[] intervals, Single phase)` exists.
- `SKFont` has one constructible form: `.ctor(SKTypeface, Single size,
  Single scaleX, Single skewX)`; properties include `Metrics`, `Size`,
  `Typeface`, `Edging`, `Subpixel`, `Hinting`.
- The text draw is `SKCanvas.DrawText(String, Single x, Single y,
  SKTextAlign, SKFont, SKPaint)`; `SKTextAlign` is Left=0, Center=1,
  Right=2.
- `SKFontMetrics` exposes `Ascent`, `Descent`, `Top`, `Bottom`,
  `CapHeight`, `XHeight` (all Single; Ascent is negative).
- Every `SKPaint` text member (`TextSize`, `TextAlign`, `FontMetrics`,
  `TextEncoding`, …) is **obsolete**; the `SKFont` route is mandatory.
- `SKPathBuilder` has `MoveTo(Single, Single)`, `LineTo(Single,
  Single)`, `Detach()`.
- `SKMatrix` has `CreateRotationDegrees`, `CreateScale`,
  `CreateTranslation`, and `PreConcat`/`PostConcat`.
- Glyph coverage is queryable: `SKFont.ContainsGlyph(Int32)` /
  `ContainsGlyphs(String)` and `SKTypeface.GetGlyph(Int32)`.

**Hatch (D8 decision).** `Create2DLine` on a fill paint is
matrix-convention dependent and produced contradictory output across
the four probed variants — one all-clear row and three all-painted
rows for a 45°/10 px spacing. The **explicit clipped diagonal lines**
route rendered the intended geometry exactly: at a 10 px x-intercept
step it produced `3 painted / 7 clear` runs (horizontal period ≈ 10
px, perpendicular pitch ≈ 7.07 px = 10/√2). D8 therefore resolves to
**explicit marked-up diagonal lines clipped to the primitive**, with
the generator stepping the x-intercept by `perpendicularPitch × √2`
so the perpendicular spacing equals `HatchPitchPt` in pixels.

**Dash.** `CreateDash([6,4], 0)` on a 2 px line produced exact
`6 painted / 4 clear` runs; the solid control produced one 80 px run.
The closed interval table maps cleanly, with intervals stated in
points and scaled by the transform.

**Text determinism.** Two renders of `"Hello Wg"` at 12 px were
byte-identical **in-process and across two separate test processes**
on the reference machine, for all four faces:
`Aptos` `D05078AE…10BF50A`, `Aptos-Bold` `F9B7C940…2194FE`,
`Aptos-Narrow` `308BCD89…C9D9CD`, `AptosNarrow-2bc0000-560000`
`90622F02…C32CD5`. Metrics at 12 px are identical across the four
faces for ascent/descent (`-11.267578` / `3.3808594`) and differ only
in the last decimals of `top`/`bottom`. Exact-pixel goldens are
therefore viable on the reference machine; the documented perceptual
tolerance remains the fallback for a different host, never adopted to
green a red run.

**Glyph coverage.** `ContainsGlyph` is the stop-condition check; the
permanent probe asserts the four faces contain every character the
renderer's own text emitters produce (ASCII plus the `…` ellipsis the
label truncation writes). User-supplied scripts outside the face's
coverage render as the `.notdef` box — a documented font limit, not a
renderer substitution.

## Design decisions (behavioural)

- **D1 — Consume the scene's text facts.** Position/side/bounds come
  from the scene; the renderer never re-measures or reselects (the
  R4.4 D1 discipline, raster side).
- **D2 — The pinned font is resolved once per process** and reported
  (family/version) in test output; a missing/mismatched font follows
  the R8.2a policy exactly (clear error or approved fallback) — a
  **positive test** constructs the missing-pin case.
- **D3 — Patterns are patterns.** Hatch draws with the chosen API at
  the token spacing/width as closely as the API allows; any deviation
  is measured and recorded (the R8.3/R8.4 goldens become the
  equivalence evidence; deviations never silently ship).
  **Landed 2026-11-23:** `HatchPatternPainter` honours both tokens
  exactly — the x-intercept step is the perpendicular
  `HatchPitchPt` times √2, the stroke width is `HatchLinePt` — so the
  raster is closer to the contract than Excel's fixed
  `MsoPatternType` set; the deviation direction is recorded above,
  not silently shipped. `StrokeDashMap` states every dash interval in
  stroke-width multiples and throws on an unmapped member rather than
  drawing the nearest pattern, the `ExcelShapeWriter.MapDashStyle`
  rule applied to the raster side.
- **D4 — Determinism extends to text.** Two renders byte-identical
  (antialiasing settings pinned per the test-strategy list).

## Stop conditions (item-specific)

  labels) → stop; the ADR's options are revisited, never silently
  swapped.

  tolerance → record and stop if the deviation is material (R8.4's
  visual-diff gate would fail anyway).
