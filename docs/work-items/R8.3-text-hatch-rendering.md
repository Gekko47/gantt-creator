## Design decisions (behavioural)

- **D1 — Consume the scene's text facts.** Position/side/bounds come
  from the scene; the renderer never re-measures or reselects (the
  R4.4 D1 discipline, raster side).
- **D2 — The pinned font is resolved once per process** and reported
  (family/version) in test output; a missing/mismatched font follows
  the R8.2a policy exactly (clear error or approved fallback) — a
  **positive test** constructs the missing-pin case.
- **D3 — Patterns are patterns.** Hatch draws with the chosen API at
  the token spacing/width as closely as the API allows; any deviation
  is measured and recorded (the R8.3/R8.4 goldens become the
  equivalence evidence; deviations never silently ship).
- **D4 — Determinism extends to text.** Two renders byte-identical
  (antialiasing settings pinned per the test-strategy list).

## Acceptance tests

  antialiasing, per policy; geometry exact); clipping tests; pattern

## Stop conditions (item-specific)

- The chosen font cannot render the required glyph set (Unicode
  labels) → stop; the ADR's options are revisited, never silently
  swapped.
- The hatch API cannot express `HatchPitchPt` within a documented
  tolerance → record and stop if the deviation is material (R8.4's
  visual-diff gate would fail anyway).

## Risk and rollback

Main risk: text determinism across machines — the pinned font +
antialias settings exist exactly for this. Rollback: `git revert`.
