- **Extract the shared pre-flight before writing the command.** `CopyEditableCommand.Run`
  owns ~200 lines of read → config → validate → measure → request → selection → bounds
  ([`CopyEditableCommand.Run()`](../../src/GanttCreator.AddIn/CopyEditableCommand.cs)).
  Add `EditableExportPreflight` (AddIn) returning `EditableExportPreparation` or a typed
  refusal; both commands consume it. The existing 33 `CopyEditableCommandTests` facts
  stay green; add a parity fact that both commands produce the same resolution.
- **Add the post-resolution bounds guard.** Before any staging shape is created, the
  pre-flight must reject a resolved `ExportBoundsOutcome` whose `Bounds.Width` or
  `Bounds.Height` is not finite and strictly positive with
  `ExportBoundsRefusal.InvalidBounds`. The resolver already refuses a non-positive
  `request.PlotBounds`
  ([`ExportBoundsResolver.TryResolve()`](../../src/GanttCreator.Core/Scene/ExportBoundsResolver.cs)),
  but the resolved `ChartBounds` was not checked. The transfer consumes
  `ExportBounds.Bounds` (zero-origin) and never re-applies `PlacementDelta`.
- **Add the additive lifecycle transfer seam (option B).** The lifecycle invokes the copy
  seam and immediately enters cleanup
  ([`StagingLifecycle.Run()`](../../src/GanttCreator.Office/StagingLifecycle.cs)).
  Add an optional `Transfer` hook and a `StagingLifecycleOutcome.Transfer` result plus
  `StagingLifecycleRefusal.TransferRefused`. The hook is
  `Func<StagedGroupOutcome, StagingCopyResult, StagingTransferResult>? Transfer = null`;
  `StagingTransferResult` carries success, the validated count/bounds and a typed
  refusal. It runs only after a successful verified copy and before the `finally`
  cleanup; every existing R6 caller is source-compatible because the new member is
  optional.
- **The R7.2 button-contract decision must be recorded before this row starts**
  (D-R7.2: attach to the active editable presentation; create only when none is open,
  announced). The R7.2 stop-point stands until the human records it.
- **Correct the `RibbonState` gate.** `CopyEditable` is currently enabled on
  `SheetInitialised` alone, but `SheetInitialised` is true in a `NeedsRepair` workbook
  whose configuration is missing (`ResolveMode`), so the button is enabled for a command
  that will refuse at the configuration read. The corrected rules:
  - `RibbonState.IsVisible(ExportGroup)` → `Mode == RibbonMode.Ready`;
  - `RibbonState.IsEnabled(CopyEditable)` and `SendToPowerPoint` →
    `Mode == RibbonMode.Ready && ActiveSheetIsGanttSheet` (equivalently
    `HasActiveWorkbook && SheetInitialised && ConfigurationPresent && ActiveSheetIsGanttSheet`);
  - the `Export` group is hidden in `FirstRun` and `NeedsRepair`; the buttons are never
    enabled without a readable table **and** a present configuration.
  Add pins for FirstRun, NeedsRepair (table readable, config missing), Ready on the
  Gantt sheet, and Ready on another sheet.

## Design decisions (behavioural)

- **D1 — One command, the full pipeline.** Composition → staging → grouping →
  copy (verified) → transfer (attach/start → paste → validate → position) → cleanup —
  pinned order via the fake ports and the lifecycle seam. The transfer runs inside the
  lifecycle, after the verified copy and before cleanup, so the clipboard is live while
  the staged shapes exist and the cleanup remains the one authority. Concise count-only
  success ("Sent N shapes to the active slide"); each typed failure → one actionable
  message.
- **D2 — Ownership assertions are structural.** The transfer port has no
  `Save`/`SaveAs`/`Close`/`Quit` member (R7.1's test); the command tests assert that only
  the expected port members were called and that no `FinalReleaseComObject`, `Quit` or
  `Close` appears in the new source. Only owned proxies are released, in reverse order,
  exactly once; any event connection is detached exactly once.
- **D3 — A failed transfer never costs user data.** Excel staging is cleaned (R6.5);
  PowerPoint is untouched on failure (R7.5); the Excel state scope (R4.2) wraps the whole
  command and is disposed even on a pre-flight refusal.
- **D4 — One pre-flight authority.** `EditableExportPreflight` is the only place that
  reads, validates, measures and resolves the export; both commands call it. A second
  copy of that chain is a defect.
- **D5 — The transfer composes the copy's scene.** `EditableExportRequest.Create` pins
  `SceneCompositionProfile.EditableExport`; the transfer adds a parity pin that its
  scene bounds equal the copy's. `SceneCompositionProfile.PowerPoint` remains unused
  until a renderer-specific difference exists.
- **D6 — The ribbon gate is `Mode == Ready`.** `ExportGroup` is visible only when the
  table is readable and the configuration is present; both export buttons enable only on
  the Gantt sheet. `SheetInitialised` alone is not sufficient.

## Stop conditions (item-specific)

- Any path needs PowerPoint save/close to succeed → stop; that is a separate explicit
  command the release does not have.
- The R7.2 button contract is undecided → stop.
- The lifecycle transfer seam would require a second cleanup authority → stop; the seam
  belongs inside the existing `finally`.
- The resolved `Bounds` cannot be made finite/positive without a new export contract →
  stop; record it; the human decides.

## Risk and rollback

Main risk: composite-pipeline ordering drift — the command's order pin, the lifecycle
seam's order pin and each stage's own contract guard it. Rollback: `git revert`.
