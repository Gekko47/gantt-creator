## Outcome

Every managed column is classified, the engine columns are hidden and locked and
repaired if unhidden, `Duration` is visible and locked, `GanttRowHeightPt` exists
as a metric token, `CriticalLinePt` is gone and `CriticalFill` is present, and the
workbook schema advances 3 → 4 with the integrity checker reporting the change.

## Scope

- `src/GanttCreator.Core/GanttSchemaVersion.cs` — **3 → 4**
- `src/GanttCreator.Core/GanttTableColumns.cs` — column classification contract;
  `Duration` after `Finish`, `SiblingOrder` after `ParentId`
- `src/GanttCreator.Core/GanttRowDto.cs` — matching cell states at the same
  positions
- `src/GanttCreator.Core/GanttCatalogues.cs` — add `GanttRowHeightPt`; **remove

- `tests/` — contract, Office contract and AddIn tests
- `docs/REPO-MAP.md`, `docs/STATUS.md`

## Exclusions

- **The `Duration` calculation itself** — R4.7F. This row makes the column exist,
  visible and locked; it does not compute the value.
- **The Critical Interval representation change** — R4.7E owns the capability
  flip and the validator change. This row owns only the *token* changes
  (`CriticalLinePt` out, `CriticalFill` in).
- No worksheet protection redesign beyond the column state.
- **No migration of an existing workbook.**

## Design decisions

- **D1 — Three classes, and the classification is a contract with a test:**
  *user-visible and editable* (`Type`, `Description`, `Start`, `Finish`);
  *user-visible and locked* (`Duration`); *engine-hidden and locked* (`Id`,
  `ParentId`, `SiblingOrder`, `LaneId`, `StackIndex`, `StyleKey`, `LabelPosition`,
  `FillColour`, `StrokeColour`, `Visible`, `SortOrder`).
- **D2 — Engine columns stay physically in `tblGanttData`**, hidden and locked.
  REV5 §11 and REV6 §1 both permit this over a disruptive migration, and it keeps
  one logical row in one table. The state is **repaired** if a user unhides one.
- **D3 — `Duration` is owned by the add-in, written, and locked.** Not a formula
  and not user-editable: a formula would be visible in the formula bar and would
  contradict the locked presentation.
- **D4 — `GanttRowHeightPt` replaces `LaneHeightPt`** in the metric catalogue, and
  **`CriticalLinePt` is removed**. R4.7D consumes the former; R4.7E consumes the
  latter's absence.
- **D5 — The version bump is the last change in the commit sequence.** All the
  D1-D4 changes land first; `CurrentSchemaVersion` becomes 4 last, so the
  integrity checker is the gate rather than a manual review.
- **D6 — No migration, and the error says so.** There are no active users, so a
  version-3 workbook is **reported, not converted**. The message must be
  Ribbon-visible and actionable, not a generic integrity string.

## Acceptance tests

- **Automated**:
  - every column has exactly one classification, and the set is exhaustive
  - engine columns are hidden and locked after Initialise; un-hiding one and
    refreshing restores it (positive test)
  - `Duration` is locked and rejects a manual edit; the four authoring columns
    accept edits
  - the reader, validator and schema agree on column **order**
  - `CriticalLinePt` is absent from the catalogue and the materialised metrics
    table; `CriticalFill` is present with `#FF0000`
  - a version-3 workbook produces a typed, actionable mismatch refusal (positive
    test)
- **Office host (Required)**: on a protected sheet, confirm the engine columns and
  `Duration` reject edits while the authoring cells accept them, and that the
  version bump is detected. Record the host build.

## Step 0 — verify prerequisites

- **R4.7A must have landed**; this row adds `SiblingOrder` to the same schema and
  DTO, and two rows must not both claim that constructor position.
- `GanttTableSchema.Default` is currently 13 required + optional `SortOrder`. The
  new order is `Id`, `LaneId`, `StackIndex`, `Type`, `Description`, `Start`,
  `Finish`, **`Duration`**, `ParentId`, **`SiblingOrder`**, `StyleKey`,
  `LabelPosition`, `FillColour`, `StrokeColour`, `Visible`, `SortOrder`.
- `ConfigIntegrity` and the R2.10 repair workflow already read
  `CurrentSchemaVersion`; re-read how a mismatch is reported before adding a case.

## Stop conditions

- A migration path becomes necessary → stop and ask the owner.
- Protection would prevent an add-in operation the product requires (Add Child,
  grouping, Duration write, height normalisation) → stop; ADR-0008 governs.

## Risk and rollback

Main risk: the column-order change ripples into the reader, the validator and
their tests. Mitigated by changing schema and DTO together in one commit.
Rollback: `git revert`.
