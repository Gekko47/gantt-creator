## Outcome

A Critical Interval is a real user-authored child row with its own `Start`,
`Finish`, `Description`, ID and permitted styling, rendering as a **filled
rectangle** at half the predetermined `ActivityHeightPt`, vertically centred on its
own visual slot, drawn from its **own** dates and projected onto the parent lane,
consuming no lane height — with **no renderer reinterpreting it as a line**.

## Design decisions

- **D1 — The scene primitive stays `SceneRect`** and is what the host draws.
- **D2 — The rect is filled** with `CriticalFill` = `#FF0000`. The new token
  exists because reusing `CriticalStroke` as a fill would make the catalogue's own
  naming contradict its use, and a later change to the outline colour would
  silently change the bar.
- **D3 — SUPERSEDED 2026-09-30. The height is `PredeterminedHeightPt / 2`** — half
  the *resolved style's* `ActivityHeightPt` — and the rect is **centred on its own
  visual slot**, not top-aligned to the parent. The parent bar's resolved height
  is no longer an input: `CriticalOverlayRequest` carries no
  `ParentVisibleBounds` and `TryBuild` takes no parent-bounds dictionary. The
  half-height denominator therefore comes from the `CriticalInterval` preset's
  own `ActivityHeightPt` (D4), with no new token and no parent lookup.
- **D4 — `CriticalLinePt` is retired** (landed in R4.7C). The `CriticalInterval`
  preset keeps its `ActivityHeightPt` reference, which supplies the denominator.
- **D5 — The catalogue, the validator and the checklist change together.** A
  partial change is the failure mode: the entity renders filled while the
  validator rejects the user's own fill override, which looks like a rendering
  choice rather than a defect. One commit, three sites.
- **D6 — `CriticalInterval` remains a genuine child** with independent dates, its
  own ID, and permitted styling, projected `OverlayParent`. The parent link
  governs **lane membership only** — it is never read for geometry.
- **D7 — The colour-capability change goes in the *integration* fixture, not the
  canonical one.** The committed golden *does* carry critical primitives
  (**two** of them, `…000c1:critical` and `…000c2:critical`), and the geometry
  change in `017199f` moved both, so the golden was regenerated in `806a632`.
  Adding a child to the canonical fixture for the *capability* flip would force a
  fourth regeneration for a change the snapshot already pins; adding it to the
  integration fixture pins the fill contract without one. **This decision
  previously claimed the golden "contains no critical overlay primitive", which
  was false** — the second interval had been silently deleted for falling
  outside its parent, and reading the snapshot as critical-free is how the
  guide/code divergence survived.

## Step 0 — verify prerequisites

- **R4.7C must have landed**: `CriticalFill` in the catalogue and `CriticalLinePt`
  removed. Doing the capability flip first would produce an entity whose style
  names a token that does not exist.
- **Re-read `CriticalOverlayBuilder` before changing it** — this row rewrote it
  twice, and the stale guidance below is what a reader would otherwise copy. The
  pre-row form placed the rect at `parent.Top` with height
  `request.CriticalLinePt`; **neither survives**. The current request carries
  `PredeterminedHeightPt` and `SlotCentreY` and **no parent bounds at all**, and
  the rect is centred on `SlotCentreY`.
- **Check the caller too.** `SceneBuilder` supplies `placement.SlotCentreY`, which
  is **lane-relative**; the plot top must be added before the value reaches the
  builder, exactly as the span and milestone passes add it. Omitting it draws the
  bar outside the plot — the defect the canonical golden recorded faithfully
  rather than caught.
- `CriticalInterval` has `EntityColourCapability.Fill | Stroke`
  (`EntityTypeCatalog`), and `08-TEST-CHECKLIST.md` §C has been amended to match;
  a `FillColour` override is accepted.

## Stop conditions

- Excel cannot fill a 4pt rectangle legibly at the reference zoom → stop and
  report; do not switch to an outline to compensate, which reintroduces the
  reinterpretation this row removes.
- A golden diff appears **in the colour-capability commit** → stop. D7 scopes that
  commit to the vertical integration fixture; a snapshot change there means the
  canonical fixture was altered when it should not have been. A diff in the
  *geometry* commit is expected and is regenerated under human review.

## Risk and rollback

Main risk: a partial change across the three D5 sites. Mitigated by requiring all
three in one commit and by the positive test for the accepted fill. Rollback:
`git revert`.
