# Work item — R4.7E

> roadmap revision 10. Decision:

> `CriticalLinePt` retired). Checklist: C, B, M, E, I.

## Outcome

A Critical Interval is a real user-authored child row with its own `Start`,
`Finish`, `Description`, ID and permitted styling, rendering as a **filled
rectangle** at half the predetermined `ActivityHeightPt`, vertically centred on its
own visual slot, drawn from its **own** dates and projected onto the parent lane,
consuming no lane height — with **no renderer reinterpreting it as a line**.

## Status (2026-09-30) — geometry pulled forward, remainder still open

The owner ruling of 2026-09-30 replaced this row's geometry rule, and the
replacement **landed in `017199f`**, not here. What is now true:

- **D3 as written below is SUPERSEDED.** Height is `PredeterminedHeightPt / 2`
  (the resolved style's `ActivityHeightPt`), **not** `ParentVisibleBounds.Height / 2`.
  `CriticalOverlayRequest` no longer carries `ParentVisibleBounds` at all, and
  `TryBuild` no longer takes a parent-bounds dictionary.
- **The horizontal extent is the row's own Start and Finish**, clipped only to
  the plot. It may be shorter than, equal to, or longer than its parent. An
  interval wholly outside its parent is now drawn rather than deleted.
- The bar is **centred on its own visual slot**, not top-aligned to the parent's.
- `UnresolvedParent`, `ClippedToParentCode` and `OutsideParentCode` were removed as
  meaningless; `ClippedToPlotCode` / `OutsidePlotCode` replaced the last two.
- The golden snapshot **did** change and was regenerated in `806a632`. Both the
  roadmap and the entity guide header had claimed it contained no critical
  primitive; both claims were false and have been corrected.

**Still outstanding here, unchanged:** the `EntityColourCapability.Fill` flip and
the corresponding `GanttRowValidator` change. ADR-0027 D6 requires those three to
land as one commit, because the current state is the partial one it warns about —
the preset fills while the validator still refuses a user `FillColour` override.
Also outstanding: the vertical integration fixture carrying a critical child
inside its parent, which the golden no longer substitutes for.

## Exclusions

- **No `SceneLine` change.** REV5 §7/§16 and REV6 §9/§16 proposed a line
  primitive; the owner **rejected** it. `SceneLine` remains in use for grid lines,
  delineators, panel borders and splitter bands, untouched.
- **No renderer special case.** `SceneShapeRenderer` needs **no** critical branch —
  that is the point of the decision.
- **No `CriticalOverlayHeightRatio` token.** The half-height is derived.
- No canonical-fixture change (see D7).

## Design decisions

- **D1 — The scene primitive stays `SceneRect`** and is what the host draws.
- **D2 — The rect is filled** with `CriticalFill` = `#FF0000`. The new token
  exists because reusing `CriticalStroke` as a fill would make the catalogue's own
  naming contradict its use, and a later change to the outline colour would
  silently change the bar.
- **D3 — Height is `ParentVisibleBounds.Height / 2`, top-aligned** to the
  parent's post-clip top. `ParentVisibleBounds` already carries the resolved
  parent height, so no new token and no new input are needed.
- **D4 — `CriticalLinePt` is retired** (landed in R4.7C). The `CriticalInterval`
  preset keeps its `ActivityHeightPt` reference, which supplies the denominator.
- **D5 — The catalogue, the validator and the checklist change together.** A
  partial change is the failure mode: the entity renders filled while the
  validator rejects the user's own fill override, which looks like a rendering
  choice rather than a defect. One commit, three sites.
- **D6 — `CriticalInterval` remains a genuine child** with independent dates, its
  own ID, and permitted styling, projected `OverlayParent`.
- **D7 — The critical child goes in the *integration* fixture, not the canonical
  one.** The committed golden contains **no** critical overlay primitive — its
  only `critical` occurrence is the warning `CriticalIntervalOutsideParent` —
  which is exactly why the guide/code divergence survived. Adding a child to the
  canonical fixture would regenerate the golden a third time; adding it to the
  integration fixture pins the representation without one.

## Acceptance tests

- **Automated** — `dotnet test tests/GanttCreator.Core.Tests`:
  - the overlay's `Bounds.Height` is exactly half the parent's resolved height,
    and its `Top` is the parent's top
  - the resolved style carries the **fill**, not only a stroke
  - a `FillColour` override on a critical interval is **accepted** (positive test
    for the changed path) and reaches the scene
  - a capability the type genuinely does not hold is still a blocking error
  - a critical child with independent dates renders on the parent lane
  - two critical children on one parent both render and overlap correctly
  - an interval wholly outside the parent still warns and emits nothing
  - the integration fixture's critical child is present in the built scene
  - **no golden change is expected**; if one occurs, the commit is wrong
- **Office host (Required)**: style a critical child and read the fill colour back
  off the live host. Record the host build.

## Step 0 — verify prerequisites

- **R4.7C must have landed**: `CriticalFill` in the catalogue and `CriticalLinePt`
  removed. Doing the capability flip first would produce an entity whose style
  names a token that does not exist.
- `CriticalOverlayBuilder` currently places the rect at `parent.Top` with height
  `request.CriticalLinePt` (lines 200-208). Only the height source changes; the
  top alignment is already correct.
- `CriticalInterval` currently has `EntityColourCapability.Stroke` only
  (`EntityTypeCatalog.cs:132`), and `08-TEST-CHECKLIST.md` §C still states that a
  fill override is a blocking error. Both change in this row.

## Stop conditions

- Excel cannot fill a 4pt rectangle legibly at the reference zoom → stop and
  report; do not switch to an outline to compensate, which reintroduces the
  reinterpretation this row removes.
- A golden diff appears → stop. D7 says there should be none.

## Risk and rollback

Main risk: a partial change across the three D5 sites. Mitigated by requiring all
three in one commit and by the positive test for the accepted fill. Rollback:
`git revert`.
