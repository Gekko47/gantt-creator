## Outcome

A per-row **date-label selector** in the ribbon's **Labels** group
writes the `DateLabelPosition` value into the selected row's table
cell — every option validated against the selected Type's allowed
date-label set — and the scene reflects the choice (which of the
start/finish date labels render) only after Refresh, pinned by
capability, validation, and scene snapshot tests for every option.

## Design decisions (behavioural)

- **D1 — Options come from the catalogue, derived from the date
  mode.** The control offers exactly the selected Type's allowed
  date-label choices, derived from `EntityTypeDefinition.DateMode`:
  `None` → no options (the control is disabled, exactly as the
  description-label dropdown is for a dateless type); `StartOnly` →
  `Auto`, `Start`, `None`; `StartFinish` → `Auto`, `Start`,
  `Finish`, `None`. No option list is authored twice. `Custom
  Activity` is a span, so it reads `StartFinish`; its style does not
  carry a date mode, so the capability is **type-only** (unlike
  `LabelPosition`, which a `Custom Activity` style can narrow).
- **D2 — Table write, never shape edit.** The control writes the
  `DateLabelPosition` cell (or clears it for `Auto`) — it never
  touches a generated shape (the architecture's per-entity rule).
- **D3 — Blank/`Auto` preserves the current scene behaviour.** A blank
  cell (the default for every existing row) means `Auto`: the scene
  plans **both** date labels for a span, the **start** label for a
  milestone or delineator, and **none** for a dateless type — exactly
  the behaviour the scene already produces. `Start` restricts the row
  to its start-date label; `Finish` restricts it to its finish-date
  label (a span only; a milestone/delineator has no finish date, so
  `Finish` is never offered for them); `None` hides the row's date
  labels entirely.
- **D4 — Type-only capability check.** Because the capability derives
  from the type's date mode, validation and the mutator check the
  value against the type alone — no style-registry lookup, no
  `StyleUnknown` refusal. A value outside the type's set is refused
  with `DateLabelNotAllowedForType`; a value that is not a defined
  enum member is refused with `UnknownDateLabelPosition`.
- **D5 — The vocabulary is `Auto` / `Start` / `Finish` / `None`
  (settled by the product owner 2026-10-14; `None` added by the
  second owner ruling 2026-10-14).** `Auto` is the both-labels
  default; `Start` and `Finish` each restrict to one date label;
  `None` names no date labels at all (the row's dates are hidden).
  The second ruling also asked for a `Both` option and rejected it:
  `Both` names what `Auto` already means for a span, so it would be
  a redundant option, and `None` is the only new capability. This is
  a new closed enum `GanttDateLabelPosition`, distinct from the
  `LabelPosition` placement vocabulary (which describes *where* a
  label sits, not *which* date label shows). §23's never-suppress
  rule governs the placement fallback for labels the row still
  shows; an explicit `None` is the same class of per-row override as
  `Start`/`Finish` (which already suppress one label of a clipped
  event), so it is not a §23 violation.

## Stop conditions (item-specific)

- A date-label choice outside the type's derived set must be offered →
  stop (single-catalogue invariant).
- The control would need to move a label directly or change label
  **placement** geometry → stop (§23 placement is the scene's, and
  Refresh-only rendering governs).
- `Finish` offered for a `StartOnly` type, or any option for a dateless
  type → stop (capability invariant).

## Risk and rollback

Main risk: the schema-version bump stranding a version-14 workbook —
mitigated by ADR-0029 D6 (the version gate reports the mismatch and
Initialise materialises the column; no silent coercion). Rollback:
`git revert`.

**Realized 2026-10-14 and fixed (recorded in `../STATUS.md`).**
The stranding arrived not through the version gate but through the
required-column contract: `DateLabelPosition` was added as
`isRequired: true`, so a pre-R5.14 table failed the reader's column
map and reported `TableMissing`, which the ribbon-state gate maps to
`SheetInitialised=false` — the whole Gantt group greyed on open, and
the config-sheet version gate never ran. Fix (owner ruling, Option 1
— the `SortOrder` precedent): the column is **optional**; a missing
column reads as blank (= `Auto`, D3), and Initialise still
materialises it and advances the stored version to 15. The mutator
refuses a write on a table that still lacks the column (typed
`TableMissing` refusal, not a negative table index). Residual
follow-up (needs an owner decision): split the `TableMissing`
refusal vocabulary so "table absent" and "schema newer than the
reader" are distinct, and align
`ExcelGanttValidationReporter.TryBuildColumnMap` (which duplicates
the reader's column check) with that vocabulary.
