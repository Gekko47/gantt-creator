# Work item — R5.9a Show Properties control and in-cell validation

> **Guide status**: Authored (Tier B — binding contract) 2026-11-01. This row
> exists because R5.9's Option B decision (2026-10-31) deferred the Show
> Properties control and the in-cell `StyleKey`/`LabelPosition` validation to
> a named follow-up row. Until it lands, `Validate` is the only guard for
> those columns.

## Outcome

The Ribbon gains the **Show Properties** control defined by entity guide §3
(show/hide the property columns), and the `StyleKey` and `LabelPosition`
cells carry in-cell validation whose refusal vocabulary matches the existing
validator codes. The control and validation are contract-tested; the live
gate confirms the columns hide/show without changing any cell value.

## Context and owed deferrals

R5.9's roadmap row carries the scope-check STOP-point. The product owner
resolved it as **Option B**: amend the entity guide to define the control and
the two in-cell validations, and defer implementation to this row. The R5.9
row's own release scope is the Ribbon presentation delta (keytips,
screentips, supertips, labels), which has landed.

## Scope

- `src/GanttCreator.AddIn/RibbonResources/Ribbon.xml` — the Show Properties
  control (toggle), with keytip, screentip, supertip, and label per the R5.9
  presentation standard.
- `src/GanttCreator.Office/` — a narrow column-visibility port over the
  existing column-presentation adapter; no schedule-content writes.
- In-cell validation: `StyleKey` must be blank or an existing approved named
  style key; `LabelPosition` must be blank or permitted for the row's `Type`.
  Refusals reuse `UnknownType`-style typed codes (`StyleKeyUnknown`,
  `UnknownLabelPosition`).
- Tests: Ribbon XML/callback contract, column-visibility port contract,
  validation positives, live hide/show without value mutation.
- `docs/REPO-MAP.md`, `docs/STATUS.md`, status line.

## Exclusions

- No change to the worksheet schema or column order.
- No protection behaviour (ADR-0051 retains the unprotected workflow).
- No new dialog; the control is a Ribbon toggle.
- No schedule-content writes from the visibility path (positive test).

## Design decisions (behavioural)

- **D1 — Visibility only.** Toggling Show Properties hides or shows the
  property columns; no cell value changes. The live gate proves the `Value2`
  matrix is byte-identical around a toggle.
- **D2 — Validation is preventive, not authoritative.** In-cell validation
  refuses a bad entry at the cell boundary; the full-table validator remains
  the correctness authority because paste can bypass data validation.
- **D3 — Refusal vocabulary is shared.** The in-cell messages reuse the
  existing codes so the warnings panel and the notes cannot disagree.

## Acceptance tests

- **Automated**: AddIn — the control exists with the presentation attributes
  and its callback resolves; Office contract — the visibility port hides and
  shows exactly the property columns and writes nothing else; Core/Office —
  `StyleKey`/`LabelPosition` validation positives.
- **Office host (Required)** — live: toggle Show Properties on and off;
  confirm the columns hide/show, no cell value changes, and a bad `StyleKey`
  is refused in-cell with the shared code.

## Stop conditions (item-specific)

- The control needs a schema change or a new worksheet → stop.
- A visibility toggle would write schedule content → stop.
- The entity-guide §3 definition proves insufficient → stop and re-scope.

## Risk and rollback

Main risk: a visibility toggle marking the workbook dirty through an
unnecessary write — mitigated by the no-write pin. Rollback: `git revert`.
