## Design decisions (behavioural)

- **D1 — One command, the seven steps.** `RefreshSheetCommand` runs:
  read (R2.4 refusals → one actionable message each) → validate with
  registry (R2.9) → blocking errors → surface (R2.6 note flow reused
  verbatim; **zero mutation**) → else build scene (R3.12 `SceneBuilder`)
  → render (R4.5–R4.7 inside the R4.2 scope) → summary on success
  (counts only, per the R2.6 discipline).
- **D2 — Presenter degradation and the boundary.** Identical to
  R2.6/R2.2: unexpected exceptions cross the one command boundary;
  presenter failure degrades to no dialog; nothing scatters message
  boxes.
- **D3 — Ribbon gating.** The Refresh button gates on workbook
  presence (the existing truth table); callback is thin, routes
  through `CommandBoundary`, and refreshes ribbon state after the run.
- **D4 — Validate re-exercised, not rewritten.** The live gate runs
  both commands on a valid and an invalid workbook; Validate's
  behaviour is R2.6's, unchanged.
