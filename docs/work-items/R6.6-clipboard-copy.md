## Design decisions (behavioural)

- **D1 — Success = verified format, not a non-throwing call.** The
  copy stage reports success only when the expected Office drawing
  format(s) (from the spike evidence) are present; a silent `Copy()`
  return proves nothing (**positive test**: format absent → typed
  failure, no success reported).
- **D2 — Clipboard-unavailable is a distinct failure.** The
  compatibility-matrix failure row ("clipboard unavailable") is a
  typed refusal with an actionable message (not an exception, not a
  silent pass) — injection-tested.
- **D3 — Verification is immediate and bounded.** Format enumeration
  happens right after copy (before cleanup per the ADR ordering); no
  polling loops, no sleeps (bounded, deterministic).

## Acceptance tests

- **Office host (Required)** — live: copy in Excel; inspect the

## Stop conditions (item-specific)

- The expected format set differs from the spike evidence on a
  supported build → stop; update the ADR, never widen the check to
  "any format".
- Clipboard verification needs polling/sleeps → stop (D3).

## Risk and rollback

measured it; the verification set is per-evidence. Rollback: `git
revert`.
