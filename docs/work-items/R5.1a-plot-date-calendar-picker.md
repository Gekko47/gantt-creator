## Outcome

The Chart group's two plot-date rows gain a calendar button between the edit box and
the `Auto` checkbox:

```text
[ Start ][ edtPlotStartDate ][ btnPlotStartCalendar ][ Auto ]
[ Finish][ edtPlotFinishDate ][ btnPlotFinishCalendar][ Auto ]
```

A picked date populates the matching custom plot date through the existing commit path.
Each button is disabled exactly when its edit box is: no workbook, no initialised Gantt
sheet, or that end in AUTO mode. The edit-box text is never stale — a typed date, a picked
date, and every automatic pass that redraws the chart re-query `getText` immediately.

## Owner rulings

| # | Question | Ruling |
|---|---|---|
| D1 | Does a plot-date change override R5.20's `AutoRefreshEnabled` suspension? | **No — R5.20 wins.** Text and button states update instantly; the chart rebuilds on the coalesced pass only while the switch is on. |
| D2 | Calendar rendering | **Native `MonthCalendar`** in a small tool-window popup; keyboard/wheel month scrolling, screen-reader and high-contrast support come free. |
| D3 | Icon reuse | **Two buttons, one `calendar` glyph.** The label column and the supertip name the end; sharing the asset keeps one decode for both. |
| D4 | Work item identity | **`R5.1a`**, a slice of the landed R5.1 row. |
| D5 | A cleared plot-date box | **Revert silently** to the stored date. Never switch the end to Auto: that would be a settings round-trip plus a full rebuild, and it duplicates the Auto checkbox beside it. |
| D6 | Where the start-after-finish guard runs | **At input, before any write or pass, against the opposite end's EFFECTIVE date** — the stored date in explicit mode, the data-derived date the disabled box already shows in AUTO mode — then revert. |

## Superseded from R5.1

- R5.1 recorded "settings save on every change and the chart rebuilds only on Refresh".
  A successful plot-range commit now schedules the coalesced automatic pass (D1), and the
  edit-box text is refreshed by targeted invalidation rather than only by a full reload.
- R5.1's landing notes said a cleared box was refused; a blank entry is now a silent revert
  (D5) and no longer warns.

## Landed design

- **Surface.** `btnPlotStartCalendar` / `btnPlotFinishCalendar`, label + `showLabel="false"`
  (the label is the accessible name), `keytip` `SC`/`FC`, `getImage="GetGlyph"` on the one
  shared `calendar` slug, `getEnabled="GetEnabled"`, `onAction` per end.
- **Gate.** [`RibbonState.IsEnabled`](../../src/GanttCreator.AddIn/RibbonState.cs) gives each
  button its edit box's predicate. The switch fails open, so the truth-table test pins the
  two ids.
- **Picker.** [`PlotDatePickerForm`](../../src/GanttCreator.AddIn/PlotDatePickerForm.cs) hosts
  one `MonthCalendar` in a `FixedToolWindow`, positioned at the cursor inside the working
  area, system font, DPI scaling, Office-palette tints **bypassed under Windows high
  contrast**. Bounds come from the opposite end's effective date, so the calendar normally
  cannot offer an inverted pair; a bound is applied only when that text parses, because
  `MinDate > MaxDate` throws.
- **Routing.** `PickPlotStartDate`/`PickPlotFinishDate` build a `PlotDatePickerRequest`, resolve
  a cancelled dialog or an unchanged date to a complete no-op, and otherwise call the existing
  `SetPlotStartDate`/`SetPlotFinishDate`, so parse, inversion check, persistence and scheduling
  stay one path.
- **Never stale.** `InvalidatePlotDateRow` re-invalidates the date box, the calendar button and
  the Auto box for one end, and is used by all four setters on both the accept and refuse paths.
  A silent pass carries the rendered range on `GanttRefreshOutcome.PlotStart/PlotFinish`, and
  `RibbonStateService.UpdateEffectivePlotDates` writes only AUTO ends whose formatted text
  actually moved.
- **Persistence.** `PersistPlotSettings` became `TryPersistPlotRange` (four plot keys) and
  `TryPersistPlotLayout` (five layout keys), both through `TryWriteSettings`, which schedules
  one pass on success and — on a refused or throwing write — restores the caller's row and
  presents one actionable message instead of an operation-id error dialog.

## Exclusions

No new settings key, no schema bump, no catalogue-hash change, no Core change, no scene or
renderer change, no custom-drawn calendar, no second helper worksheet, no current-date marker.
