## Outcome

Every transfer failure mode — protected/read-only presentation, unsupported view, active
slide show, no window, no slide, no presentation, unsupported clipboard/partial document,
COM busy/rejected call, missing member/unsupported build — maps to a distinct typed
failure; only the measured transient COM rejections retry, with a bounded attempt count
and an explicit diagnostic budget (never sleeps, never a spin); cleanup runs on every
path — pinned by typed-mapping, bounded-retry and cleanup tests and a live
safe-failure reproduction.

## Step 0 — verify prerequisites (Tier A, revised 2026-11-21)

- R7.1–R7.4 land first; R6.5's Excel-side cleanup contract re-read (a failed transfer
  still cleans the Excel staging). **R6.8's measured busy-clipboard body is the
  Excel-side precedent:** a locked clipboard makes `Shape.Copy` fail and the command
  reports `CopyRefused`/`HostRejected` with zero residue — the same evidence-first shape
  this row's retry filter must follow.
- **The transient set is measured on the reference host through the typed PIA, not
  guessed.** The adapter records the `COMException.HResult` values its own calls produce.
  Expected candidates: `RPC_E_CALL_REJECTED` `0x80010001`,
  `RPC_E_SERVERCALL_RETRYLATER` `0x8001010A`,
  `RPC_E_SERVERCALL_REJECTED` `0x8001010B`. The filter uses only the values the probe
  observed. A missing member (`DISP_E_MEMBERNOTFOUND`) is an unsupported-build failure,
  never a transient retry.
- **No `dynamic`.** Typed PIA calls throw `COMException`, `InvalidCastException` or the
  host's typed error; there is no `RuntimeBinderException` path to catch.
- **The "deadline" is a diagnostic budget, not a sleep loop.** A synchronous retry that
  waits for a wall-clock deadline without sleeping is a CPU spin, and sleeping is
  forbidden. The implementable rule is: bounded attempt count, measured HRESULT filter,
  `Stopwatch` elapsed time used only for diagnostics and the refusal message. No
  polling loop, no `Thread.Sleep`, no `Task.Run` around COM.

## Design decisions (behavioural)

- **D1 — Distinct typed failures.** The taxonomy is: `NoPresentation`,
  `PresentationReadOnly`, `PresentationProtectedView`, `NoWindow`, `NoSlide`,
  `UnsupportedView`, `SlideShowActive`, `ClipboardUnavailable`, `PastePayloadMissing`,
  `PartialDocument`, `PasteValidationFailed`, `HostBusy`, `HostRejected`,
  `UnsupportedBuild`, `OwnershipFailed`, plus the construction members. Each carries an
  actionable user message and a technical log record (operation ID + HRESULT where
  available); none is an exception across the boundary and none is silent.
- **D2 — Bounded retry, evidence-filtered.** Only the measured transient rejections
  retry; the attempt cap is explicit (three is the starting point, confirmed by the
  probe); timeout diagnostics name the filter, the attempts and the elapsed budget.
  **Positive tests:** a non-transient failure never retries; no sleep primitive appears
  anywhere in the diff.
- **D3 — Cleanup on every path.** Every failure path still runs the Excel-side staging
  cleanup (R6.5) and releases only owned PowerPoint proxies; the user's PowerPoint is
  never closed or saved. The adapter owns no PowerPoint event connection unless a later
  row adds one; if it does, the connection is detached exactly once in `Dispose`.
- **D4 — `FinalReleaseComObject` is forbidden.** Release with
  `Marshal.ReleaseComObject`, reverse order, exactly once; never force-release a shared
  root; never `Quit`/`Close` a pre-existing host.
- **D5 — The Excel state scope is not reused.** `IApplicationStateScope` is Excel-shaped;
  PowerPoint restores only the settings it actually changed, and only if the probe shows
  a change is needed.

## Stop conditions (item-specific)

- A failure mode cannot be reproduced safely → record it; the human decides whether it is
  supported-tested or documented-only.
- A retry would need sleeps, a spin loop or unbounded waiting → stop (D2).
- A typed PIA member needed for a mapping is unavailable on a supported build → record
  the build and stop; do not return to `dynamic`.

## Risk and rollback

Main risk: hanging on a busy host — the bounded attempt count and the
`verify-office.ps1` watchdog/ownership discipline apply to the harness too. Rollback:
`git revert`.
