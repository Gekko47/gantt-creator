## Outcome

Every transfer failure mode — protected presentation, missing active
slide, unsupported clipboard format, COM busy/rejected-call — maps to
a distinct typed failure; only known transient COM rejection retries,
with a bounded message filter and deadline (never sleeps); cleanup
runs on every path — pinned by typed-mapping, bounded-retry, and
cleanup tests and a live safe-failure reproduction.

## Design decisions (behavioural)

- **D1 — Four distinct typed failures** (+ paste-validation failures
  from R7.3): each carries an actionable user message and a technical
  log record (operation ID + HRESULT where available); none is an
  exception across the boundary and none is silent.
- **D2 — Bounded retry, evidence-filtered.** Only the enumerated
  transient rejections retry; the deadline is explicit; timeout
  diagnostics name the filter and elapsed budget. **Positive test**:
  a non-transient failure never retries (**positive test**: no sleep
  primitives anywhere in the diff).
- **D3 — Cleanup on every path.** Every failure path still runs the
  Excel-side staging cleanup (R6.5) and releases only owned
  PowerPoint proxies; the user's PowerPoint is never closed or saved
  by a failure path.

## Acceptance tests

## Stop conditions (item-specific)

- A failure mode cannot be reproduced safely → record it; the human
  decides whether it is supported-tested or documented-only.
- A retry would need sleeps or unbounded waiting → stop (D2).

## Risk and rollback

Main risk: hanging on a busy host — the bounded deadline + watchdog
discipline (the `verify-office.ps1` timeout pattern) applies to the
harness too. Rollback: `git revert`.
