## Context

R3.14 proved the scene model for three of the ten equivalence rows. It had to
*assemble* the field lists rather than transcribe them, because the guide's
"Entity-to-renderer equivalence" section states which **representation** each
entity takes in each renderer, not which **fields** it carries. That assembly is
recorded in the R3.14 work item's Notes and is sound, but it is an agent's
reading sitting in a test file, not a contract a renderer author can consult.

Three specific gaps make an amendment worth doing rather than leaving to each
Phase-4 row:

1. **A scene representation is not a host representation.** The critical
   interval is a `SceneRect` one `CriticalLinePt` tall in the scene, but a
   *line* in all three host renderers. The current table says "line shape"
   three times and never records the translation.
2. **Two rows draw no host object on the live worksheet.** The data
   panel/header row is Excel cells, and the validation indicator is
   cells/dialog and excluded from export. A renderer author reading only the
   current table could conclude they must draw panel rectangles on the live
   sheet, which contradicts the invariant that the worksheet data table is
   visible and beside the live Gantt, and R4.8's preservation rules.
3. **Seven of ten rows have no field-level proof.** Procurement hatch, the
   critical interval, delineators, the panel/header primitives, the
   bands/grid/frame, and the validation indicator's exclusion are all
   unguarded by any test.

## Design decisions

- **D1 — Restatement, not extension.** The table names only fields the landed
  model already carries. Any cell that would require a new field reads "not
  carried by the model; excluded" instead. This keeps the amendment inside
  "restating the contract" and outside "changing the contract".
- **D2 — A translation column, because representation differs from scene
  shape.** Each row records what the scene carries and what each host
  renderer draws, so a rect-to-line or cells-to-shapes translation is stated
  rather than inferred. This is the gap the amendment most needs to close.
- **D3 — Live-sheet column is explicit.** Every row states whether the live
  renderer draws a host object or defers to the worksheet, so no renderer
  author draws panel rectangles over the visible data table.
- **D4 — Ownership is stated once, not per row.** The nine shared-contract
  bullets already give every entity an id, type, geometry, style key, z-layer,
  and ownership metadata. The table adds the per-row *specifics* and a single
  note that the `GanttCreator.` tag is written by the shape port (R4.1 D2),
  per the R3.14 decision.
- **D5 — The legend is an eleventh row, explicitly empty.** §25 is optional,
  hidden by default, and has no equivalence row today. Recording it as "not
  carried by the model today" closes the table without inventing fields.
- **D6 — A drift guard, because this failure recurs.** A test asserts the
  guide's row set and the catalogue's row set agree. A future guide edit that
  adds, renames, or removes a row then fails the suite instead of drifting
  silently, which is the defect class this row exists to remove.
- **D7 — Approval gate.** Step 2 does not start until the product owner
  approves the field lists. Steps 1, 3, and 4 are test-only and may proceed,
  because the ten row *names* already exist in the guide; if approval changes
  any field list, step 3 is re-transcribed before the guard is trusted.

## Stop conditions (item-specific)

- Approval implies a field the model does not carry → stop; that is a model
  change, which is a different work item, not this one.
- A field list conflicts with an existing guide section → stop and report
  (scope-change protocol).
- The drift guard cannot read the guide deterministically → stop; a guard that
  depends on prose parsing is worse than none.

## Risk and rollback

Main risk: the amendment silently becoming a token change by paraphrase. Every
cell must either cite a section or read "not carried by the model; excluded",
and the review diff is the check. Rollback: `git revert`; steps 3 and 4 are
additive test changes and step 2 is a self-contained table.
