## Outcome

`Above` and `Below` no longer exist as label positions, the retained horizontal
set resolves correctly, the delineator corners and splitter positions still work,
and ADR-0015's widest-gap truncation and nothing-to-place outcomes behave exactly
as they do today.

## Scope

- `src/GanttCreator.Core/GanttLabelPosition.cs` — remove `Above = 5`, `Below = 6`
- `src/GanttCreator.Core/EntityTypeCatalog.cs` — remove both from every permitted
  set
- `src/GanttCreator.Core/Scene/LabelPlanner.cs` — milestone order loses
  `Above → Below`
- `src/GanttCreator.Core/GanttCatalogues.cs` — type-catalogue rows
- `src/GanttCreator.Core/Scene/LabelPlacementPriority.cs` if it names either
- `tests/GanttCreator.Core.Tests/Scene/LabelPlannerTests.cs` and the catalogue
  round-trip tests
- `docs/REPO-MAP.md`, `docs/STATUS.md`

## Exclusions

- **No cascade rewrite.** `LabelPlanner` already implements the cascade, the
  occupancy measurement and the truncation; this row removes two positions from it
  and changes nothing else.
- No `Auto` reordering. ADR-0015 D1 already begins at `Right`, which is the
  owner's stated preference.
- No Ribbon UI — R5.5.
- No renaming of `Inside` in the enum; the Ribbon label is **Centre**.

## Design decisions

- **D1 — All five sites change in one commit**: the enum, the capability sets, the
  planner's milestone order, the guide, and `08-TEST-CHECKLIST.md` §C. A partial
  change leaves a position that parses but cannot be placed, or a capability set
  advertising a position that no longer exists.
- **D2 — Retained horizontal set:** `None`, `Auto`, `Left`, `Right`, `Inside`.
  Numeric values are unchanged, so no stored ordinal is invalidated.
- **D3 — The delineator corners are retained** (`TopLeft`, `TopRight`,
  `BottomLeft`, `BottomRight`). They are the corners of a full-height line, not
  above/below placements, and the landed R3.10 `DelineatorBuilder` cascade depends
  on them. Removing them would break a completed row.
- **D4 — The splitter positions are retained** (`DataPanelLeft`, `PlotCentre`,
  `Both`).
- **D5 — ADR-0015 D4, D5 and D6 stand unchanged.** The widest-gap measurement, the
  `…` truncation and the nothing-to-place outcome are **reused as built**. This row
  is predominantly a catalogue-and-contract change, not an algorithm change.
- **D6 — `Inside` is shown as "Centre" in the Ribbon only.** The enum keeps its
  durable, schema-bound name.
- **D7 — A stored `Above`/`Below` value is reported, not coerced.** There are no
  active users, so no migration; validation surfaces it.
- **D8 — A collision is never resolved by changing row height.** This follows
  ADR-0026 and is asserted, because with fixed heights the temptation is to grow
  the row.
