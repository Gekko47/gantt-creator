## Design decisions

- **D1 — The thin slice is a scene-field assertion, not a render.**
  For each of the three entities the test builds through the real
  builders (fixture-scale input), then asserts the scene carries every
  equivalence-table field with a non-default, typed value: geometry
  (points), resolved style tokens (fill/stroke/width/hatch where the
  row names them), text + resolved text bounds + side (label),
  z-layer + deterministic order key, stable role-derived ID, owner ID,
  and the ownership-tag data the Excel layer will need
  (`GanttCreator.` prefix contract). A required-but-missing field =
  failing test = a defect in the model — never a renderer-side
  workaround later.
- **D2 — The gap path.** If a required field cannot be proven from the
  scene + serialization alone, stop: spike outside production code,
  draft the ADR, follow the scope-change protocol. No speculative
  model extension in this row.
- **D3 — Exit evidence.** Run the exit demonstration (fixture →
  `SceneSnapshot.Serialize` → determinism proof, recorded here +
  STATUS); `pwsh ./scripts/verify.ps1` green; upgrade the ten Phase-4
  guides to Tier A (prerequisites re-verified against landed Phase-3
  code; exact files/tests/commands; refresh date in each status line)
  **before any Phase-4 implementation starts**.

## Notes during implementation

**Step 0 reconciliation, recorded so it is not re-derived.** Two premises of
Step 0 did not hold exactly as authored, and neither is a model defect:

1. *"the three rows' field lists are transcribed into the test exactly"*. The
   guide's "Entity-to-renderer equivalence" table states which representation each
   entity takes in each renderer (`Activity/delay → rectangle shapes → rectangle
   shapes → raster rectangles`, and so on). It carries no per-entity field list.
   The field list was therefore transcribed from the same guide's "Shared entity
   contract" bullets (lines 41-51), the "Z-order contract" layer table, and each
   row's own section — §12/§13 for the bar, §22 for the label, §20/§21 for the
   milestone — with the exact line range recorded on every field in
   `EquivalenceFields`. The guide was **not** amended: adding a field table is an
   entity-contract change, which is a stop condition, not a side effect of this row.
   `Every_transcribed_field_cites_the_entity_guide_and_is_named_once_per_row`
   keeps the transcription honest.
2. *D1 asks for "the ownership-tag data the Excel layer will need (`GanttCreator.`
   prefix contract)"*. No `GanttCreator.` string exists anywhere in Core or
   Office, and R4.1 D2/R4.3 assign the tag to the Phase-4 shape-write port. The
   product owner decided on 2026-09-26 that the scene's ownership metadata is
   `OwnerId` (row/chart/rows kind, value, `OwnedRows`) plus the role-derived
   `PrimitiveId`, which is what a renderer composes the tag from. The catalogue
   asserts those two fields and cites the phase that owns the literal prefix, so a
   later reviewer cannot read the missing string as a defect.
