[`docs/adr/0030`](adr/0030-live-chart-vertical-anchoring.md) and work item `R4.7I` (1 October 2026) add **one** further ADR and guide, from a live defect report: the chart's bars did not line up with their activity rows. **No source file changed, so no project row above is affected yet.** The finding worth carrying is structural rather than numeric. The plot's top was `TitleBandHeightPt + YearBandHeightPt + PeriodBandHeightPt` (58pt) and its height was the **size preset's page height** (~531pt for A4 landscape) — both properties of the paper, neither of the sheet — and `GanttRefreshOrchestrator` renders with `ChartOriginDelta.Identity`, so those page coordinates landed literally 58pt below row 1 while the first body row's real top is the never-normalised header height below it. Net ≈ 43pt ≈ 2.4 rows. `PanelCellGrid` carried column widths, per-row heights and the header height but **no absolute sheet position**, so ADR-0026 D3's `lane Top == Excel row Top` was *unrepresentable* rather than merely unmet — which is why a constant offset correction was rejected. Horizontal placement was already correct and is out of scope. The ADR records the owner's option-C ruling **and one divergence**: two band rows are reserved but only **one** is inserted, because entity guide §4 already requires the panel header's height to align with the period header's bottom, making the header row the period band's row.
