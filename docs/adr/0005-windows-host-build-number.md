# ADR-0005 — Document the actual host as Windows 11 25H2 (build 26200)

- **Status**: Accepted
- **Date**: 2026-09-04
- **Context**: The host reports `ProductName = "Windows 10 Pro"` from `HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion`, yet `CurrentBuild = 26200` is the Windows 11 24H2 / 25H2 build number. The discrepancy is the well-known "Windows 10 reporting on Windows 11" registry surface Microsoft ships on some configurations (insider rings, certain OEM images, and some in-place upgrade paths). The build number is the source of truth; the `ProductName` string is misleading.
- **Decision**: The recorded host is **Windows 11 25H2 (build 26200)**, x64, Professional edition. The `docs/01-ENVIRONMENT.md` skill table is updated to reflect this. The `docs/KNOWN-LIMITATIONS.md` L1 entry ("Windows 10 not Windows 11") is removed. `AGENTS.md` is unchanged because it does not assert a host version. From this commit forward, the rule for the recorded environment is **the build number, not the registry's `ProductName` string**; future contributors who see "Windows 10 Pro" in the registry should treat the build as authoritative and record both.
- **Consequences**: The environment record matches the user's statement and the actual binary. The L1 known-limitation is closed. The first R10.5 release run will still need to be rehearsed on a clean Windows 11 reference machine to satisfy the portability gate — ADR-0003 already covers the IDE side; this ADR covers the OS side.
- **Alternatives considered**: Trust the `ProductName` string and document Windows 10 (rejected — the build number contradicts the string, and the user has stated the actual host is Windows 11). Refuse to document the host until the registry is corrected (rejected — the build number is enough; the registry discrepancy is a Microsoft artefact, not a project concern).
