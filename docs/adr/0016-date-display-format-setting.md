# ADR-0016 — Approved date display format for event dates

- **Status**: Accepted
- **Date**: 2026-09-26
- **Context**: Entity guide §3 requires data-panel date cells to use "the approved display format" and §23 requires start/finish date labels to use the "approved invariant display format", but neither names a format and no code-owned setting selects one. The twelve settings approved by ADR-0007 D3 and extended by ADR-0014 contain no date-format key; `PeriodLabelFormat` selects the period-header band label and is not a substitute, because a month-only label is ambiguous for a start/finish pair. R3.11's stop condition ("the date display-format setting from ADR-0007 is unnamed → stop, D-G1 residue") is therefore armed. This is a rendering concern, not a data concern: R2.4 reads serial dates into neutral `DateOnly` values, so formatting is the first point at which a culture can leak into the output.
- **Decision**:
  - **D1 — The format is `dd/mm/yyyy`.** The product owner approved the GB/UK day-first format. This is a closed value, not a free-text pattern.
  - **D2 — One new setting key: `DateDisplayFormat`.** Stored in `tblGanttSettings` as exact ordinal text, defaulting to `DdMMyyyy`. It is a distinct key from `PeriodLabelFormat`, which continues to select the period-header band label only.
  - **D3 — A closed enum and a strict parser, not a pattern string.** `GanttDateDisplayFormat` has the single approved member `DdMMyyyy`, parsed by `GanttChartSettings.TryParseDateDisplayFormat` on exact ordinal text. This mirrors the `GanttPeriodLabelFormat` / `TryParsePeriodLabelFormat` pair added by ADR-0014. An unrecognised stored value is refused, never coerced and never defaulted silently.
  - **D4 — Rendering is culture-invariant.** The value is formatted through `DateOnly.ToString("dd/MM/yyyy", CultureInfo.InvariantCulture)`. The host's regional settings must never change scene text: an `en-GB` and an `en-US` host render the same date identically. This is the property R3.11's date-format pin and R3.12's golden scene snapshot both depend on.
  - **D5 — The enum may grow without a schema bump.** Adding a later approved member changes the permitted *value* set, not the *key* set. Under ADR-0007 D3 and the `GanttSchemaVersion` remarks, only a key-set change bumps the version, so a future format may be added by a guide amendment plus an ADR without a second version advance.
  - **D6 — Workbook schema version 2 → 3.** ADR-0007 D3 makes the exact `tblGanttSettings` key set part of the workbook schema contract, and the `GanttSchemaVersion` remarks require a bump when that contract changes. The catalogue hash (ADR-0007 D6) covers the settings catalogue and therefore changes with it.
  - **D7 — No migration, and the reader's exact-key-set check is unchanged.** No workbook has shipped; schema v2 was never released. The reader's existing `rows.Count != GanttCatalogues.Settings.Count` comparison (ADR-0007 D4 — the settings table always regenerates to exactly the approved key set) remains the authority, so a workbook lacking the key is refused as unreadable rather than tolerated. No lenient path, no deprecation window, and no dependency on the deferred R2.10 repair work.
- **Consequences**: R3.11's `PanelBuilder` and `DateLabelBuilder` can format against one code-owned value with no culture branch and no locale fallback. The scene snapshot becomes host-independent, which is what lets R3.12 commit a byte-stable golden file. Adding the key is a visible schema change: a workbook written before this ADR is refused on read, which is correct and intended for unreleased software. A user-facing format picker remains a separate downstream settings-dialog work item and is not part of Core-only R3.11; the VeryHidden worksheet is not a user editor.
- **Alternatives considered**: reuse `PeriodLabelFormat` (rejected because `MMM` is ambiguous for a start/finish pair and §3 and §23 describe a different contract); infer the format from the host locale or from `TimeScale` (rejected because the entity guide requires an explicit setting and because locale inference would make scene text host-dependent); store an unrestricted .NET format string (rejected because it admits invalid and ambiguous patterns and would put rendering policy in a user-editable cell); a code-owned constant with no setting key (rejected because the product owner chose a workbook setting, and a setting is the only route to a later format without a code change); name it in the entity guide only, with no workbook key (rejected because the VeryHidden worksheet is not a user editor, so a setting the user cannot change buys nothing over a constant and costs a schema bump).
