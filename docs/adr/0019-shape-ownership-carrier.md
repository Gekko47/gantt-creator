# ADR-0019 — Shape ownership carrier is `AlternativeText`, with a bounded versioned tag

- **Status**: Accepted
- **Date**: 2026-09-27
- **Context**: Entity guide "Shared entity contract" requires ownership metadata beginning `GanttCreator.` *in Excel shapes*, and "Ownership, editability, and refresh" requires Refresh to touch only shapes carrying valid Gantt Creator ownership metadata. R4.1 D2 named the carrier as `Shape.Tag`, and the manifest's Phase-3-exit upgrade deliberately left the exact PIA members "unprobed rather than guessed" (the Tier-A upgrade fixes names against landed code; it does not license inventing host behaviour). The R4.1 Step-0 probe was run on 2026-09-27 against the installed `Microsoft.Office.Interop.Excel.dll` (ExcelDna.Interop 16.0.0, ADR-0004), and it **falsifies the assumption**: enumerating all 67 properties of `Microsoft.Office.Interop.Excel.Shape` returns **no `Tag` member**, and the Microsoft Learn Excel `Shape` property list agrees. `Tag` is a **PowerPoint** `Shape` member; the guide had conflated the two object models. Excel's writable string carriers are `Name`, `Title`, `AlternativeText`, and `OnAction`. R4.1 D2 is therefore not implementable as written, and because the same carrier is referenced by R4.3 D2 (the reconciliation pair), R4.8 D1 (the ownership filter), and R9.4 (the damage classes), this is a cross-row contract change and an `AGENTS.md` stop condition rather than a local fix.
- **Decision**:
  - **D1 — `Shape.AlternativeText` is the ownership carrier.** Probed read/write `String`, semantically descriptive metadata for machines, and absent from the user's normal view. `Name` is rejected because R4.3 D2 already reserves it for the stable scene primitive ID and the two members must stay distinct. `Title` is rejected because R9.5 accessibility labels are its natural consumer and two subsystems writing one member is the class of defect ADR-0018 was raised to remove. `OnAction` is rejected because it is a macro-name field: writing a Gantt tag there would create a macro-security surface out of a bookkeeping string.
  - **D2 — The tag is bounded and versioned: `GanttCreator.Owned.v1:{hash}`.** The `{hash}` is a stable hash of `ScenePrimitive.PrimitiveId`, **not** the identifier itself. This is load-bearing, not cosmetic: under ADR-0017 a shared owner's `SceneOwnerId.Value` is a `|`-joined list of contributing row IDs, so a membership-sensitive `PrimitiveId` is unbounded. An unbounded tag risks host truncation, and a truncated tag would break R4.7's reconciliation key and R4.8's prefix filter simultaneously. The version segment lets R9.4 distinguish a tag written by this build from user content or a foreign add-in.
  - **D3 — `Name` + `AlternativeText` form the reconciliation pair.** R4.3 writes `Name` = `PrimitiveId` and `AlternativeText` = the bounded tag; R4.7 reconciles on the pair; R4.8's ownership filter tests the `GanttCreator.Owned.v1:` prefix. The entity guide's "`GanttCreator.` prefix" requirement is unchanged — only its carrier is corrected.
  - **D4 — R9.4 diagnoses mixed name/tag disagreement and repairs both members.** Its enumerated damage classes (duplicate marks, missing marks, orphaned tags, mixed name/tag disagreements) all survive the change; only the member name in its Step 0 changes.
  - **D5 — The tag constant and its hash helper live in `GanttCreator.Office`, never in Core.** R3.16's `EquivalenceFields` states that asserting a `GanttCreator.` string in Core "would be a model extension, which this row forbids", because the scene's ownership metadata is `OwnerId` plus the role-derived `PrimitiveId` and the renderer composes the tag from them. Keeping the constant Office-side preserves that boundary and keeps Core Office-free and interop-free.
- **Consequences**: R4.1 D2, R4.3 D2, R4.8 D1, R9.4 Step 0/Scope, and the entity guide's ownership section are amended to name `AlternativeText`. R4.1 gains one named Step-0 obligation: probe live, on the reference host, whether `AlternativeText` truncates the full tag. If it does, the remedy is a narrower hash width — the shape of the decision is unchanged, because D2 already made the tag bounded. If truncation proved aggressive enough to force a structural change, that is a stop-and-report, not a local fudge. No scene type, token value, geometry rule, z-layer, label position, or golden fixture changes: this ADR alters only which host member carries the ownership string.
- **Alternatives considered**: use `Shape.Name` as the sole identity-and-ownership carrier (rejected — it collapses the name/tag pair that R4.7 reconciles on and the R4.8 name-versus-tag disagreement check, and changes four rows' contracts for no gain); use `Title` (rejected — R9.5 accessibility labels are the better fit and one member must have one owner); use `OnAction` (rejected — macro-name field, macro-security surface); write the full `PrimitiveId` into `AlternativeText` (rejected — unbounded under ADR-0017, so truncation would silently break reconciliation and the ownership filter); defer the decision to R4.3 or R4.9 (rejected — R4.1 is the row that defines the tag member, and deferring strands the contract for three dependent rows).
